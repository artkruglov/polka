Сделано с Claude · история Полки

Одна регулярка, которая могла остановить сервер

Полка проверяет каждую сохранённую HTML-страницу: можно ли показать её без скриптов, есть ли формы, ссылки на чужие сайты, автопереход. Проверка была регулярным выражением. За день до открытого релиза ИИ-ревью безопасности посчитало, сколько это стоит: страница в 480 КБ останавливала весь сервер примерно на минуту.

Что делает классификатор

При каждом сохранении сервер решает, какой у страницы профиль: static (можно показать без скриптов и выпустить ссылку), limited (скрипты есть, но текст читается) или unsupported (форма, поле пароля, внешний адрес, автопереход — ссылку не выпускаем). А при каждом просмотре по ссылке вторая функция вставляет в <head> тег <base target="_blank">, чтобы ссылки внутри чужой страницы открывались в новой вкладке.

Обе работали на потоке запросов: пока идёт проверка, сервер не отвечает никому. Проверка была такой:

const interactive = /<script\b|<(?:iframe|frame|object|embed|applet|form)\b|<[^>]+\son[a-z]+\s*=|…/i;
const unsafe      = /<form\b|<input\b[^>]+type\s*=\s*["']?password\b|…|<meta[^>]+http-equiv\s*=\s*["']?refresh/i;
const head        = /<head(?:\s[^>]*)?>/i;

Виновник — фрагменты вроде <[^>]+\son[a-z]+\s*=. Встретив <, движок читает [^>]+ до ближайшего >. Если в странице нет ни одного > — например, она состоит из <meta , повторённого 80 000 раз, — он читает до конца, не находит on…=, откатывается и начинает заново со следующего <. Работа растёт как квадрат размера страницы.

Модель считает теги, а не байты и не шаги движка регулярных выражений; она показывает форму роста, а не точное время. Ниже — настоящие измерения.

Лимит загрузки — 5 МБ. Такая страница заняла бы сервер не на минуту, а на часы: всё это время в очереди стоят вход, коннектор, ссылки и проверка здоровья. Вторая половина атаки не требовала даже аккаунта: страница из <head классифицировалась как static, получала ссылку, и каждый её просмотр стоил серверу около 20 секунд; грант на просмотр действовал 60 секунд, а число запросов на грант никто не ограничивал.

Как сделали хуже, прежде чем сделать лучше

Честная часть истории: квадрат в регулярке жил в коде с первого дня, но в rc.3 мы его удвоили — своим же исправлением безопасности. Всё произошло вечером 22 сентября 2026.

  1. 22.09.2026, 20:49Релиз rc.2. Первое ревью безопасности перед выкладкой находит обход классификатора: браузер раскрывает символьные ссылки, а регулярка читает сырой текст, поэтому http-equiv="&#x72;efresh" проходил как обычная страница и получал ссылку.
  2. 22.09.2026, 21:11 · коммит d079285 · rc.3Исправление, которое удвоило цену. Классификатор стал дополнительно разбирать документ через parse5 и прогонять те же регулярки по раскодированным тегам. Обход закрыт, но теперь шаблоны бегут дважды: по исходнику и по тегам. Дерево уже построено — а решение по-прежнему принимает регулярка.
  3. 22.09.2026, вечер · ревью сервераЕдинственная блокирующая находка, F1. Второе ревью (другой экземпляр Claude, отдельно от автора кода) измеряет время на разных размерах, прослеживает вызовы до потока запросов и пишет: одна страница замораживает весь сервер; запустить может любой, кто умеет сохранять, а вторую половину — любой, у кого есть ссылка. Там же — важная оговорка: ограничить квантификатор ([^>]{0,N}) недостаточно, скан всё равно перезапускается с каждого <.
  4. 22.09.2026, 22:00 · коммит 3e0be3bОдин проход по дереву. classifyHtml обходит дерево parse5 один раз: имена тегов, имена атрибутов и значения в том виде, в каком на них реагирует браузер. Поиск <head> переписан вручную, без регулярки. Все прежние профили, включая корпус из 20 страниц, не изменились. Новый тест держит страницы-«наводнения» в 1 МБ под 1,5 с.
  5. 22.09.2026, 22:10Релиз rc.4. В changelog: «Классификатор страниц работает за линейное время… 5 МБ — меньше полсекунды».

До и после

Было: регулярка по сырому тексту

const tags = decodedTags(source);   // rc.3: дерево уже есть…
if (unsafe.test(source) || unsafe.test(tags))
  return "unsupported";              // …но решает регулярка, дважды
if (!interactive.test(source) && !interactive.test(tags))
  return "static";

Стало: один обход дерева

const walk = (node, hidden) => {
  if (tag === "form") unsafe = true;
  if (ACTIVE_ELEMENTS.has(tag)) interactive = true;
  for (const { name, value } of node.attrs ?? []) {
    if (attr.startsWith("on")) interactive = true;
    if (SCRIPT_URL.test(target)) interactive = true;
    if ((attr.endsWith("src") || attr.endsWith("action"))
        && REMOTE_URL.test(target)) unsafe = true;
    …
  }
  for (const child of node.childNodes ?? []) walk(child, inner);
};
walk(parse(source), false);

Регулярки остались только там, где они безопасны: SCRIPT_URL и REMOTE_URL проверяют начало одного значения атрибута, а не весь документ. Перед публикацией этой страницы Редакция повторила замер на текущем коде: старый классификатор на 40 КБ — около 1 с, на 80 КБ — около 4 с (вдвое больше страница, вчетверо дольше); новый на 5 МБ каждой из пяти «враждебных» страниц — от 80 до 324 мс.

Урок не про регулярные выражения вообще, а про то, где они бегут: одна проверка на потоке запросов стоит столько, сколько самая злая страница, которую разрешает лимит. И про то, что своё же исправление стоит перемерить.
