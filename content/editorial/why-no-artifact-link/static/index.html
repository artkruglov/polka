Сделано с Claude · история Полки

Почему сервер не может забрать артефакт по ссылке

Мечта простая: вставил ссылку на артефакт Claude — и работа лежит на Полке. Мы проверили, что на самом деле видит сервер, когда идёт по такой ссылке. Ниже — каждый шаг как он был, с байтами и кодами ответов, и путь, который работает вместо этого.

Эксперимент 20–21 сентября 2026

Взяли настоящую публичную ссылку на минимальный React-артефакт (автор выложил его как воспроизведение ошибки в открытом баг-трекере) и сделали то, что сделал бы любой сервер: обычный HTTPS-запрос без cookies, без авторизации, без подмены User-Agent, с таймаутом 20 секунд. Файлы провайдера не сохранялись и не исполнялись. Потом повторили запрос на следующий день и через новый модуль публичной загрузки Полки.

Результат записан в docs/specs/CLAUDE_IMPORT_EXPERIMENT.md как отрицательный: автоматический перенос артефакта по ссылке Claude не подтверждён. Это оказалось полезнее, чем «почти получилось»: ограничение попало в FAQ, в дорожную карту и в интерфейс страницы «Сохранить».

Что видит сервер — и что видит Claude

Два пути к одной цели. Первый — сервер Полки, который сам идёт за ссылкой. Второй — Claude, который приносит код сам через коннектор. Переключайте пути и листайте шаги.

  1. Путь 1 · сервер Полки

    Ссылка из Share-диалога

    Новые ссылки Claude вида claude.ai/artifact/… открываются только пользователю, который вошёл в свой аккаунт Claude. У сервера Полки аккаунта нет и быть не должно.

    GET /artifact/<id>   (без cookies, без Authorization)
→ артефакт открывается только вошедшему пользователю Claude;
   серверу без браузера — проверка Cloudflare, HTTP 403

    Содержимого артефакта нет. Чужие cookies или сессия пользователя — не вариант: это чужой доступ.

  2. Запрос без браузера

    На запрос, в котором нет настоящего браузера, сайт отвечает проверкой Cloudflare: HTTP 403 и страница «Just a moment…». Даже headless-браузер получил экран «докажите, что вы человек».

    GET https://…/public/artifacts/<id>   (повтор 20.09.2026, urllib)
→ HTTP 403   Cloudflare «Just a moment…»

    Пройти такую проверку автоматически — значит выдать программу за человека. Мы этого не делаем.

  3. Публичная страница: HTTP 200, но пустая

    Старые публичные ссылки claude.ai/public/artifacts/… иногда отвечают 200. Внутри — оболочка приложения: два пустых div, внешний скрипт и стили провайдера. Самого артефакта в HTML нет: его подгружает скрипт уже в браузере.

    GET /public/artifacts/<id>   (20.09.2026, curl)
→ HTTP 200  text/html  Cache-Control: private, no-store
   body: 123 943 байта
   <div id="root"></div>  <div id="portal-root"></div>
   <script type="module" src="…/index-….js">
   UUID артефакта в HTML: не найден

    Получить 200 — не значит получить работу. Это хеш оболочки, а не копия артефакта.

  4. Внутренний API: 403 и robots.txt

    В загрузчике страницы виден шаблон запроса /api/published_artifacts/<id>. Мы запросили его один раз, честно и без ухищрений — 21.09.2026, через новый модуль публичной загрузки Полки.

    GET /api/published_artifacts/<id>   (21.09.2026)
→ HTTP 403

GET /robots.txt
→ Disallow: /api/*        (для общего краулера)

    API закрыт для программ, и владелец сайта прямо просит туда не ходить. Подбор fingerprint, cookies и обход отказа в эксперимент не входили и не войдут.

  5. Вывод

    Сервер Полки не может сам забрать артефакт по ссылке Claude. В одном запросе он получает 200 с пустой оболочкой, в другом — 403, и ни в одном — содержимое работы. Со ссылками ChatGPT (share и canvas) ситуация похожая.

    Ссылка Claude/ChatGPT вставлена на странице «Сохранить»
→ Полка узнаёт её до любого запроса, объясняет причину
   и показывает поле для файла прямо в карточке   (коммит 1256784)

    Обход защиты — не вариант: это нарушение условий Anthropic, притворство перед антибот-проверкой и хрупкость: IP сервера рано или поздно заблокируют, и Полка встанет для всех. Вместо этого — путь 2.

  1. Путь 2 · коннектор

    Человек подключает Полку в Claude

    В настройках Claude.ai добавляется custom connector с адресом polochka.app/mcp. Client ID вводить не нужно: приложение регистрируется само (Dynamic Client Registration), вход — OAuth 2.1 с PKCE.

    Claude → polochka.app/mcp: регистрация клиента, запрос авторизации
Полка → человеку: «Разрешить доступ к вашей полке для claude.ai?»
Человек нажимает «Разрешить»

    Сервер видит согласие вошедшего пользователя Полки, а не чужую сессию Claude.

  2. Одна фраза в чате

    «Сохрани этот артефакт на Полку и дай ссылку». Claude вызывает инструмент polka_publish и передаёт код артефакта сам: одну HTML-страницу или исходник React-компонента.

    MCP tools/call polka_publish
  html: "<!doctype html>…"     (или component: исходник React-компонента)
  title: "…"

    Ничего не нужно скачивать: код приходит от того, у кого он и так есть.

  3. Что видит сервер Полки

    Авторизованный запрос с кодом внутри. Сервер ничего не запрашивает у Claude: проверяет размер и тип, классифицирует страницу, при включённом интерактивном просмотре собирает интерактивную версию и сохраняет работу приватно.

    → проверка токена и разрешения capture
→ лимит 5 МиБ, тип HTML, классификация страницы
→ сборка интерактивной версии (без сети)
→ сохранено: приватно, ссылки пока нет

    Ни одного запроса наружу. Работа лежит на Полке как независимая копия.

  4. Ссылка — в ответ

    Если подключению разрешено «Управлять ссылками», Claude возвращает в чат готовую ссылку вида polochka.app/s#…; без этого разрешения работа остаётся приватной, и инструмент объясняет модели, почему ссылки нет. Ссылку потом можно отозвать со страницы работы.

    ← ссылка https://polochka.app/s#…
   interactiveReady: true   scriptsRunForRecipients: true

    Та же цель — «вставил, и работа на Полке» — только законным путём и с копией, которая не исчезнет, если артефакт удалят в чате.

Шаг 1 из 5: Ссылка из Share-диалога

Что работает вместо этого

Ограничение сформулировано просто: автоматический перенос возможен только двумя легитимными путями — Claude сам передаёт код или браузер пользователя с его доступом. Из этого выросли способы, которые Полка предлагает сегодня.

Работает

Коннектор в Claude.ai и ChatGPT

Полка подключается как удалённый MCP-сервер со входом через OAuth 2.1. Модель вызывает polka_publish и приносит код сама. Вручную проверено с Claude.ai 22.09.2026; ChatGPT подключается по той же схеме, но ещё не проверен.

Работает

Файл из своего браузера

В чате: ⋯ → Download. Файл перетаскивается прямо в карточку на странице «Сохранить» — она появляется, как только Полка узнаёт ссылку Claude или ChatGPT.

Работает

«Вставить код»

Кнопка «Копировать» в чате копирует код артефакта. На странице «Сохранить» есть поле «Вставить код» — файл скачивать не нужно.

Работает

Агент на вашей машине

Claude Code и Codex подключаются к Полке одной командой через тот же MCP и OAuth и сохраняют работу от вашего имени.

В планах

Расширение браузера

«Сохранить на Полку» на странице артефакта — в вашем браузере, с вашим доступом. Это этап 4 дорожной карты, после коннектора; ещё не сделано.

Почему мы не «просто обошли»

Идея «запустить браузер на сервере» приходит первой. Мы её по сути проверили: headless-браузер получил ту же проверку «докажите, что вы человек». Дальше есть только маскировка бота под человека — а это обход защиты сайта и нарушение условий Anthropic. Полка не обходит защиту и не использует чужие cookies; так записано в FAQ и в дорожной карте, и так ведёт себя код: ссылка провайдера распознаётся ещё до любого запроса.

  • Наблюдения зафиксированы с точными числами: 200, text/html, 123 943 байта, пустой div#root; затем 403 от Cloudflare; API — 403; Disallow: /api/*.
  • Что не проверялось, записано тоже: содержимое API, разрешённый экспорт, полнота зависимостей. Отсутствие ответа в одном запросе — не доказательство недоступности для всех.
  • Публичность чужого артефакта не даёт лицензии на его повторную публикацию в составе Полки.
