# Передача Claude: GitHub и запуск Полки

Дата: 21 сентября 2026. Это инструкция следующему исполнителю, не заявление о production-ready.

## 1. Что именно выпускаем

**Полка сохраняет артефакты агента и позволяет открыть их по понятной ссылке, управлять доступом и повторно использовать материалы.** Создание происходит у выбранного пользователем агента. MCP — основной путь «положи на Полку»; загрузка файла — резервный. Публичная витрина и приватный обмен — разные режимы.

Не превращать релиз обратно в встроенный чат, генератор презентаций или обычный файловый диск. Не обещать импорт любой ссылки Claude/ChatGPT, открытие «у всех без VPN», российское хранение или enterprise-безопасность без проверки выбранной установки.

Два отдельных результата:
1. **Open-source prerelease на GitHub:** воспроизводимый исходный код, лицензия, понятный запуск, честные ограничения.
2. **Hosted pilot:** работающий HTTPS-сервис с изолированным интерактивным viewer, регистрацией, MCP, резервным копированием и оператором. Публикация репозитория не закрывает этот результат.

## 5. P0 — GitHub prerelease

1. Получить точный `owner/repo` и visibility. Не угадывать доступность репозитория и не подменять Lanka.
2. Сформировать список файлов релиза: server/web/packages/scripts/tests/deploy, package+lock, конфигурация, лицензия, актуальные docs. Просмотреть удаления и перемещения. Исключить секреты, `.env`, дампы, пользовательские uploads, локальные логи, персональные снимки и недоказанные демо-права. Проверить также git history и staged diff; `.gitignore` не удаляет уже tracked секреты.
3. Добавить CONTRIBUTING, SECURITY с каналом сообщения о проблемах, issue templates и CI. Проверить название/описание/темы репозитория и README: ценность → скриншоты → быстрый запуск → MCP → ограничения → self-host.
4. На чистом checkout: `npm ci`, `npm run check`, `npm run build`. Интеграционные тесты требуют локальных PostgreSQL и S3; штатный `npm test` создаёт изолированные ресурсы. **Не запускать `tsx --test ...` с рабочим `.env`: есть тесты с записью.** Узкий запуск: `node --env-file=.env --import tsx scripts/test-isolated.ts tests/single-file-agent-context.test.ts`.
5. CI должен повторять проверки с disposable PostgreSQL/S3, собирать Docker image, выполнять smoke, фиксировать lockfile и digest, проверять секреты и лицензии. Не выдавать production-секреты pull requests из forks.
6. Создать проверенный commit, push ветки, PR при принятом workflow. После успешной проверки чистого checkout — tag и GitHub **prerelease**, например `v0.1.0-rc.1`, только если версия свободна и согласована. Release notes честно отделяют local-tested от cloud-tested. Docker image публиковать с immutable digest и ссылкой на commit.

Критерий: другой разработчик клонирует именно опубликованный commit и воспроизводит запуск/тесты по README. Публичный репозиторий не содержит рабочих данных.

## 6. P0 — инфраструктура и конфигурация

Нужны от владельца: облачный аккаунт/проект, регион, бюджет, домен приложения, отдельный registrable domain viewer, DNS/TLS, SMTP sender и оператор. Yandex Cloud подходит к гипотезе хранения в РФ, но выбор не заменяет проверки сетевой доступности.

Первая поставка: app/API + maintenance, PostgreSQL в приватной сети, приватный versioned S3 bucket, TLS reverse proxy, отдельный viewer origin, secret store, логирование без токенов/содержимого. Одна VM допустима для ограниченного пилота, но не называется HA. 50 000 пользователей — план ёмкости, не измеренная нагрузочная характеристика.

- Провиженить отдельные schema-owner/runtime роли. Runtime не получает DDL/CREATEDB/роль владельца. Purge и restore — отдельные роли по recipes.
- Миграции001–026 выполняются schema-owner, затем актуальные grants, storage capability check, app readiness, maintenance. Проверить права реального runtime против реального провайдера.
- S3: private, versioning, чтение/удаление точной версии, ограниченный IAM; не открывать bucket ради viewer. Retention/lifecycle не должны удалять живые pinned версии.
- Production cookies Secure, HTTPS origins, секреты вне git; стабильный LINK_KEY и его восстановление защищены отдельно.
- Использовать process supervisor/container restart policy. `npm run dev` на ноутбуке не является эксплуатационной поставкой.

Полезные команды проверки candidate без запуска:

```sh
node --env-file=deploy/base.env deploy/check-base-image.mjs
docker compose --env-file deploy/base.env -f deploy/compose.base.yml config -q
```

Это не готовая команда production deploy: `compose.base.yml` выключает live viewer и mail. `config -q` предпочтительнее полного вывода, содержащего секреты.

## 7. P0 — интерактивность и главная ценность

**Самый важный незакрытый технический блок:** base Compose использует container HOST=0.0.0.0, а текущий viewer staging runbook — loopback listeners и allowlist до 100 revisions. Они не образуют готовую общую production-топологию.

Claude должен выбрать и реализовать одну согласованную topology, не просто включить флаг:
- отдельные app/viewer домены, no app cookies/Authorization на viewer;
- безопасные proxy headers/Host/SNI, CSP, sandbox allow-scripts, отсутствие утечки capability в access/error logs;
- приватный, unlisted и публичный просмотр; expiry/revoke, старые ссылки после обновления/restore;
- CPU/RAM/time/file limits сборщика и ограничения сети; egress-проверки с положительным контролем;
- реальный HTTPS desktop/mobile, iframe, навигация, popup/form/storage, зависимости ресурсов;
- deployment/rollback инструкция для выбранного варианта.

Если блок не закрыт, можно выпустить исходники и ограниченный static pilot, но нельзя объявлять основной интерактивный сервис готовым.

URL-import: сначала проверить реальные разрешённые публичные ссылки Claude/ChatGPT и другие заявленные источники в целевом облаке. Материал должен сохраняться своей копией и открываться независимо от исходной ссылки. Сохранить SSRF/redirect/размер/time проверки; не импортировать приватные чаты чужими cookies и не обходить авторизацию. Неподдерживаемый источник — честное объяснение + файл/MCP, без фиктивного успеха. Пока нет доказательств, не рекламировать «вставь любую ссылку». Доступность в РФ проверить из реальных целевых сетей; локальный curl этого не доказывает.

MCP: smoke с реальным Codex и Claude Code на публичном HTTPS endpoint: подключение/scopes, capture/status, чтение шаблона, revoke. Не все Claude/ChatGPT клиенты поддерживают одинаковый bearer-token onboarding. OAuth discovery/PKCE — отдельный блок только при необходимости конкретного клиента; не обещать «любой агент» без матрицы совместимости. Полке не требуется собственный внешний LLM API: агенты могут обращаться к её MCP сами.

## 8. P0 — эксплуатация и пилот

- Реальная почта: registration/login, expiry/replay, deliverability, SPF/DKIM/DMARC; тест SMTP overlay не равен доставке. Ручные приглашения библиотек обозначить явно.
- Backup PostgreSQL + versioned blobs + ключи; retention, расписание, алерты. Восстановить на отдельной инфраструктуре и проверить, что отзыв/удаление не отменились. Определить и измерить RPO/RTO.
- Перед upgrade: backup, migration rehearsal, наблюдение, rollback. Не откатывать только бинарник при несовместимой схеме; восстановление на отдельную цель требует процедуры согласования DB/blobs/erasure ledger.
- Health/readiness, метрики ошибок/latency/очереди/storage, алерты, operator contact; логи без capability, mail токенов и содержимого.
- Квоты/rate limits/abuse-report и модерация витрины. Приватные/unlisted материалы не попадают в индекс, OG и каталог; noindex не заменяет права.
- Нагрузочный тест на репрезентативных размерах артефактов и одновременных просмотрах; замерить p95, queue delay, ошибки и стоимость, определить пределы пилота.
- Privacy/terms/retention/удаление и условия размещения проверены для фактической поставки. Не включать account deletion в облаке без отдельной приёмки worker/restore.
- Начальное содержимое с правами и источниками. Синтетические аккаунты/примеры помечать демо, не выдавать за реальных пользователей.

Telegram-бот — следующий канал распространения, не замена core: username/token от BotFather, secret store, HTTPS webhook+secret, idempotency, лимиты, привязка аккаунта, выбор доступа, отзыв, ошибки неподдерживаемых URL. Никогда не публиковать материал автоматически только потому, что его прислали боту. Если бот не входит в первый pilot, убрать с лендинга обещание готовности.

## 9. Критерий go/no-go

Один новый пользователь проходит: вход → MCP/файл/поддерживаемая ссылка → сохранение → интерактивный просмотр → приватная ссылка другу без аккаунта агента → отзыв → библиотека/шаблон → новый результат. Другой tenant не читает приватное. Сбой и повтор не создают дубликаты. После restart и restore права сохраняются. Пройти с реальными пользователями и сохранить доказательства; симуляция не интервью.

Начать с ограниченного пилота, не заявлять 50 000 активных пользователей или полную корпоративную сертификацию. GitHub prerelease может предшествовать hosted pilot, если ограничения ясны.

## 10. Как работать экономно

Один результат на этап: release repository → production topology → deployment → end-to-end acceptance. Между ними короткий handoff: готово, commit/files, команды и результаты, остаток, следующий один результат. Luna — небольшие UI/docs, Sol — backend по контракту, сильная модель — архитектура/приёмка. Один исполнитель одновременно. Не повторять все исследования и успешные тесты без изменений.
