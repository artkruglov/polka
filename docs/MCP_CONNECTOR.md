# Полка как коннектор Claude.ai и ChatGPT

22.09.2026. Удалённый MCP-сервер Полки (`https://polochka.app/mcp`) подключается в чат-приложения как коннектор с входом через OAuth 2.1. После подключения достаточно написать в чате «сохрани этот артефакт на Полку» — модель вызовет `polka_publish` и вернёт ссылку `https://polochka.app/s#…`.

Ручные токены со страницы «Агенты» для Codex CLI, Claude Code и других клиентов продолжают работать как раньше.

В примерах используется адрес `https://polochka.app`. На своей установке подставьте свой `APP_ORIGIN`.

## Подключить

### Claude.ai (Pro/Max)

1. Settings → Connectors → **Add custom connector**.
2. Name: `Полка`, URL: `https://polochka.app/mcp`. Поля OAuth Client ID/Secret оставьте пустыми: Claude зарегистрируется сам (Dynamic Client Registration).
3. **Connect** → откроется Полка. Если вы не вошли, сначала войдите; затем страница «Разрешить доступ к вашей полке для **claude.ai**?» (в заголовке — сайт, куда вернётся ответ).
4. Отметьте разрешения и нажмите **Разрешить**. Вас вернёт в Claude.
5. В чате включите коннектор (меню инструментов) и попросите: «Сохрани этот артефакт на Полку и дай ссылку».

### Claude для Team / Enterprise (для всей организации)

1. Владелец организации: Admin settings → Connectors → **Add custom connector**, URL `https://polochka.app/mcp`.
2. Коннектор появится у участников в Settings → Connectors. Каждый участник нажимает **Connect** и входит в **свою** Полку: доступ выдаётся на аккаунт Полки, а не на организацию. Общего токена нет.

### ChatGPT

1. Settings → Apps & Connectors → Advanced settings → включите **Developer mode** (для Business/Enterprise режим должен разрешить администратор рабочего пространства).
2. Apps & Connectors → **Create**: Name `Полка`, MCP Server URL `https://polochka.app/mcp`, Authentication **OAuth**. ChatGPT регистрируется сам; client ID вводить не нужно.
3. Подтвердите доступ на странице Полки, как выше.
4. В чате выберите коннектор в меню «+» → Developer mode и попросите сохранить артефакт.

Названия пунктов меню у Claude и ChatGPT меняются; ориентир — «custom connector / MCP server URL / OAuth».

## Разрешения

Страница согласия показывает имя приложения (его сообщает само приложение), адрес, куда вернётся ответ, и разрешения. По умолчанию включены:

| Разрешение | Scope | Зачем чату |
|---|---|---|
| Сведения и статус | `context` | всегда; лимиты и статус своих сохранений |
| Сохранять новые работы | `capture` | `polka_publish`, `polka_capture` |
| Читать список | `read` | найти ранее сохранённое |
| Управлять ссылками | `share` | ссылка сразу в ответе `polka_publish` |

Выключены по умолчанию: создавать версии (`revise`), названия/папки/корзина (`manage`: в том числе создать, переименовать и удалить пустую папку, разложить работы по папкам), читать исходники и шаблоны (`source:read`). Разрешения действуют на всю Полку. Без «Управлять ссылками» работа сохраняется приватно, а инструмент объясняет модели, почему ссылки нет.

## Как это устроено

- Discovery: `/.well-known/oauth-protected-resource` и `/.well-known/oauth-protected-resource/mcp` (RFC 9728), `/.well-known/oauth-authorization-server` (RFC 8414). `/mcp` без токена отвечает `401` и `WWW-Authenticate: Bearer resource_metadata="…"`.
- `POST /oauth/register` — DCR (RFC 7591). Имена вроде Claude/Anthropic и ChatGPT/OpenAI (без учёта регистра и похожих кириллических букв) сохраняются как есть, только если все redirect URI ведут на claude.ai/claude.com или chatgpt.com/openai.com; иначе к имени добавляется «(имя не подтверждено)». Страница согласия показывает прежде всего сайт, который получит ответ. Остальное: только `authorization_code` и `refresh_token`, методы `none`, `client_secret_post`, `client_secret_basic`. Redirect URI — только https; http — только loopback (любой порт при запросе). Allowlist клиентов нет.
- `GET /oauth/authorize` — только `response_type=code` и PKCE `S256`; `resource` (RFC 8707) необязателен; если передан, должен быть `<APP_ORIGIN>/mcp`. Ошибка запроса показывается на Полке и не пересылается автоматически на адрес клиента. Запрос привязан к браузеру cookie `polka_oauth` на 10 минут.
- `/oauth/consent` — страница согласия; решение `POST /oauth/authorize/decision` требует сессию, CSRF-токен сессии и Origin Полки.
- `POST /oauth/token` — обмен кода (одноразовый, 60 с, привязан к клиенту, redirect_uri, PKCE, scopes и владельцу) и refresh с ротацией. Повтор кода отзывает выданное по нему подключение. Повтор уже использованного refresh-токена отзывает всё подключение; исключение — повтор непосредственного предшественника живого токена в течение 60 с (потерянный ответ, параллельный refresh): он получает `invalid_grant` без отзыва. `/oauth/token` и `/oauth/revoke` принимают только `application/x-www-form-urlencoded`.
- `POST /oauth/revoke` (RFC 7009): отзыв любого из токенов закрывает подключение целиком.
- Подтверждённый доступ — обычная строка `agent_connections` с отметкой клиента: все MCP-инструменты, проверки scope, аудит и страница «Агенты» те же. Access token живёт 1 час; refresh — 30 дней с продлением при использовании, но подключение не старше 1 года. Повторное подключение того же зарегистрированного клиента (`client_id`) заменяет прежнее; новая регистрация (DCR) создаёт отдельное подключение, прежнее остаётся. Refresh-токен выдаётся, если клиент зарегистрировал grant `refresh_token`.
- В БД хранятся только SHA-256 кодов, токенов и секретов клиентов. Удаление аккаунта закрывает подключения сразу, окончательная очистка удаляет коды и refresh-токены аккаунта (миграция 028).

## Отозвать

- Полка → «Агенты»: у подключения «Отозвать доступ». Access и refresh токены перестают работать сразу; приложение попросит подключиться заново.
- Или удалите коннектор в самом приложении.
- Уже выданные ссылки при отзыве подключения не закрываются — их закрывают на Полке.

## Ограничения

- Описание `polka_publish` зависит от режима viewer. При `HTML_LIVE_MODE=disabled` получатель видит страницу в статическом sandbox без скриптов и сети, и модель просят прислать самодостаточный HTML со статическим снимком React/JSX. При включённом режиме (hosted production: `polochka.page`) модель просят сохранить JavaScript внутри одного HTML (библиотеки встроены, JSX скомпилирован, без сети и внешних адресов); `polka_publish` сам собирает интерактивную версию и привязывает к ней ссылку (`scriptsRunForRecipients: true`, `interactiveReady: true`). Если сборка отказала, работа сохраняется, ссылка — статичная, если это возможно, а причина приходит в `interactiveUnavailableReason`. Страница с внешними скриптами или формами сохраняется, но ссылка на неё не выпускается (`linkUnavailableReason`).
- Лимит одного сохранения — 5 МБ HTML (`MAX_BYTES`, см. DECISIONS 22.09.2026); квоты аккаунта те же, что у загрузки.
- Проверено интеграционными тестами (`tests/mcp-oauth.test.ts`) на протоколе и формате запросов Claude.ai/ChatGPT. Ручная приёмка на polochka.app 22.09.2026: в Claude.ai сохранение через коннектор и ссылка проверены (шаги 4–5 ниже); отзыв подключения (шаг 6) и ChatGPT (шаг 7) ещё не проверены.

## Приёмка после выкладки

1. `docker compose --env-file hosted.env up -d` в `deploy/hosted` (выполняет миграции до 028 и grants). На другой форме установки — `npm run db:migrate` и повторно `deploy/runtime-grants.sql` (и рецепты purge/restore воркеров, если используются): они ожидают ровно миграции 001–028.
2. `curl -s https://polochka.app/.well-known/oauth-protected-resource/mcp` → `resource: https://polochka.app/mcp`.
3. `curl -si -X POST https://polochka.app/mcp` → `401` и `WWW-Authenticate` с `resource_metadata`.
4. Claude.ai: добавить коннектор, пройти вход и согласие; в «Агентах» появится подключение «Claude» со статусом «Доступ разрешён; запросов пока нет», после первого запроса — «Коннектор обращался к Полке».
5. В чате: «Сделай одностраничный отчёт и сохрани его на Полку». Ответ содержит ссылку `https://polochka.app/s#…`; она открывается в приватном окне.
6. В «Агентах» отозвать подключение; следующий запрос из Claude должен потребовать повторного подключения.
7. Повторить 4–6 в ChatGPT (Developer mode).

22.09.2026 на polochka.app пройдены шаги 4–5 с Claude.ai: настоящий чат сохранил страницу через коннектор, ссылка `https://polochka.app/s#…` открылась в приватном окне как интерактивная страница. Шаги 6 и 7 ещё не выполнены.
