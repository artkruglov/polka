# Витрина и библиотека хороших работ

Уточнение после первого рабочего среза. **Запланировано, не реализовано.** Витрина отобранных примеров входит в первый внешний выпуск. [Подача собственных исследований и проектов с небольшой модерацией](COMMUNITY_PUBLICATION.md) переносится в ранний M1.1; расширенная социальная лента остаётся M5.

## Зачем

Человек без готового файла должен увидеть, что здесь можно сделать, открыть работающий пример без входа и выбрать отправную точку. Путь: **увидел → попробовал → взял за основу → сохранил своё**. Просмотр примера — M1; самостоятельная копия и адаптация — M2. Неготовые действия не показываются как работающие.

Референс — [Explore Higgsfield](https://higgsfield.ai/): рядом с визуальными примерами есть Recreate, а для опубликованных проектов предлагается посмотреть, как они созданы. Берём принцип «результат ведёт к действию», сохраняя собственный дизайн Полки. Красивые обложки не заменяют живой материал.

## Три понятных места

| Место | Содержание | Граница |
|---|---|---|
| «Вдохновение» | Отобранные демо, категории, подборки по задаче | M1 — наши лицензированные примеры; M1.1 — также работы пользователей после модерации. Посетителю не нужен аккаунт или агент |
| «Моя полка» | Собственные работы и папки; позднее сохранённые примеры | Закладка не копия. Взять за основу создаёт собственную закрытую работу, не меняя источник |
| «Библиотека команды» | Доступные сотруднику примеры, шаблоны и лучшие работы коллег | M4: membership и правила компании. При внутренней установке нет обязательной загрузки внешней галереи |

На публичной главной — один выразительный пример и галерея реальных работ, с M1.1 — также пользовательские исследования и проекты с авторством. «Новое», «Выбор редакции» и категории помогают найти полезное. В личной среде рабочая полка остаётся отдельным понятным разделом; её не нужно каждый раз прокручивать через рекламную ленту. Новый посетитель может начать с «Посмотреть примеры» или «Добавить свою работу».

Карточка: реальная обложка, название, задача, формат; у интерактивного примера понятное обозначение. По открытию — крупный действующий материал. Рядом: «Взять за основу» после M2, «Как это сделано», автор и условия использования. Инструкция/рецепт доступна по запросу, а не загромождает просмотр техническими деталями.

## Стартовая коллекция: шесть сильных демо

| Пример | Что человек пробует |
|---|---|
| «Города, которые нас изменили» | HTML-презентация: крупная типографика, иллюстрации, переходы, управление с клавиатуры |
| «Пульс команды» | Отчёт с выводами и графиками: сменить период и увидеть соответствующие данные |
| «Экономика продукта» | Дашборд: поменять фильтр, сравнить сценарии, прочитать пояснение метрики |
| «Первое знакомство» | Прототип сервиса: пройти несколько связанных экранов и вернуться назад |
| «Как появилась идея» | Визуальная история: таймлайн, изображения, пояснения и умеренная анимация |
| «Запускаем новое» | Мини-сайт о продукте: понятная история, сравнение и демонстрация возможностей |

Каждый пример имеет законченную историю и собственную композицию. У него одна главная работа пользователя, а не набор эффектов. Сложность и интерактивность допускаются только в принятом профиле P08. Цель — шесть качественных материалов, не сотни однотипных карточек.

## Версии и переиспользование

Запись витрины ссылается на закреплённую версию демо, preview, поддержанный viewer profile, автора/лицензии и при наличии — recipe version. Витрина не сканирует приватные tenants и не делает их материалы публичными. Обновление оригинала не меняет уже созданные копии.

В M2 копия включает только явно разрешённый пакет/рецепт, получает новое владение и закрытый доступ. Если рецепт умеет менять лишь определённые данные, это названо до копирования; универсальная редактура произвольного HTML не обещается. Свой агент сможет получать такой рецепт через MCP после допуска соответствующего инструмента.

Сначала каталог поставляется с небольшим проверенным manifest и ресурсами. Для внутренней установки примеры можно включить в поставку или отключить; внешние шрифты/аналитика/обязательные запросы к нашему сервису не нужны. Не строить recommendation engine до появления использования.

## Этапы и приёмка

- **M1 / P08,P18,P22:** шесть отобранных демо, просмотр без регистрации, категории «Презентации / Отчёты / Дашборды / Прототипы / Истории / Мини-сайты». Desktop, телефон, клавиатура, reduced motion, ограниченная загрузка превью; ни одной карточки с неработающим обещанным взаимодействием. Это редакционная витрина продукта, а не публичная публикация работ посетителей.
- **M1.1 / S12,P07,P08,P18,P21,P22,P23:** авторская подача, отбор проверенной версии, общий каталог/профиль автора, снятие/жалоба, закладки и лайки; [контракт публикации](COMMUNITY_PUBLICATION.md).
- **M2 / P09,P17,P22:** взять за основу, изменить поддержанное содержимое, сохранить себе. Проверить первое полезное собственное сохранение, происхождение копии и права на пакет.
- **M4 / P15,P22:** библиотека команды и внутренние подборки по эффективным правам; закрытые данные не попадают во внешнюю витрину.
- **M5 / P22:** подписки, обсуждение и рекомендации по подтверждённому спросу; пользовательские публикации и базовые реакции уже отнесены к M1.1. Никаких вымышленных рейтингов, авторов или счётчиков.

При тестировании спрашиваем не только «красиво ли»: человек нашёл подходящий пример, понял назначение, попробовал взаимодействие, затем смог сохранить собственный результат? Открытие, полезное действие и самостоятельная копия — разные события. Образец должен помогать начать работу, а не оставаться рекламным роликом.
