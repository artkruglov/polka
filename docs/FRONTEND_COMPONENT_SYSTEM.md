# Единая система интерфейса

> **Статус:** реализовано. На 22.09.2026 `npm run check:layers` проверяет 69 модулей; корневых legacy-стилей больше нет (см. «Визуальная система»).

## Правило композиции

`app → pages → widgets → features → entities → shared`

Импортировать можно нижний слой. Соседние срезы одного слоя соединяются родителем, а не импортируют друг друга. Shared может соединять свои примитивы; app — свои сегменты композиции. Контракты сервера остаются в packages/contracts. Проверка разбирает синтаксис TS/TSX/JS: обычные и динамические импорты, re-export, type imports и require. Вычисляемые пути отклоняются. За пределами фронтенда разрешены только packages/contracts и packages/editorial.ts; новые корневые модули запрещены, кроме main.tsx, component-catalog-entry.tsx и vite-env.d.ts. Это проверка архитектуры импортов, не граница безопасности исполняемого кода.

## Каталог для разработки

Запуск: `npx vite --config apps/web/vite.config.ts --port 4398`.
Маршрут: `/dev/components`. Подключается лениво только при `import.meta.env.DEV`; в production сборку не включается. Это локальный каталог компонентов, не серверная рабочая установка на 4390.

В браузере проверены: загрузка каталога, ArrowRight переключает вкладку и фокус, Escape закрывает диалог и возвращает фокус на кнопку. Button и LinkButton используют одинаковые стили, но сохраняют семантику действия и перехода соответственно. Loading/disabled показаны на кнопках; ошибки связаны с полями через aria-describedby.

## Правки по ревью релиза (22.09.2026)

### Сеть и ошибки

`shared/api/client.ts` имеет один путь запроса: `send()` проверяет статус до чтения тела, поэтому HTML-страница прокси (502/504) больше не превращается в «Unexpected token '<'». Сетевой сбой становится `ApiError(0, "network")` с русским текстом; для 413/429/5xx без JSON есть понятные подписи. `request`, `bytes`, загрузка байтов и консент `/oauth/...` используют этот же путь — отдельного дублирующего помощника больше нет. Тест `tests/agent-connections.test.ts` проверяет HTML-ошибку и обрыв сети.

### Аккаунт и возможности установки

`entities/account` держит один запрос `/me` на загрузку страницы: гостем считается только 401, остальные ошибки дают `error` и общий `retry` (`useAccountState`). Вход и выход обновляют кэш через `rememberAccount`, поэтому `app/workspace` больше не делает собственный `me()`. Возможности установки читает один кэшированный `entities/capabilities` (`/capabilities`): `emailLogin`, `urlImport`, `livePreview`. Отдельный `features/import-url/useImportCapabilities` удалён; `LivePreview` остаётся на своём запросе.

### Разделение бандла

`app/routing/lazy-pages.tsx` загружает страницы (agents, templates, oauth-consent, signup, discover, landing, library-invite, start, recipient, bring) через `React.lazy` с общим `Suspense` и границей ошибки загрузки чанка. Рабочая область («/», /works, /trash) остаётся в начальном чанке. Zod уходит в отдельный ленивый чанк: формы загрузки, `paste-code` и жалобы берут константы из нового `packages/contracts/constants.ts` (без zod), а `tests/unit.test.ts` проверяет, что значения совпадают с `packages/contracts/index.ts`. Начальная загрузка: было 545.61 КБ JS (159.90 gzip) и 94.50 КБ CSS, стало 331.58 КБ JS (104.21 gzip) и 64.58 КБ CSS; остальное приходит по маршрутам.

### Сохранение

`entities/artifact/useSaveUpload.ts` — общий поток сохранения для файла и вставленного кода: загрузка один раз, затем чтение сохранённой работы. Если чтение не удалось, квитанция остаётся на экране (`entities/artifact/SavedReceipt.tsx`), «Показать результат» повторяет только чтение и не отправляет заново завершённую загрузку. Проверки файла и список форматов — в `entities/artifact/upload.ts`, выбор папки — `entities/folder/FolderSelect.tsx`; их используют UploadPanel, FileSave, PasteCode и импорт по ссылке. Заголовок страницы для загрузки и вставки извлекает один `entities/artifact/html-title.ts`.

### Мелкие исправления интерфейса

Список подключений на `/settings/agents` перестаёт «загружаться» при любой ошибке и показывает причину с повтором; отзыв доступа подтверждается диалогом, схема разрешений берётся из контрактов. Reader описывает открытую версию, а не последнюю. Сортировка полки честно помечена: пока есть непрогруженные страницы, порядок и фильтр действуют на загруженные работы. Обложки карточек грузятся при приближении к экрану (IntersectionObserver). Диалог «Поделиться» не падает без адреса ссылки, не объявляет radiogroup дважды и сбрасывает «Скопировано» вместе с адресом. Консент всегда передаёт scope `context`. Страница получателя отличает «ссылка недоступна» от «Полка не отвечает» и даёт повтор. `sessionStorage` в импорте по ссылке обёрнут в try/catch.

### Терминология и чистка

Пользовательские объекты называются «работа», «артефакт» — только о Claude/ChatGPT; «Моя полка» со строчной «п»; размер везде «5 МБ». Из рабочих экранов убраны прототипные бейджи «работает / в плане» (`shared/ui/Status.tsx` удалён вместе с `StatusRibbon` и `readinessLabel`), а также неиспользуемые `Brand`, `PrototypeMark`, `IconLink` и их CSS. Копирование везде идёт через `shared/ui/CopyText.tsx` (`useCopy`, `CopyButton`). Обложки «Ленты» рисуются из данных материала (`entities/editorial/Artwork.tsx`), список слагов `covers.ts` удалён. `classify-demo.ts` переименован в `classify-link.ts`.
