# Корпоративный пилот Полки

Полка не должна продаваться компании как ещё один диск. Диск — необходимый фундамент. Ценность для организации появляется в связке **«разрешённый агент → сохранённый артефакт → понятная версия → безопасный обмен и ревью»**.

## Большие jobs

| Job | Что хочет человек или компания | Что нужно доказать |
|---|---|---|
| Сохранить результат агента | Сотрудник говорит агенту «положи это на Полку» и получает private receipt | MCP/connector сохраняет точные байты, provenance и новую версию; агент не публикует |
| Поделиться внутри | Автор отправляет коллеге ссылку, коллега открывает её под корпоративной учётной записью | Workspace, identity, ACL и отзыв доступа работают на каждом маршруте |
| Довести до решения | Reviewer оставляет замечание к версии, автор или агент выпускает следующую версию | Комментарий привязан к revision/якорю; diff виден; старый выпуск не меняется |
| Не потерять работу | Сотрудник ушёл или агент отключён, материалы должны остаться компании | Owning tenant, offboarding, продолжатель, backup/restore и аудит доказаны |
| Не выпустить секрет | Security admin запрещает внешний egress, внешние модели и публичные ссылки для закрытых материалов | Policy enforcement на сервере; UI и MCP не обходят ограничение |
| Развернуть без внешнего сервиса | IT ставит Polka в своём контуре и подключает разрешённый storage/IdP/agent | Воспроизводимый профиль установки, конфигурация S3/MinIO, OIDC, egress и health checks |
| Найти полезное | Команда возвращается к прошлым отчётам и шаблонам | Поиск и метаданные соблюдают ACL; каталог не раскрывает private работы |

## Что обязательно для первого корпоративного пилота

Это минимальный вертикальный срез, который стоит добавить к личному agent-first входу:

1. **Организация и рабочая область.** Один personal tenant для простого входа и один organization tenant для пилота. У работы есть owning tenant и автор; папка не является границей безопасности сама по себе.
2. **Корпоративный вход.** OIDC/SSO один раз на выбранном провайдере, server-side membership и базовые роли `member`, `reviewer`, `admin`. Локальный пароль остаётся для development.
3. **Внутренняя ссылка.** По умолчанию private; режим «В компании» открывает только членам workspace. Invite и unlisted — отдельные проверяемые режимы, не замена membership.
4. **Разрешённый agent capture.** Один реальный MCP adapter, scoped token, receipt, provenance и запрет `share/publish/approve` для агента. Агент может создать candidate, человек — поделиться и выпустить.
5. **Версии и простой review.** Комментарий к revision/page/anchor, статус open/resolved, ответ автора, новая версия и явное переключение ссылки. Совместное редактирование в реальном времени пока не нужно.
6. **Безопасность и эксплуатация.** Egress profile, классификация, запрет внешних моделей по policy, audit событий capture/share/revoke/review, backup/restore и offboarding.
7. **Установка.** Docker Compose для малого пилота, конфигурация внешнего S3 или MinIO, Postgres, OIDC и отдельный домен для доставляемых артефактов. Hosted и self-hosted используют один application contract.

## Что не добавлять в корпоративный пилот

- универсальный редактор уровня Figma;
- зеркалирование внешнего чата или собственный чат-агент;
- все модели и все MCP-провайдеры сразу;
- автоматическую публичную витрину, лайки и рекомендации для закрытого контура;
- наследование сложных прав на сотнях уровней папок;
- DLP, legal hold и SCIM как видимость функции без реальной интеграции.

## Сквозной сценарий приёмки

1. Оператор разворачивает Polka внутри тестового контура, подключает Postgres, S3/MinIO и OIDC.
2. Сотрудник входит через корпоративную учётную запись и открывает workspace.
3. Разрешённый агент по MCP сохраняет HTML/ZIP-артефакт в папку «Входящие от агента»; в чате появляется receipt, а в Полке — private revision.
4. Сотрудник отправляет внутреннюю ссылку reviewer. Reviewer открывает версию, оставляет замечание, но не видит закрытый prompt trace и источники без права.
5. Агент или автор создаёт candidate v2. Reviewer видит diff и принимает его вручную; ссылка переключается только явным действием.
6. Администратор отключает сотрудника. Новые сессии, grants и agent runs прекращаются, а работа остаётся у owning tenant и доступна продолжателю.
7. Аудит показывает actor, agent delegation, operation, revision, share/review и результат без секретов.

Пока этот сценарий не пройден на одном реальном внутреннем агенте и на реальных правилах egress, нельзя называть продукт корпоративно готовым. Личная ссылка и публичный demo остаются более короткими входами для первых пользователей.
