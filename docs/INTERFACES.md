# Интерфейсы и состояния

Проект интерфейса, не готовое приложение. Привязка — [J01–J19](PRODUCT_AND_STORIES.md), [F01–F24](REQUIREMENTS.md), [доступ и ссылки S01–S12](SHARING_AND_DISCOVERY.md). [Кликабельный прототип v2](design/polka-interface.html) показывает полку, папку, карточки/список, разные типы работ, версии, доступ и получателя. Все данные демонстрационные; публикация и авторизация не реализованы. [Переход к продукту](PROTOTYPE_TO_PRODUCT.md) отделяет проверку UX от реализации сервера.

## Навигация

Слева: «Моя полка», «Доступные мне», «Недавние», «Избранное», дерево папок, «Корзина». Пустые второстепенные разделы не занимают внимание; M1 реализует полку/папки/корзину, остальные появляются с работающим контрактом. Сверху — выбор личной/корпоративной среды, поиск, «Загрузить» и меню профиля. В личной среде скрыта настройка организации.

Внутри папки: хлебные крошки, название, поиск/сортировка, карточки или список. Крупная обложка полезна HTML/PDF/изображениям; список лучше большого числа рабочих файлов. Выбор вида запоминается. Папка является местом хранения; подборка и публичная библиотека позднее не подменяют её.

| Экран | Основное действие | Вторичные действия / критические состояния |
|---|---|---|
| Лендинг | «Загрузить работу», рядом «Посмотреть пример» | Поддержанные HTML/ZIP, кандидат «Вставить HTML»; «Для компании». Создание своего отчёта B — после M2; агент не обязателен |
| Вдохновение M1 | Открыть и попробовать живой пример без входа | Реальные обложки, категории по задаче, крупный viewer. «Взять за основу»/закладки после M2; [коллекция и приёмка](DEMO_LIBRARY.md). Пользовательская публикация — M5 |
| Личный вход | Подтвердить личность и вернуться к действию | Ошибка/expiry/повтор, смена адреса, сохранённое намерение; guest recipe draft с объявленным TTL — отдельный M2 |
| Полка / папка | Найти и открыть либо загрузить | Имя/тип/размер/время/статус, контекстное меню, доступ, move, empty/error/loading, выбор нескольких после отдельной приёмки |
| Загрузка | Передать выбранный файл и получить receipt | Прогресс байтов, пауза/повтор/отмена при поддержке; отдельные проверка/сохранено/готовится preview; не скрывать превышение квоты |
| Работа / viewer | Увидеть содержание | Заголовок, папка, видимая версия и доступ, «Поделиться»; данные оригинала/скачивание в меню. Preview-first, не множество панелей |
| Рецепт / правка M2 | Выбрать текст/график и изменить | Контекстная панель только для поддержанной области, сохранение/Undo/CAS. M1 для произвольного HTML предлагает новую версию, не фиктивную правку DOM |
| Поделиться | Открыть доступ явным действием, затем скопировать активный адрес | Статус/аудитория/поиск видны. Срок/copy/download/pinned — в дополнительных настройках. Отмена не меняет настройки; отзыв постоянно доступен, сохранение опций не включает отозванную ссылку. Индексируемая публичность — M5 |
| Получатель | Открыть без исходного агента | Статичный или интерактивный режим явно обозначен; новый runtime только когда необходим. Разрешённая копия после входа; отзыв без private metadata |
| Версии | Понять изменения / открыть предыдущую | Источник, автор, preview, восстановление как новая revision. Официальный выпуск и простой checkpoint различаются |
| Обсуждение M3 | Замечание к месту и проверяемое исправление | Version/route/anchor; исчезнувшее место, unresolved/resolved, before/after; нет автоматического «решено» от ответа агента |
| Агент M3 | Поручить действие конкретному разрешённому подключению | Scope, skill/recipe, реальные события, вопрос, cancel, сохранённые результаты, восстановление. MCP-настройки не выводятся в основной UX |
| Компания M4 | Управлять участниками/политиками и работами | Пространства, группы/папки, offboarding, разрешённые агенты, классификация, audit, Brand Library, approvals; разные полномочия администратора и издателя |

## Быстрые взаимодействия

Drag-and-drop загружает в видимую папку после проверки назначения. Переименование inline не меняет object key. В M1 папка не меняет аудиторию. После добавления корпоративного наследования M4 перенос показывает изменение доступа; cross-tenant перенос — отдельная разрешённая копия. «Скопировать ссылку» не создаёт внешнего доступа молча: если share ещё нет, открывается панель аудитории.

Изменения каталога приходят автоматически; действия сохраняются независимо от socket. Во время потери связи локальный ввод виден как несохранённый. Нельзя писать «всё синхронизировано», если подтверждён только локальный буфер. При конфликте предлагается сравнить/сохранить свой вариант, а не перезаписать.

## Визуальное направление

Нейтральная тёплая поверхность, почти чёрный текст, зелёный акцент для ориентации. Выразительность — у работ; sidebar и метаданные спокойнее. Токены — [tokens.css](design/ui/tokens.css): сетка с шагом 4–8 px, скругления контролов 8 px, обложек 12 px, панелей 16–18 px. Desktop-контролы компактнее, touch-цель от 44 px. Один набор типографики/иконок/состояний; системный шрифт в макете, локальный лицензированный шрифт при выборе в продукте. Нет обязательного чата, трёх панелей или полей структуры слайда.

На полке работы идут сразу после компактных папок и фильтров. Вид списка и сортировка работают. В просмотре sidebar скрыт, кнопка новой версии находится сверху, фокус имеет видимый выход. Обложки макета нарисованы для наших вымышленных примеров; реальные работы требуют снимка их содержания либо честного placeholder, а не автоматически придуманного постера. Проверка на плотном произвольном HTML остаётся открытой.

На телефоне — одна основная поверхность и контекстная нижняя панель. Не загружать все обложки и все страницы документа при первом открытии; responsive thumbnail, pagination/virtualization по измерению. Просмотр не блокируется установкой приложения или чатом. Keyboard/focus/contrast и screen-reader оболочки проверяются отдельно от доступности произвольного HTML runtime.

|---|---|---|
| Полка → папка | Большие обложки, имя/тип/время/аудитория; список для плотных папок, breadcrumbs и поиск по имени | Пустая папка, нет результатов, перезапуск, длинное имя, пагинация; J04 |
| Принести → просмотреть | Файл либо вставка HTML; «Передаём» → «Сохранено» → «Просмотр готов». При ошибке исходник не исчезает | Повтор без дубля, неподдержанный формат, квота и сеть; J01/J03 |
| Работа → поделиться | Постоянная подпись аудитории. Панель со статусом и выбором «Только я / По ссылке»; ссылка копируется только после включения | S01/S02/S03/S09; приглашения после S10, company/public после допуска; будущий сценарий доступен отдельно в макете |
| Выбор «По ссылке» | «Откроет любой, кому перешлют ссылку». Поиск: «Просим не показывать в поиске»; без замка и слова «приватно» | Пользователь правильно предсказывает пересылку; нет ложного «гарантированно не индексируется» |
| Выбор «Приглашённые» | Подтверждённые люди, роль, добавить/удалить. «Чтобы открыть, нужно войти» | Wrong account, expired invite, отзыв. В прототипе это сценарий, в продукте появляется после S10 |
| Изменение работы | «На полке — v4; по ссылке — v3», кнопка «Обновить по ссылке». После проверки — та же ссылка и v4 | S06, CAS; нельзя незаметно изменить pinned release |
| Получатель без доступа | Нейтральный экран «Чтобы открыть работу, нужен доступ», без названия/обложки; вход и возврат по намерению | S01/S02/S10; никаких сведений о других приглашённых |
| Отзыв | «Отключить ссылку», после действия — «Новые открытия недоступны» и честное пояснение срока grants | S07; ссылка из кеша/старой вкладки соответствует принятому TTL |
| Public M5 | Отдельный preview «Это смогут найти в поиске», видимые title/description/cover, подтверждение публикации | S12; private/context исключены; запрет компании не обходится |

## Правила качества

Один главный акцент на экран: загрузка на полке, содержание в работе, аудитория в share. Мягкие контуры контролов, воздух и ровная типографика; статус передаётся текстом, а не только цветом. Нет обязательного чата или правого инспектора. Панели открываются по действию и закрываются Escape; фокус возвращается к вызвавшему контролу.

Прототип проверяет реальные переключения экранов, search, состояния share, save/update и неизвестного получателя на desktop/mobile. Он не загружает недоверенный HTML, не отправляет приглашения и не доказывает защиту ссылок. Настоящий frontend принимает эти сценарии с backend и отдельными аккаунтами.

## Проверка перед выпуском

Маршруты: личный A, B, получатель, папка/возврат, право отозвано, плохая связь и занятый runtime. Размеры 360/768/1440 CSS px, длинные русские подписи, EN-текст, ноль/null/отрицательные значения, большие папки. Запись viewport/build/revision и снимки фактического UI. Макеты не считаются доказательством выполнения задач; скорость и понятность проверяются живым пользователем в целевой сети.
