# Проверка песочницы агента

> **Статус:** в коде с 16.10.2026 (`scripts/polka-sandbox-check.mjs`), без миграций. Проверено на стенде `deploy/agent-stand` (Ubuntu 24.04, sandbox-runtime 0.0.79, Codex 0.162.1).

## Зачем

Служба ИБ хочет знать, что агент, которому выдали задачу, не прочитает ключи и токены на машине, не отправит данные наружу и не запишет ничего вне своей папки. Это обещают песочницы: sandbox-runtime (`srt`, открытый движок песочницы Claude Code), песочница Codex, контейнеры. Скрипт проверяет обещание на конкретной машине и конкретных настройках, а не по документации.

Полка сама агентов не запускает и песочниц не делает. Скрипт — открытый инструмент, которым ИБ или платформенная команда проверяет свою среду.

## Как устроена проверка

Каждая проверка выполняется дважды:

1. **Контроль — без песочницы.** Действие должно получиться: приманка читается, сайт отвечает, файл пишется. Если не получилось, проверка ничего не доказывает и получает «не проверено».
2. **Проверка — через песочницу** (`--runner`). Действие не должно получиться.

Отказ команды ещё не доказывает блокировку: инструмента может не быть, песочница может не запуститься, команда может упасть по таймауту. Поэтому:

- **Песочница должна работать.** Под ней обязательно проходят `echo` и чтение разрешённого файла (`--allowed-read`). Если хоть одно не прошло, все «заблокировано» превращаются в «не проверено».
- **Каждый способ чтения сначала читает разрешённый файл** — `cat`, `bash -c`, `python3`, `node`. Если инструмент под песочницей не запускается, его проверка — «не проверено». Так, под песочницей Codex 0.162.1 `node` не стартует, и без этой сверки чтение через `node` выглядело бы заблокированным.
- **Сетевые инструменты** (`curl`, `python3`) должны открыть разрешённый адрес (`--allowed-url`). Если разрешённого адреса нет — хотя бы запуститься.
- **Приманки — случайные значения.** «Прочитано» означает, что найдено именно это значение, а не что команда вернула 0.

## Что проверяется

| Часть | Проверка |
|---|---|
| Запуск | секрет из окружения того, кто запускает агента, не доходит до команды (`env`) |
| Песочница | каждую приманку (`--canary`) не читает ни один из четырёх инструментов |
| Песочница | запись вне рабочей папки (в HOME проверяющего) не проходит; запись в рабочую папку (`--work`) проходит |
| Песочница | `curl` и `python3` не открывают запрещённый адрес (`--blocked-url`), DNS-запрос не проходит; разрешённый адрес открывается |
| Песочница | Docker через `/var/run/docker.sock` недоступен (если сокета нет — «не применимо») |

Приманки создаёт тот, кто готовит машину, в путях, которые песочница должна закрывать: на стенде это `/home/agent/.ssh/id_canary`, `/home/agent/.aws/credentials`, `/opt/agent-stand/canary/secret`. Приманка внутри рабочей папки агента читается по определению — это не утечка, а граница, которую надо знать.

## Запуск

```bash
node polka-sandbox-check.mjs \
  --runner "env -i PATH=/usr/local/bin:/usr/bin:/bin HOME=/work/check srt --settings /etc/agent-stand/srt.json -c" \
  --canary /home/agent/.ssh/id_canary --canary /opt/agent-stand/canary/secret \
  --allowed-read /work/check/ok.txt --work /work/check \
  --allowed-url http://127.0.0.1:4390/api/health --blocked-url https://example.com \
  --settings-file /etc/agent-stand/srt.json --json report.json
```

`--runner` — префикс команды, которому последним аргументом передаётся строка для shell; `none` — без песочницы. Результат — таблица в терминале и, с `--json`, отчёт `polka-sandbox-check/1`: время, система, префикс, sha256 файла настроек, итог по каждой проверке.

Итоги: «заблокировано», «НЕ ЗАБЛОКИРОВАНО», «не проверено», «работает» и «не работает» для того, что должно работать, «не применимо». Код выхода: 0 — всё заблокировано, 1 — что-то не заблокировано, 2 — что-то не проверено или не работает.

## Что показали прогоны на стенде (16.10.2026)

- **`env -i` + `srt` с настройками стенда:** заблокировано всё — чтение приманок всеми инструментами, окружение, запись вне `/work`, сеть и DNS. Работают: команды, рабочая папка, Полка по разрешённому адресу.
- **Песочница Codex (`codex sandbox`, профиль по умолчанию):** запись вне папки, сеть и DNS заблокированы, но **приманки читаются** через `cat`, `bash` и `python3`. Песочница Codex не запрещает чтение файлов, поэтому секреты в HOME агента она не прячет.

## Чего проверка не делает

- Это свидетельство одного прогона на одной машине, а не допуск и не сертификат.
- Не проверяет утечку через **разрешённые** адреса: всё, что агент может отправить модели или Полке, он может отправить.
- Не проверяет уязвимости ядра и выход из песочницы через них.
- Не проверяет полноту списка закрытых путей: проверяются только переданные приманки.
- `srt` пока в бете (0.0.x): после обновления проверку нужно повторить.
