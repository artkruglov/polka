# Рабочее место агента

> **Статус:** в коде с 02.10.2026 (версия 0.7.0): `polka_list_files`, `polka_read_file`, `polka_change_files`, REST `GET /api/v1/works/:id/file` и `POST /api/v1/works/:id/changes`. Меняет позиционирование: [POSITIONING](POSITIONING.md) (до этой редакции «Полка хранит принятое»). Решения — [DECISIONS](DECISIONS.md#02102026-полка--рабочее-место-агента-с-версиями).

## Идея

Облачному агенту нужно место, где его работа живёт между сессиями и чатами: папка, в которую он кладёт файлы, откуда берёт их в следующий раз, которую видят другие агенты и человек. У Vercel Sandbox Drives это диск внутри песочницы. У Полки то же, но **с версиями и ссылками**: папка проекта — это работа; каждое сохранение — неизменная версия; человеку достаточно ссылки, без аккаунта.

Одной строкой: **Полка — рабочее место для ваших AI-агентов: папка с версиями, ссылкой для людей и чтением для других агентов.**

## Что уже есть (проверено по коду 02.10.2026)

| Операция агента | CLI / HTTP (нужен выход в сеть) | MCP (для чата без выхода в сеть) |
|---|---|---|
| Создать работу из файлов | `POST /api/v1/projects`, `PUT` файлов, `finalize`; `polka-publish-project.mjs` | `polka_capture` (манифест и все файлы в вызове), `polka_publish` (одна страница) |
| Взять папку | `GET /api/v1/works/:id/files`, `…/revisions/:rev/files/:index`; `polka-pull.mjs` | `polka_read_source`: **все** файлы версии одним ответом, base64, без списка и без выбора файла |
| Править один файл | `POST /api/v1/works/:id/edits` | `polka_revise` с `edits` (только существующий текстовый файл) |
| Сохранить следующую версию | `finalize` с `reuse` (неизменённые файлы копируются внутри хранилища) | `polka_revise`: новый манифест и **все** файлы заново |
| Что изменилось | `GET /works?since=`, `GET /events`, `GET /snapshot` | `polka_list` (`since`) |
| Токены без человека | сервисные доступы и токены задач (`SERVICE_ACCOUNTS=on`) | то же; OAuth-коннектор выдаёт человек один раз |

## Чего не хватало до 0.7.0 (почему это не был «диск» для чата)

1. В чате (Claude.ai, ChatGPT) нет выхода на чужие домены, CLI недоступен. По MCP папку нельзя ни перечислить, ни прочитать по одному файлу: `polka_read_source` отдаёт всё сразу, и большой проект не помещается в один ответ.
2. Нельзя **добавить, удалить или переименовать файл** без пересылки всей папки: `polka_revise` либо принимает полный набор файлов, либо патчит один существующий текстовый файл.
3. Нет REST-пары у части операций (правило паритета): добавление и удаление файла.

## Предложение

Три операции (сделаны) поверх существующих функций, каждая даёт новую неизменную версию и не двигает ссылку сама:

- **`polka_list_files`** `{artifactId, revisionId?}` → `files: [{path, mime, size, sha256}]`, без байтов (право `source:read`). REST-пара уже есть: `GET /api/v1/works/:id/files`.
- **`polka_read_file`** `{artifactId, revisionId, path}` → один файл (текст или base64), потолок на вызов (256 КиБ; больше — ошибка с подсказкой читать по частям или через CLI). REST-пара: `…/files/:index` и выбор по пути `GET /api/v1/works/:id/file?path=`.
- **`polka_change_files`** `{artifactId, baseRevisionId, put: [{path, encoding, data}], remove: [path], key}` → новая версия: неизменённые файлы копируются внутри хранилища (как `reuse`), `put` добавляет или заменяет, `remove` удаляет. Конфликт базы — `conflict` с `currentRevisionId`, как у `polka_revise`. Новая REST-пара: `POST /api/v1/works/:id/changes`.

Работает для работы-папки (проект, runtime `project-v1`; создаётся `polka_capture` с таким манифестом или CLI). Страница и пакет меняются через `polka_revise`, который заново классифицирует страницу. Новый файл получает тип по расширению, заменяемый сохраняет прежний тип; Base64 и UTF-8 проверяются строго, как в `polka_capture`. Пределы остаются прежними: страница 5 МиБ, файл проекта 5 МиБ (видео до 200 МиБ только потоком), проект до 400 файлов и 48 МБ. Рабочий мусор (зависимости, кэши, промежуточные файлы) не хранится: Полка принимает то, что агент решил сохранить версией.

## Чего не делаем (и почему)

- **Монтирование и синхронизация папки** (решение 27.09.2026): версии, а не файловая система. Нет перезаписи на месте, блокировок и дельт на лету.
- **Хранение зависимостей и промежуточных файлов**: в пределах лимитов Полка хранит папку проекта, а не рабочий каталог процесса.
- **Агентское принятие версии** (`curate`): отметку «принято» ставит человек.
- **Вебхуки**: агент опрашивает ленту.

## Авторизация облачного агента

- Чат-агент: OAuth-коннектор (человек соглашается один раз), права `source:read` и `revise` (и `capture` для новых работ). Права токена не больше прав человека на полке.
- Агент без человека: сервисный доступ с названным ответственным (свои установки; в облаке выключены до пилота) и токен задачи на 5–60 минут.
