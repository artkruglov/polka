# Сессии агентов

> **Статус:** в коде с 0.11.0 (миграция 065); чтение компанией (общий ключ отпечатков, `context.sessions`, `policies.sessionDelete`, `managed-settings`) — с 0.12.0. На polochka.app включается для отдельных полок оператором; на своей установке — `AGENT_SESSION_QUOTA_BYTES`. Исследование данных и выбор хранилища — [agent-telemetry-storage](../research/agent-telemetry-storage.md).

## Зачем

Автор видит, что делали его агенты Claude Code и Codex: какие команды запускали, куда обращались, где видели секреты и куда их передали, сколько ушло токенов и денег, какие работы и пулл-реквесты из этого вышли. Это первый шаг к центру управления агентами компании; там те же данные собираются по многим людям (коммерческая редакция, по пилоту).

## Что уходит с компьютера

`polka-sessions.mjs` (Node 22, без зависимостей) читает сессии на компьютере человека:
- Claude Code: `~/.claude/projects/<проект>/<id>.jsonl` (или в `$CLAUDE_CONFIG_DIR`, если папка Claude Code перенесена);
- Codex: `~/.codex/sessions/ГГГГ/ММ/ДД/rollout-*.jsonl` (или в `$CODEX_HOME`).

**Секреты скрываются до отправки.** Правила по мотивам gitleaks: ключи облаков (в том числе Yandex Cloud), токены Git-хостингов, ключи моделей, JWT, закрытые ключи, пароли в URL, заголовки авторизации, присваивания `*_PASSWORD=`, `token: …`. Найденное значение заменяется меткой `[REDACTED:<тип>:<отпечаток>]`. Отпечаток — первые 12 знаков HMAC-SHA256 с ключом полки (`GET /api/v1/sessions/key`), поэтому один и тот же секрет на разных компьютерах человека совпадает, а по отпечатку значение не восстановить.

На сервер уходят три части:
1. **Индекс** `polka-session-index/1` — факты: источник, проект (имя папки, адрес репозитория без учётных данных, ветка), время, число запросов, вызовы инструментов (вид, имя, шаблон команды без значений, адреса, статус, длительность, размеры ввода и вывода), токены по моделям, стоимость, если её записал сам агент, ссылки на работы Полки и пулл-реквесты.
2. **Отчёт о секретах:** тип, отпечаток, префикс вида `ghp_`, длина, где встречен (модель видела, передан в команду, записан в файл, отправлен сетевым инструментом). Значений нет.
3. **Расшифровка** `polka-session-transcript/1`, gzip: запросы, ответы, вызовы с входом (до 4 000 знаков) и выводом (первые 2 000 и последние 1 000 знаков), всё после скрытия секретов. Картинки заменены меткой. **Рассуждения модели (thinking) не отправляются** без `--thinking`.

Проверка на 1 974 реальных сессиях этой машины: повторный прогон правил по уже скрытой расшифровке находит только обрезанные куски на границе сокращения вывода, а не значения.

**Честно:** правила ловят известные виды секретов и присваивания с говорящими именами. Пароль без подсказки в тексте («вот пароль: …» на другой строке) правило может пропустить. Сессия — самоотчёт человека: он сам решает, какие сессии отправить.

## Как включить

1. Оператор даёт полке место: на своей установке `AGENT_SESSION_QUOTA_BYTES` (для всех личных полок), на polochka.app — по одной полке.
2. Человек выпускает на странице «Агенты» токен с правом **«Сессии агентов»** (право отдельное, по умолчанию выключено, только на личной полке).
3. `node polka-sessions.mjs login` — токен со стандартного ввода, хранится в `~/.polka/sessions-token` с правами 600 и никогда не передаётся аргументом.
4. Отправка: `sync --since 7d` (новые и изменённые), `upload <id>`; `preview <id>` показывает, что уйдёт, ничего не отправляя.
5. Автоматически: плагин Полки ставит хук `SessionEnd` для Claude Code. Он ничего не делает без `POLKA_SESSIONS=on` в окружении и отправляет сессию в фоне, не задерживая выход. Что ответила отправка, пишется в `~/.polka/sessions-hook.log` (до 1 МБ): там видно, дошла ли сессия. Для Codex хуков нет: `sync --source codex` по расписанию.

## Сервер

- **Не работы.** Сессии лежат в своих таблицах (`agent_sessions`, `agent_session_tool_calls`, `agent_session_secrets`, `agent_session_links`), а расшифровка — в хранилище под `<полка>/sessions/`. Их нет в списке и поиске полки, у них нет версий: повторная отправка той же сессии заменяет её. Внешняя модель модерации их не читает.
- **Своя квота:** `tenants.session_quota_bytes` (или `AGENT_SESSION_QUOTA_BYTES`, если больше) против `session_used_bytes` — сжатый индекс плюс расшифровка. 0 — выключено, ответ 403 `sessions_disabled`.
- **Пределы:** индекс до 8 МБ сжатым, до 20 000 вызовов на сессию (остальные считаются, но не хранятся), расшифровка до 64 МБ.
- **Правила v1** считает сервер, а не машина: секрет ушёл наружу; разрушительная команда (`rm -rf`, `git push --force`, `git reset --hard`, `terraform destroy`, `kubectl delete` и подобные); скрипт из сети в оболочку (`curl … | sh`); режим без подтверждений (`bypassPermissions`, `never/danger-full-access`). Статус секретов тоже пересчитывает сервер.
- **Стоимость:** то, что записал агент (Claude Code), иначе оценка по ценам установки `AGENT_MODEL_PRICES` (USD за миллион токенов по префиксу модели), если известны цены всех моделей сессии; иначе только токены.
- **Связи:** id работ из результатов инструментов Полки проверяются по этой полке; чужие отбрасываются. Ссылки на пулл-реквесты Claude Code записывает сам (`pr-link`).
- **Журнал:** `session.saved` и `session.deleted` в `audit_outbox` — только id и счётчики.
- **Стирание аккаунта** удаляет сессии, ключ отпечатков и обнуляет счётчик (триггер миграции 065 на переименование аккаунта при стирании); расшифровки уходят вместе с объектами полки.

## В компании

С 0.12 установка может быть устроена так, что сессии всех сотрудников читает компания: служба ИБ, руководители инфраструктуры и разработки. Консоль для этого — центр управления в коммерческой редакции; ядро даёт ей три вещи.

- **Один ключ отпечатков на установку:** `AGENT_SESSION_FINGERPRINTS=installation`. Ключ выводится из `LINK_KEY` односторонне, поэтому один и тот же секрет у разных людей даёт один отпечаток, а машины не узнают `LINK_KEY`. При переключении меняются отпечатки сессий, отправленных после него; сохранённые остаются прежними. Ключ получает каждый, у кого есть право «Сессии агентов». Поэтому тот, кто видит отпечатки, может проверить догадку о слабом пароле. Значение по отпечатку не восстановить, но короткий пароль можно подобрать перебором.
- **Предупреждение для человека:** `AGENT_SESSION_NOTICE` — текст, который человек видит при `login` и на странице «Сессии» до того, как отправит сессии. Например, кто в компании их читает и сколько хранит. Если компания читает сессии, сотрудников по закону нужно уведомить заранее; этот текст — место для такого уведомления, но не замена ему.
- **Точки расширения:** `context.sessions` — чтение сессий всех людей установки. `policies.sessionDelete` — компания может запретить сотруднику удалять свои сессии (например, пока не истёк срок хранения). Стирание всего аккаунта политика не останавливает. `context.redact(text)` — те же правила и метки секретов, что у `polka-sessions.mjs`, для текста, который пришёл на сервер нескрытым (телеметрия агентов); при `AGENT_SESSION_FINGERPRINTS=installation` отпечатки совпадают с отпечатками сессий. См. [EXTENSIONS](EXTENSIONS.md).

**Сбор без самоотчёта.** Компания раскладывает `polka-sessions.mjs` по машинам по постоянному пути и добавляет хук в управляемые настройки Claude Code (`managed-settings.json` через MDM или консоль администратора claude.ai). Человек их не отключит. Фрагмент для файла печатает `node polka-sessions.mjs managed-settings --script <путь на машинах> --endpoint <адрес Полки>`. Каждый сотрудник один раз делает `login` со своим токеном. Сессии, которые хук пропустил (выключили машину, не было сети), досылает `sync --since 2d` по расписанию. Для Codex обязательных хуков пока нет — только `sync --source codex` по расписанию.

**Честно:** сбор видит только машины с управляемыми настройками; агенты на личных машинах и в облаке (Claude.ai, Codex cloud) в него не попадают. Файлы сессий лежат у человека, и повторная отправка заменяет сессию на сервере, так что исправленный файл заменит настоящий.

## Где смотреть

- **Веб:** «Сессии» — список с фильтрами; страница сессии — факты, предупреждения, секреты, вызовы, связи, расшифровка, скачать, удалить; «Секреты» — отпечатки по всем сессиям; «Расход» — по дням и моделям, адреса, MCP-серверы. На странице работы — «Сделано в сессии».
- **Агент:** `polka_sessions` и `polka_session_stats` (право `sessions`, [инструменты MCP](../connect-agents.md#инструменты-mcp)).
- **HTTP** для CLI: [PUBLISH_API](../PUBLISH_API.md#сессии-агентов).
