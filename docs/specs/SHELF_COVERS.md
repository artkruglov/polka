# Обложки на полке

> **Статус:** реализовано 25.09.2026 (миграция 040). Снимки экрана — по флагу `COVER_SNAPSHOTS_ENABLED`, по умолчанию выключены.

## Зачем

Раньше карточка показывала уменьшенную копию верха страницы в живом iframe: мелкий нечитаемый текст, а под ним то же название крупно. Все текстовые отчёты выглядели одинаково — серый блок микротекста. На полке из 50 работ открывалось до 50 iframe.

Теперь у карточки одна из двух обложек, и выбирает её сервер:

- **Текстовая** (отчёт, документ, заметка, Markdown): собственный заголовок документа читаемым размером, 2–4 строки лида, метка вида («Отчёт», «Заметка») и акцент — основной цвет страницы или стабильный оттенок серии.
- **Визуальная** (дашборд, приложение, яркая страница, изображение): снимок первого экрана 1280×800, сохранённый как JPEG 960×600 и обрезанный под 16:10. Пока снимка нет (или снимки выключены) — цветная обложка с заголовком и меткой «Дашборд» / «Приложение».

Ссылки показывают сервис и адрес (название уже под обложкой). В списке — миниатюра 96×60: снимок или тонированная плитка с иконкой вида.

## Как решается «текст или картинка»

`apps/server/cover-facts.ts`, один проход parse5 по первому мегабайту HTML (в воркере с дедлайном 3 с для больших страниц). Сигналы: длина видимого текста, заголовки h1–h3, абзацы от 40 символов, таблицы, `<canvas>`, SVG крупнее иконки, изображения, видео, элементы управления, библиотеки графиков (по адресу скрипта и по вызову), «оболочка» (скрипт есть, текста в разметке меньше 200 символов).

Картинка набирает очки за canvas, рисунки, графики, изображения, элементы управления и особенно за оболочку и почти пустой текст; текст — за длину, заголовки, абзацы и таблицы. Длинный отчёт с одним графиком остаётся текстовым. Неверная догадка стоит только менее выразительной карточки; безопасность от неё не зависит.

Текстовые файлы всегда текстовые: заголовок — Markdown «#» или первая короткая строка.

Решение, заголовок, лид, акцент и сигналы хранятся в `revision_covers` вместе с версией (`COVER_VERSION` в cover-facts.ts; если логика меняется, версию поднимают, и старые обложки пересчитываются при следующем запросе).

## Поток

1. `GET /api/artifacts` отдаёт `revision.cover` (без самой картинки). `null` — обложка ещё не решена.
2. Карточка рядом с экраном (IntersectionObserver, 400 px) один раз спрашивает `GET /api/revisions/:id/cover`. Сервер читает версию, решает и сохраняет. Сохранение работы это не замедляет: на пути записи ничего не добавлено.
3. Для визуальной работы при включённых снимках строка получает `image_state='wanted'`, а процесс приложения ставит её в очередь (одна страница за раз). Строка захватывается (`pending` с истечением через 2 минуты), поэтому несколько экземпляров приложения не рисуют одно и то же дважды. Карточка переспрашивает каждые 3 с, не больше 10 раз.
4. Снимок отдаёт `GET /api/revisions/:id/cover.jpg?k=<ключ>` с `Cache-Control: private, max-age=31536000, immutable`. Ключ меняется вместе с картинкой. Изображение без снимка отдаётся как есть.

## Рендерер

`POST /snapshot {html, script}` в изолированном рендерере (apps/renderer/snapshot.ts). Страница подаётся Chromium с зарезервированного адреса `cover.polka.invalid`. Все остальные запросы, WebSocket, service workers, загрузки и разрешения отклоняются: скрипт страницы может рисовать, но ни до кого не дотянется. Один свежий контекст на страницу, 15 с на всё, ничего не сохраняется. Для страницы с готовой интерактивной версией рисуется она (как у получателя), иначе сам файл; многофайловый пакет без сборки не рисуется. Пустой первый экран (`blank`) снимка не даёт.

**Данные.** Приватная страница владельца уходит в рендерер. Поэтому `COVER_SNAPSHOTS_ENABLED=false` по умолчанию. Включать только для рендерера на той же VM (`--profile renderer`) или в России. Рендерер в Амстердаме (deploy/renderer) для обложек не годится: это трансграничная передача личного содержимого.

## Хранение и удаление

Картинка (до 256 КБ, обычно 10–40 КБ) лежит в `revision_covers.image`, а не в объектном хранилище. Строка ссылается на ревизию с `ON DELETE CASCADE`, поэтому любое удаление версии — корзина, временные полки, удаление аккаунта, повтор стирания после восстановления — забирает и обложку, без новых объектов для учёта. Обложка версии, изолированной модерацией или с удалённым содержимым, не показывается никому, включая владельца. При удалении содержимого модератором строка удаляется.

## Существующие работы

Обложки заполняются лениво при первом показе. Заранее их можно заполнить скриптом (от роли runtime, права в deploy/runtime-grants.sql):

```
npm run covers:backfill -- --dry-run      # сколько и каких, ничего не пишет
npm run covers:backfill                   # решения и тексты
npm run covers:backfill -- --snapshots    # плюс снимки, по одному, через рендерер
```

Скрипт идемпотентен: читает только последние версии работ не из корзины без обложки текущей версии.

## Стоимость

- Решение: один разбор HTML на версию. Для больших страниц — в воркере, до 3 с.
- Снимок: около 1,5 с работы Chromium на странице. Рендерер обрабатывает запросы по одному и делит очередь с импортом по ссылке; при `busy` строка повторяется до трёх раз.
- Полка из 50 работ: ни одного iframe. JSON обложек запрашивается только для ещё не решённых версий. Картинки грузятся лениво и кэшируются браузером навсегда.
