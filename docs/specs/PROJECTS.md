# Проекты: связанные страницы одной работой

> **Статус:** в коде с 25.09.2026, этапы 1–4: миграция 043, HTTP API и CLI, просмотрщик проектов, страница проекта у владельца и получателя, ссылки. Проверено в браузере на Y360-v2 (107 файлов, 14,1 МБ). На polochka.app не выложено. Первый случай — исследование Y360-v2 от агента: 28 markdown-документов, 16 HTML-экранов со своим `index.html`, общие CSS/JS/шрифты и 47 картинок, 109 файлов на 14,8 МБ (без записей экрана и служебных файлов).

Агент в Claude Code или Codex часто делает не одну страницу, а папку: README разделов, документы, экраны, картинки. Файлы ссылаются друг на друга. Сейчас Полка показывает у работы ровно одну страницу, поэтому такую папку можно только скачать.

**Проект** — одна работа из многих страниц. Её открывают целиком: слева дерево разделов, справа страница. По ссылкам внутри проекта можно переходить. Markdown отрисован, пути в тексте стали ссылками, у HTML-экранов работают их собственные стили, шрифты и картинки. Проект сохраняется одной версией со своим SHA-256 и отправляется одной ссылкой.

## Что считается проектом

Пакет (`storage_kind='bundle'`) с `manifest.runtime = 'project-v1'`. Всё, что уже есть у пакетов, работает и здесь: неизменяемые версии, идемпотентная загрузка, квота, корзина и экспорт.

| | Пакет (как сейчас) | Проект |
|---|---|---|
| Файлов | до 64 | до 400 |
| Объём | до 5 МиБ всего | до 48 МиБ всего, каждый файл до 5 МиБ |
| Точка входа | HTML | `README.md`, `index.md` или `index.html` |
| Типы | HTML, CSS, JS, JSON, SVG, PNG/JPEG/WebP, WOFF2, текст | те же плюс Markdown (`text/markdown`) и GIF |
| Просмотр | одна страница | дерево и переходы, просмотрщик проектов |

Точку входа выбирает загрузчик в порядке `README.md` → `index.md` → `index.html` в корне; её можно задать явно.

## Загрузка

- **Агент с доступом к папке** (Claude Code, Codex, скрипты): `node polka-publish-project.mjs ./Y360-v2`.
  - Скрипт обходит папку и пропускает скрытые файлы, `node_modules`, `__pycache__`, `.git` и `*.pyc`.
  - Файлы больше 5 МиБ и неподдержанных типов он тоже пропускает и перечисляет их в отчёте, чтобы агент сказал о них владельцу.
  - Скрипт показывает, что уйдёт, и отправляет через HTTP API с токеном.
  - Путь файла должен быть ASCII (как у пакетов). Файлы с другими именами скрипт перечисляет как пропущенные.
- **HTTP API** с токеном агента (scope `capture`):
  - `POST /api/v1/projects` — начало загрузки: манифест, название, папка; для новой версии ещё `artifactId` и `baseRevisionId`.
  - `PUT /api/v1/projects/:uploadId/files/:index` — байты файла.
  - `POST /api/v1/projects/:uploadId/finalize` — сохранение.
  - Это те же функции, что у загрузки пакетов из браузера, с лимитами проекта.
- **Модерация.** При сохранении каждый HTML-файл проходит тот же разбор, что страница, каждый скрипт — тот же сканер. Markdown и текст проверяются фильтром содержимого как текст.
- **Поиск.** Индексируется текст всех markdown-документов и видимый текст HTML-страниц проекта, в пределах 60 000 символов ([CONTENT_SEARCH](CONTENT_SEARCH.md)).

## Просмотр

### Просмотрщик проектов (домен просмотра)

`GET /project/:token/<путь>` на домене просмотра отдаёт файл закреплённой версии проекта по его пути.

- **Доступ** — отдельная таблица `project_view_grants`.
  - Доступ живёт 30 минут и привязан к версии и к сессии владельца либо к ссылке получателя. Каждое чтение перепроверяет корзину, отзыв ссылки и выход из аккаунта, как у просмотра одной страницы.
  - 60 секунд, как у обычного просмотра, здесь не хватит: проект читают долго, страница за страницей.
  - Токен стоит в пути, поэтому относительные адреса внутри проекта (`shared/y360.css`, `../02-users/roles-jobs.md`) разрешаются сами.
- **HTML-страницы** отдаются как есть, в песочнице:
  - `sandbox allow-scripts allow-popups allow-popups-to-escape-sandbox`, без `allow-same-origin` и без выхода наверх;
  - CSP разрешает стили, скрипты, картинки и шрифты только из `<домен просмотра>/project/<токен>/`, а `connect-src`, `frame-src`, `form-action` и `worker-src` закрыты;
  - внешние ссылки идут через подписанную страницу `/away` в новой вкладке;
  - ссылки внутри проекта открываются в том же окне просмотра.
- **Markdown** Полка рисует сама: `markdown-it` без HTML (`html: false`), таблицы, списки, код. Страница собирается в шаблон Полки со своими стилями, без скриптов автора.
  - Ссылки `[..](путь)` и пути в обратных кавычках (`` `02-users/user-stories.md` ``), указывающие на файл проекта, становятся переходами.
  - Путь ищется так: от документа → от корня проекта → по имени файла, если оно в проекте одно. В Y360-v2 так разрешаются 167 из 182 упоминаний.
  - Остальные показываются как код с пометкой «вне проекта».
  - Картинки проекта показываются, внешние картинки — нет.
- **Картинки и текст** показываются простой страницей Полки.
- **Субресурсы** (CSS, JS, шрифты, картинки) отдаются только на запрос из страницы (`Sec-Fetch-Dest` не `document`/`iframe`). HTML и Markdown отдаются только как документ во фрейме (`iframe` + `navigate`), как у существующих просмотрщиков.
- **Синхронизация с деревом.** В каждую страницу добавляется скрипт Полки с одноразовым nonce, и больше он ничего не делает. Он сообщает родителю путь открытой страницы (`postMessage` на `APP_ORIGIN`), чтобы дерево подсветило её.

### Страница проекта (приложение)

У владельца (`/works/:id`) и получателя (`/s#…`) одна раскладка:
- **Слева** — дерево. Папки сворачиваются. Точка входа и README разделов идут первыми. Документы и страницы показаны сразу, ресурсы (CSS, JS, шрифты) — под «Файлы проекта».
- **Сверху** — хлебные крошки и «Открыть отдельно».
- **Справа** — iframe просмотрщика проектов.

Адрес страницы помнит открытый путь (`/works/:id#path=02-users/user-stories.md`), поэтому ссылку на конкретный документ можно переслать. На телефоне дерево открывается кнопкой «Содержание».

## Этапы

1. **Хранение и загрузка.** Рантайм `project-v1`, лимиты, Markdown и GIF в типах, миграция (ограничения на число файлов, размер и точку входа проекта), HTTP API с токеном, скрипт `polka-publish-project.mjs`, модерация и поиск по всем страницам.
2. **Просмотрщик проектов.** Доступы, маршрут, markdown с разрешением ссылок, CSP, скрипт синхронизации.
3. **Страница проекта** у владельца и получателя: дерево, крошки, адрес с путём.
4. **Ссылки на проект** для получателя, обложка проекта на полке, указание агентам в скилле и `llms.txt`.

## Ограничения

- Скрипты HTML-страниц работают, но без сети: данные только из файлов проекта.
- Страницы проекта не собираются в интерактивную версию с React-рантаймом. Для этого есть обычные работы.
- Правка отдельных файлов проекта через `polka_revise` — позже. Новая версия проекта загружается целиком.
- Ссылки из markdown на файлы вне проекта не открываются.
