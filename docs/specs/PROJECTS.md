# Проекты: связанные страницы одной работой

> **Статус:** в коде с 25.09.2026, этапы 1–4 и правка одного файла (27.09.2026): миграция 043, HTTP API и CLI, просмотрщик проектов, страница проекта у владельца и получателя, ссылки. Проверено в браузере на Y360-v2 (107 файлов, 14,1 МБ). На polochka.app работает с 26.09.2026. Первый случай — исследование Y360-v2 от агента: 28 markdown-документов, 16 HTML-экранов со своим `index.html`, общие CSS/JS/шрифты и 47 картинок, 109 файлов на 14,8 МБ (без записей экрана и служебных файлов).

Агент в Claude Code или Codex часто делает не одну страницу, а папку: README разделов, документы, экраны, картинки. Файлы ссылаются друг на друга. Сейчас Полка показывает у работы ровно одну страницу, поэтому такую папку можно только скачать.

**Проект** — одна работа из многих страниц. Её открывают целиком: слева дерево разделов, справа страница. По ссылкам внутри проекта можно переходить. Markdown отрисован, пути в тексте стали ссылками, у HTML-экранов работают их собственные стили, шрифты и картинки. Проект сохраняется одной версией со своим SHA-256 и отправляется одной ссылкой.

## Что считается проектом

Пакет (`storage_kind='bundle'`) с `manifest.runtime = 'project-v1'`. Всё, что уже есть у пакетов, работает и здесь: неизменяемые версии, идемпотентная загрузка, квота, корзина и экспорт.

| | Пакет (как сейчас) | Проект |
|---|---|---|
| Файлов | до 64 | до 400 |
| Объём | до 5 МиБ всего | до 48 МиБ всего, каждый файл до 5 МиБ |
| Точка входа | HTML | `README.md`, `index.md` или `index.html` |
| Типы | HTML, CSS, JS, JSON, SVG, PNG/JPEG/WebP, WOFF2, текст | те же плюс Markdown (`text/markdown`), GIF и видео MP4/WebM ([PROJECT_VIDEO](PROJECT_VIDEO.md)) |
| Просмотр | одна страница | дерево и переходы, просмотрщик проектов |

Точку входа выбирает загрузчик в порядке `README.md` → `index.md` → `index.html` в корне; её можно задать явно.

## Загрузка

- **Агент с доступом к папке** (Claude Code, Codex, скрипты): `node polka-publish-project.mjs ./Y360-v2`.
  - Скрипт обходит папку и пропускает скрытые файлы, `node_modules`, `__pycache__`, `.git` и `*.pyc`.
  - Файлы больше 5 МиБ и неподдержанных типов он тоже пропускает и перечисляет их в отчёте, чтобы агент сказал о них владельцу.
  - Скрипт показывает, что уйдёт, и отправляет через HTTP API с токеном.
  - Путь файла должен быть ASCII (как у пакетов). Файлы с другими именами скрипт перечисляет как пропущенные.
  - React-исходники (`.jsx`/`.tsx`) проект не собирает. Если в папке нет `README.md`, `index.md` и `index.html`, а компонент один, скрипт сохраняет его как обычную работу-компонент, её Полка собирает и запускает. Компонент можно указать и явно: `--entry App.jsx`. Если компонентов несколько, скрипт ничего не отправляет и объясняет: собрать приложение с относительными путями (`vite build --base ./`) и загрузить папку сборки. Рядом со страницами компоненты пропускаются с этой причиной.
- **Токен без ручного копирования** (миграция 046). Агент с Полкой по MCP вызывает `polka_project_upload`. Инструмент возвращает токен на 30 минут и готовую команду: скачать CLI и запустить его с этим токеном.
  - Токен — дочернее подключение того, кто его попросил. У него та же полка и те из прав родителя `capture`, `revise` и `share`, что у родителя есть (`share` — чтобы CLI сразу вернул ссылку), и отдельная audience `<origin>/api/v1/projects`: его принимают только маршруты проектов и `POST /api/v1/publish` (страница или компонент с диска, `pageCommand`). `/mcp`, `/api/v1/status`, правки и вход по ссылке его не принимают.
  - Живёт 30 минут и перестаёт работать, как только родительское подключение отозвано или истекло. За эти 30 минут им можно загрузить несколько проектов и версий: он не расходуется на одну загрузку.
  - Токен попадает в историю чата агента, поэтому он такой короткий и узкий.
  - Не больше 10 токенов в час на подключение.
  - На странице «Агенты» такие токены не показываются. Читателю полки отдела инструмент не предлагается.
- **HTTP API** с токеном агента (scope `capture`):
  - `POST /api/v1/projects` — начало загрузки: манифест, название, папка; для новой версии ещё `artifactId` и `baseRevisionId`.
  - `PUT /api/v1/projects/:uploadId/files/:index` — байты файла.
  - `POST /api/v1/projects/:uploadId/finalize` — сохранение.
  - Это те же функции, что у загрузки пакетов из браузера, с лимитами проекта.
- **Модерация.** При сохранении каждый HTML-файл проходит тот же разбор, что страница, каждый скрипт — тот же сканер. Markdown и текст проверяются фильтром содержимого как текст.
- **Поиск.** Индексируется текст всех markdown-документов и видимый текст HTML-страниц проекта, в пределах 60 000 символов ([CONTENT_SEARCH](CONTENT_SEARCH.md)).

## Правка одного файла

Агент поправил опечатку в одном документе — перезаливать 100 файлов незачем. `polka_revise` с `edits` и `path` (и `POST /api/v1/works/:id/edits`) правит один текстовый файл проекта: Markdown, HTML, CSS, JavaScript, JSON, SVG или текст. Без `path` правится точка входа.

- Сервер читает из базовой версии только этот файл, применяет правки и сохраняет новую версию тем же путём, что загрузка пакета: тот же ключ идемпотентности, та же проверка, что `baseRevisionId` — последняя версия, те же права подключения и папки агента на каждом шаге.
- Остальные файлы не проходят через сервер Полки: хранилище копирует их версии в объекты новой загрузки (`CopyObject`). У каждой версии по-прежнему свои объекты, поэтому корзина, модерация, объединение полок и удаление работают с ней как с любой другой.
- При сохранении все файлы, в том числе скопированные, читаются обратно и сверяются с SHA-256 манифеста, страницы и тексты проходят обычную проверку и индексируются для поиска.
- Файл, заблокированный модератором, не копируется: правка отказывает, как отказало бы чтение.
- Лимиты — проекта (400 файлов, 48 МиБ), а не 64 файлов и 8 МиБ, которые может передать один вызов `polka_capture`.

Так же устроена новая версия из папки ([PUBLISH_API](../PUBLISH_API.md#polka-pull-и-push)): `polka-pull.mjs` скачивает версию в папку, `polka-publish-project.mjs` этой папки отправляет только изменённые файлы, а совпадающие с базовой версией хранилище копирует (`POST /api/v1/projects/:uploadId/reuse`).

## Просмотр

### Просмотрщик проектов (домен просмотра)

`GET /project/:token/<путь>` на домене просмотра отдаёт файл закреплённой версии проекта по его пути.

- **Доступ** — отдельная таблица `project_view_grants`.
  - Доступ живёт 30 минут и привязан к версии и к сессии владельца либо к ссылке получателя. Каждое чтение перепроверяет корзину, отзыв ссылки и выход из аккаунта, как у просмотра одной страницы.
  - 60 секунд, как у обычного просмотра, здесь не хватит: проект читают долго, страница за страницей.
  - Токен стоит в пути, поэтому относительные адреса внутри проекта (`shared/y360.css`, `../02-users/roles-jobs.md`) разрешаются сами.
- **HTML-страницы** отдаются как есть, в песочнице:
  - `sandbox allow-scripts allow-forms`, без `allow-same-origin`, всплывающих окон и выхода наверх (`form-action 'none'` не даёт форме ничего отправить);
  - CSP разрешает стили, скрипты, картинки и шрифты только из `<домен просмотра>/project/<токен>/`, `connect-src` разрешает только `fetch` своих файлов проекта (без внешней сети), а `frame-src`, `form-action` и `worker-src` закрыты;
  - ресурсы отдаются с `Access-Control-Allow-Origin: *`: страница в песочнице живёт с origin `null`, и обычная сборка Vite (`<link rel="stylesheet" crossorigin>`, модульный скрипт), шрифты, `fetch` и медиа с `crossorigin` иначе блокируются. Токен в пути и есть право на чтение, заголовок не открывает то, что нельзя было прочитать и без него;
  - внешние ссылки идут через подписанную страницу `/away` в новой вкладке;
  - ссылки внутри проекта открываются в том же окне просмотра.
- **Markdown** Полка рисует сама: `marked` (MIT, без зависимостей), HTML автора показывается как текст; таблицы, списки, код. Страница собирается в шаблон Полки со своими стилями, без скриптов автора.
  - `marked` квадратичен на некоторых входах, поэтому документ до 4 КБ рисуется сразу, больше — в воркере с дедлайном 3 с, а больше 512 КБ или не успевший за дедлайн показывается как текст. Нарисованная страница хранится в памяти по версии и пути.
  - Markdown-ссылки на путь и пути в обратных кавычках (`` `02-users/user-stories.md` ``), указывающие на файл проекта, становятся переходами.
  - Путь ищется так: от документа → от корня проекта → по имени файла, если оно в проекте одно. В Y360-v2 так разрешаются 167 из 182 упоминаний.
  - Остальные показываются как код с пометкой «вне проекта».
  - Картинки проекта показываются, внешние картинки — нет.
- **Картинки и текст** показываются простой страницей Полки.
- **Субресурсы** (CSS, JS, шрифты, картинки) отдаются только на запрос из страницы (`Sec-Fetch-Dest` не `document`/`iframe`). HTML и Markdown отдаются только как документ во фрейме (`iframe` + `navigate`), как у существующих просмотрщиков.
- **Синхронизация с деревом.** В самое начало каждой страницы (до `<!doctype>` и `<head>` исходника, чтобы ни один скрипт страницы не выполнился раньше) добавляется скрипт Полки `__polka/nav.js` (разрешён CSP по адресу) вместе с защитой от WebRTC. Страницы проекта получают и `VIEWER_GUARD`; у страниц Markdown, картинок и текста его sha256 указан в CSP. Он сообщает родителю путь открытой страницы (`postMessage` на `APP_ORIGIN`), чтобы дерево подсветило её, и передаёт приложению внешние ссылки: песочница без всплывающих окон, поэтому подписанную страницу `/away` открывает приложение.
- **Кэш.** Страница проекта просит десятки файлов, и каждый раз проверка доступа — запрос на шесть таблиц. Положительный ответ хранится `VIEWER_AUTH_CACHE_SECONDS` (10 секунд по умолчанию, 0 — проверять каждый раз): отзыв ссылки, корзина или выход закрывают открытый просмотр в пределах этого срока, а не на следующем же файле. Файл версии отдаётся с `ETag` (его SHA-256) и `Cache-Control: private, max-age=60`; на `If-None-Match` в ответ идёт `304` без чтения объекта. Страницы и Markdown собираются на каждый просмотр и не кэшируются. Текст на домене просмотра сжимается Caddy (zstd, gzip).
- **Модерация ссылки.** Каждое чтение по ссылке проверяет, что ссылка не отозвана, не истекла, не на паузе и не на проверке (`shares.moderation='none'`) и не снята из Ленты. Пауза после жалоб закрывает открытый проект сразу.

### Проект как приложение

Если точка входа — HTML-страница (игра, прототип, собранный сайт), проект открывается как эта страница на всю область, без дерева файлов. Кнопка «Файлы проекта · N» над страницей раскрывает дерево, «Скрыть файлы» убирает его. Проекты с `README.md` открываются с деревом, как раньше. У рамки просмотра стоит `allow="fullscreen"`, поэтому собственная кнопка «на весь экран» в игре работает.

### Страница проекта (приложение)

У владельца (`/works/:id`) и получателя (`/s#…`) одна раскладка:
- **Слева** — дерево. Папки сворачиваются. Точка входа и README разделов идут первыми. Документы и страницы показаны сразу, ресурсы (CSS, JS, шрифты) — под «Файлы проекта».
- **Сверху** — хлебные крошки и «Открыть отдельно».
- **Справа** — iframe просмотрщика проектов.

Адрес страницы помнит открытый путь (`/works/:id#path=02-users/user-stories.md`), поэтому ссылку на конкретный документ можно переслать. На телефоне дерево открывается кнопкой «Содержание».

## Этапы

1. **Хранение и загрузка.** Рантайм `project-v1`, лимиты, Markdown и GIF в типах, миграция (ограничения на число файлов, размер и точку входа проекта), HTTP API с токеном, скрипт `polka-publish-project.mjs`, модерация и поиск по всем страницам.
2. **Просмотрщик проектов.** Доступы, маршрут, markdown с разрешением ссылок, CSP, скрипт синхронизации.
3. **Страница проекта** у владельца и получателя: дерево, крошки, адрес с путём.
4. **Ссылки на проект** для получателя, обложка проекта на полке, указание агентам в скилле и `llms.txt`.

## Ограничения

- Скрипты HTML-страниц работают, но без сети: данные только из файлов проекта.
- Страницы проекта не собираются в интерактивную версию с React-рантаймом, скрипты с CDN (React, Babel) не загружаются. Для компонента есть обычные работы; загрузчик сам отправляет туда папку из одного компонента.
- Через `polka_revise` правится один текстовый файл за вызов (раздел «Правка одного файла»). Добавить, удалить или заменить картинку — новой версией проекта целиком.
- Ссылки из markdown на файлы вне проекта не открываются.
