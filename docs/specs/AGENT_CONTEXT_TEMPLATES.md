## Сценарий

Откройте свой материал → **Скопировать для агента**. Обычный материал предлагается как источник. Выберите «Сохранить эту версию как шаблон», укажите назначение, правила и необязательные вопросы. После закрепления шаблон по умолчанию используется как основа. Можно выбрать только оформление. Обязательной задачи на Полке нет: задача остаётся в существующем чате агента.

Раздел **Шаблоны** доступен из меню личной Полки и по `/templates`. По умолчанию каталог показывает последний закреплённый выпуск каждого материала. Предыдущие доступны по переключателю. Поиск работает по названию и назначению; прежний выпуск не подставляется вместо актуального только потому, что подошёл поиску. Открытие материала закрепляет revisionId в URL; отсутствующая версия не заменяется последней.

Копируемый текст содержит artifactId, revisionId, releaseId при наличии, назначение, правила, вопросы и способы получить исходники. Это не запуск, не публикация, не новое поручение и не доказательство чтения агентом. Предпросмотр текста раскрывается отдельно. При отказе clipboard раскрывается и выделяется текст для ручного копирования.

Без подключения: ZIP с README.md, context.md, manifest.json и точными исходными файлами в sources/. Отдельные файлы доступны в панели. ZIP не гарантированно понимается любым агентом; его можно распаковать. Скачанные копии не отзываются вместе с серверным доступом.

## API и MCP

- GET `/api/artifacts/:id/agent-context?revisionId=...&purpose=base|source|style`
- GET `/api/artifacts/:id/agent-package?revisionId=...&purpose=...`
- GET `/api/artifacts/:id/agent-file?revisionId=...&path=...`
- POST `/api/artifacts/:id/template-releases`: revisionId, summary, rules, questions
- GET `/api/templates?query=...&includePrevious=true`: поиск по названию/назначению; по умолчанию один последний выпуск на материал; до 100 совпадений, `hasMore` предлагает уточнить запрос
- MCP `polka_read_source`: точные artifactId/revisionId, необязательный purpose. Контекст, manifest и реальные файлы base64.
- MCP `polka_list_templates`: параметры `query` и `includePrevious`, разрешённые выпуски с точными идентификаторами и `isLatest`; та же логика, что в UI.

Новое явное разрешение **source:read** («Читать исходники и шаблоны») даёт доступ к исходникам всей Полки владельца. Старые токены с read сохраняют metadata-only доступ. Новый scope нужно сознательно выбрать при создании подключения; токены автоматически не расширяются. UI и MCP используют один серверный контракт. Проверки выполняются заново при чтении; чужой tenant, несовпадающая revision, корзина, отозванное подключение запрещены. Public preview не предоставляет source:read.

## Хранение и развёртывание

Миграция 021 добавляет template_releases и новое допустимое значение scope. Выпуск закреплён за revision; повтор идентичного сохранения возвращает тот же release. Другие правила для той же revision возвращают 409. Нужна новая версия для нового выпуска. Удаление artifact/revision каскадно удаляет выпуск; исходные байты и immutable manifest не меняются. Runtime grants обновлены до 021: SELECT/INSERT на releases, без UPDATE/DELETE. Сначала резервная копия и миграция, затем новый сервер; не откатывать схему удалением данных.

Рабочая установка 4390 обновлена до schema21. Приватный backup: `.local/backups/agent-context-schema21-1789985487971/metadata.dump`. Cloud rollout не проводился.

## Что остаётся за пределами этого среза

Это **личный каталог в существующем tenant**, а не общая библиотека компании. Нельзя давать сотрудникам один токен или обходить изоляцию ради шаблонов. Для общей библиотеки нужны организация/членство, роли редактора и читателя шаблонов, отдельный доступ к исходникам, публикация/отзыв корпоративного выпуска, аудит и проверка после исключения сотрудника. Публичный доступ к просмотру не должен автоматически раскрывать брендовые исходники.

Также остаются: пагинация большого каталога (поиск реализован), человеческая сертификация корпоративного стиля, ручная проверка минимум в одном реальном подключённом агенте и одном агенте с прикреплёнными файлами, реальная пользовательская приёмка. Редактор презентаций и встроенный чат не входят в эту функцию.

Подробный следующий этап: [библиотека компании — истории, роли, данные, UI/MCP и приёмка](COMPANY_TEMPLATE_LIBRARY.md). Реализованные части и оставшиеся ограничения указаны в таблице выше; личный каталог не подменяет общую библиотеку.

### Реализована основа библиотеки, ещё без пользовательских маршрутов

## Обычные исходники — серверный пакет реализован

Реализуется передачу single-file text/plain, image/png, image/jpeg, image/webp через существующие context/MCP/ZIP/file endpoints. Новые форматы загрузки, включая PDF, в этот пакет не входят.

- Stored revision и HTML BundleManifest не менять. Для non-HTML нужен отдельный versioned sourceDescriptor, без runtime/entrypoint обещаний, manifest/manifestSha256=null. HTML response сохраняет прежний manifest.
- availableContent и sourceDescriptor используют детерминированный безопасный путь source.txt/png/jpg/webp по MIME. Пользовательское имя не становится ZIP path; данные title/filename не являются командами.
- Source reader проверяет pinned object version, размер, SHA256 и MAX_BYTES под той же транзакцией авторизации. Не менять builder reader ради обычных файлов.
- Приёмка: текст и изображение дают одинаковые bytes через MCP/ZIP/file; personal outsider и revoked library member отклоняются; точные publication/revision сохраняются; mismatch bytes вызывает отказ. HTML regression обязателен.
- Публикация версии шаблона разрешена и для этих материалов, вопросы остаются необязательными; обычный материал по умолчанию источник. UI не должен обещать HTML-preview текстового/графического файла.


Серверный пакет принят 21.09.2026: check; single-file+HTML regression 3/3; library-source 1/1, оба прогона isolated с cleanup и workingResourcesModified=false. Ведущий проверил pinned object version, отказ при checksum mismatch и правила purpose (release→base, без release→source). `sourceDescriptor={kind:"single-file",schema:1,files:[...]}` добавляется только для non-HTML; HTML manifest не меняется. Catalog возвращает mime в обеих ветках. Следующий UI-пакет: не предлагать HTML live-preview non-HTML шаблонам, оставить передачу исходников и показать формат.

Интеграционный npm test на schema26: 241 passed, 0failed/0skipped; результат. Новый UI истории проверен check/build отдельно; браузерная приёмка не подменяется этим прогоном.
