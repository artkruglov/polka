# Видео в проектах

> **Статус:** в коде с 30.09.2026, миграция 050. Работает у проектов (`project-v1`): игра, презентация или отчёт, у которых рядом со страницами лежит MP4 или WebM.

Проект сохраняет видео как обычный файл версии: тот же манифест, неизменяемая версия, квота, корзина и удаление. Отличается путь байтов: видео большое, поэтому оно нигде не читается в память целиком.

## Лимиты

| | Страницы, картинки, текст | Видео |
|---|---|---|
| Типы | как у проекта | `video/mp4`, `video/webm` |
| Один файл | до 5 МиБ | до 200 МиБ |
| Всего в проекте | до 48 МиБ | до 400 МиБ сверху |

Видео учитывается в квоте полки как обычные байты (по умолчанию 100 МиБ). Вместо этого лимита оператор ставит полке свою квоту.

## Кто может

Скана видео у Полки нет: страницы, тексты и картинки проходят фильтр, видео нет. Поэтому видео сохраняется только на полке с флагом `tenants.video_enabled` (по умолчанию выключен). Оператор включает его вместе с квотой:

```sql
UPDATE tenants SET video_enabled=true, quota_bytes=2147483648 WHERE owner_id=(SELECT id FROM accounts WHERE name='…');
```

Без флага `POST /api/v1/projects` с видео в манифесте отвечает `403` и просит написать оператору. Жалоба, блокировка и юридическое удержание работают с видео как с любым файлом версии.

## Загрузка

`PUT /api/v1/projects/:uploadId/media/:index` принимает байты как `application/octet-stream` с `Content-Length`.

- Тело не буферизуется. Полка читает поток кусками по 8 МиБ и отправляет их в S3 как multipart-загрузку; в памяти не больше двух кусков.
- Пока идёт поток, считаются размер и SHA-256, проверяются первые байты (`ftyp` у MP4, заголовок EBML у WebM). Если что-то не совпало с манифестом, multipart-загрузка отменяется: версии объекта не появляется.
- Повтор того же файла безопасен: хранилище возвращает уже записанную версию.
- Запрос может идти до 20 минут; у остальных запросов на приём 30 секунд (`onRequest` в `app.ts`).
- На сохранении (`finalize`) видео не читается обратно: сверяются размер и SHA-256 из метаданных объекта (`HeadObject`). Метаданные записаны при загрузке и сохраняются при копировании.
- Новая версия проекта не пересылает видео, которое не менялось: `POST …/reuse` копирует его внутри S3.
- Видео меньше 5 МиБ можно отправить и обычным `PUT …/files/:index`.

Готовый клиент `polka-publish-project.mjs` считает хеш потоком, отправляет видео через `/media/` и в отчёте пропускает файлы больше 200 МиБ. `polka-pull.mjs` пишет видео на диск потоком и проверяет хеш.

## Просмотр

`GET /project/:token/<путь>` на домене просмотра отдаёт видео с поддержкой `Range` (`206 Partial Content`, `Accept-Ranges: bytes`, `416` за пределами файла). Из хранилища читается только запрошенный кусок, поэтому перемотка не тянет весь файл.

- Как и ресурсы страницы: только по запросу `<video>` (`Sec-Fetch-Dest: video`), не как документ и не как скрипт или картинка. Часть движков не шлёт Fetch Metadata для медиа, в этом случае файл тоже отдаётся: токен в пути — это и есть право на чтение, а видео не выполняет скрипты.
- CSP страниц проекта уже разрешает `media-src` только с адреса проекта.
- Каждый запрос перепроверяет корзину, отзыв ссылки, выход из аккаунта и блокировки, как чтение любого файла проекта.
- Файл в дереве проекта открывается страницей с плеером (`<video controls>`) внутри обычной песочницы просмотрщика.

## Чего нет

- Видео нельзя отдать одним JSON-ответом: `polka_read_source` и экспорт версии отказывают (`422`) и советуют `polka-pull.mjs`.
- Браузерная загрузка (перетаскивание файла на полку) видео не принимает: там по-прежнему до 5 МиБ и один файл. Видео идёт через агента или CLI.
- Полка не перекодирует видео и не делает превью. Кодек и битрейт остаются на авторе: для игры и презентации хорошо подходит H.264 (MP4) с `faststart`, чтобы воспроизведение начиналось сразу.
- Скачивание из хранилища идёт через приложение, а не по подписанной ссылке: нагрузка на VM растёт с числом зрителей. Если видео начнут смотреть часто, отдача перейдёт на подписанные короткие ссылки хранилища или CDN.
- Незавершённые multipart-загрузки (обрыв сети между частями) в хранилище удаляются правилом жизненного цикла бакета `AbortIncompleteMultipartUpload`; сама Полка отменяет загрузку, когда видит ошибку.
