# Форматы одиночных работ: Markdown, CSV, JSON, PDF

> **Статус:** реализовано 15.10.2026 (решение владельца, issue #46): Markdown, CSV и JSON — часть 1, PDF — часть 2 ([ниже](#pdf)). Миграции не требует: `revisions.mime` — свободный текст, лимит размера — прежний `MAX_BYTES` (5 МБ).

Работа из одного файла бывает не только страницей, текстом или картинкой. Агенты часто отдают результат документом в Markdown, таблицей CSV или ответом в JSON. Такой файл теперь сохраняется как есть и показывается в своём виде: документ свёрстан, таблица — таблицей, JSON — кодом. Оригинал скачивается без изменений.

## Форматы

Одна таблица `SINGLE_FILE_FORMATS` в [packages/contracts/constants.ts](../../packages/contracts/constants.ts) описывает каждый формат: слово для полки, расширения, текстовый ли он и как показывается (`view`). Её читают форма загрузки, проверки сервера, поиск, контекст агента и просмотр.

| MIME | Расширения | Слово | Показ |
|---|---|---|---|
| `text/markdown` | `.md`, `.markdown` | Документ | свёрстанный документ |
| `text/csv` | `.csv` | Таблица | таблица, до 2 000 строк |
| `application/json` | `.json` | JSON | код как есть |
| `application/pdf` | `.pdf` | PDF | страницы pdf.js на домене просмотра |
| `text/plain` | `.txt` | Текст | чтение текста, как раньше |
| `text/html` | `.html`, `.htm` | Страница | статичный или интерактивный просмотр |
| `image/png`, `image/jpeg`, `image/webp` | | Изображение | картинка |

`isTextMime()` — текстовые форматы, кроме HTML (текст, Markdown, CSV, JSON): их байты и есть их текст. `isDrawnMime()` — форматы, для которых Полка рисует свою страницу (Markdown, CSV, JSON). `mimeForFilename()` определяет формат по расширению.

Пакеты не меняются. В пакете страницы по-прежнему нет `text/csv` и `text/markdown`, в проекте нет `text/csv`; Markdown остаётся форматом проектов и одиночных работ.

## Сохранение

- **Веб:** «Сохранить работу с компьютера» и страница «Сохранить» принимают `.md`, `.csv`, `.json`. Тип определяется по расширению: Windows называет CSV `application/vnd.ms-excel`, macOS часто не даёт Markdown типа. Название для `.md` берётся из первого заголовка `#`.
- **Проверки сервера** (`validateBytes`): UTF-8 без NUL для всех трёх; JSON должен разбираться `JSON.parse`. CSV в другой кодировке отклоняется с подсказкой сохранить файл как «CSV UTF-8».
- **Агенты:** `polka_publish` и `POST /api/v1/publish` принимают `kind: "file"` с `name` и `text` (или `base64` для картинки), `mime` — если имя без известного расширения. До 5 МБ. HTML в `kind: "file"` не принимается: страница идёт в `html`. Сохранение идёт обычными шагами одиночной загрузки (`saveSingleFile`): идемпотентность по `key`, CAS новой версии по `baseRevisionId`, перенос открытой ссылки на новую версию — как у страницы. CLI `polka-publish.mjs` отправляет так файлы `.md`, `.csv`, `.json`, `.txt`, `.png`, `.jpg`, `.webp`; раньше Markdown и текст он заворачивал в HTML.
- **Перенос полки** (`shelf-import`) принимает новые форматы сам: он строит тот же запрос сохранения.

## Показ

Страницу документа рисует Полка ([apps/server/single-file-view.ts](../../apps/server/single-file-view.ts)): своя разметка вокруг экранированного текста, без скриптов, сети и HTML автора.

- **Markdown** — тем же рендером, что документы проекта (`renderProjectMarkdownBounded`, пул воркеров с дедлайном и кэшем). У одиночного документа нет соседних файлов: путь в обратных кавычках остаётся кодом, относительная ссылка — текстом, картинки по относительному пути не показываются. Внешние ссылки ведут через подписанную страницу `/away`. HTML автора показывается текстом.
- **CSV** — таблица с шапкой из первой строки и номерами строк. Разделитель (запятая, точка с запятой, табуляция) определяет papaparse; BOM отбрасывается. Показываются первые 2 000 строк и 200 столбцов, с пометкой; остальное — в оригинале. Файл до 16 КБ разбирается на запросе, больше — в пуле воркеров с дедлайном 3 с; не успел — таблица показывается текстом.
- **JSON** — код как есть, без переформатирования: так не теряются большие числа и порядок ключей.

Страница отдаётся только с домена просмотра, по тем же правилам, что статичный просмотр HTML ([static-viewer.ts](../../apps/server/static-viewer.ts)): грант на 60 секунд, привязанный к сессии владельца или к grant получателя, проверка корзины, отзыва, выхода и блокировки при каждом чтении, только во фрейм приложения (Fetch Metadata), CSP статичного просмотра. С комментариями ответ несёт оверлей под nonce, как страница. С домена приложения такие работы не отдаются никогда: без домена просмотра (`HTML_LIVE_ENABLED=false`) приложение показывает текст файла (`<pre>`) из `/api/revisions/:id/bytes` или `/api/view/bytes`.

## Остальное

- **Поиск** читает файл как текст при сохранении и в `search-backfill` (одиночные Markdown, CSV, JSON больше не читаются как HTML), см. [CONTENT_SEARCH](CONTENT_SEARCH.md).
- **Фильтр содержимого** при сохранении и **модель-ревьюер** читают файл как текст.
- **Обложка:** Markdown — заголовок и первые строки, как у текста; CSV и JSON — жанры «Таблица» и «JSON» с названием работы.
- **Полка:** чип «Документы» включает все три формата; агенту `kind` работы — `text`.
- **Контекст агента** отдаёт файл как `source.md`, `source.csv`, `source.json` ([AGENT_CONTEXT_TEMPLATES](AGENT_CONTEXT_TEMPLATES.md)); `polka_read_file` читает CSV как текст.

## PDF

Строка `application/pdf` в `SINGLE_FILE_FORMATS`: `text: false`, `view: "pdf"`, `isPdfMime()`. Библиотека одна — `pdfjs-dist` (pdf.js, Apache-2.0, версия закреплена в `package.json`): на сервере она читает текст, в браузере рисует страницы.

### Сохранение

- **Проверка** (`validateBytes`): файл начинается с `%PDF-`, и pdf.js его открывает. Повреждённый файл, обрезанный файл или не-PDF с расширением `.pdf` — 422 с понятным текстом («Файл не открывается как PDF…»), не 500. PDF с паролем — 422 («Сохраните его без пароля»): его нельзя ни прочитать для проверки, ни показать.
- **Чтение** ([apps/server/pdf-reader.ts](../../apps/server/pdf-reader.ts)) идёт в пуле воркеров (`worker-pool.ts`, задача `pdf`), как разбор страницы: дедлайн 5 с (3 с, как у Markdown, плюс загрузка pdf.js в воркер в первый раз), лимит кучи воркера. pdf.js там только парсер: его «воркер» работает в потоке пула (`globalThis.pdfjsWorker`), своих потоков он не запускает; шрифты, canvas, картинки и сеть не используются (байты передаются как `data`, адресов шрифтов, CMap и wasm нет). В pdf.js 6 нет пути через `eval` (опция `isEvalSupported` удалена вместе с ним). Читаются первые 300 страниц, не больше 240 000 символов текста (`SEARCH_TEXT_CHARS × 4`) и 1 000 ссылок. Одно чтение на версию: ответ хранится по SHA-256 для второго шага сохранения, обложки, поиска и агента.
- **Не успел за дедлайн** — PDF сохраняется без текста и считается непроверенным, как страница, которую не удалось прочитать: сигнал `scan:incomplete`, ссылка ждёт модератора, если модерация включена.
- **Агенты и CLI:** `kind: "file"` с `name: "….pdf"` и `base64` (в `text` PDF не принимается: 422). `polka-publish.mjs report.pdf` отправляет так.

### Что читается из текста и ссылок

- **Поиск** — текст pdf.js при сохранении и в `search-backfill`, см. [CONTENT_SEARCH](CONTENT_SEARCH.md).
- **Фильтр содержимого** при сохранении — тот же текст; JavaScript документа, страниц и аннотаций идёт в фильтр как код (как обработчики `on*` страницы) и никогда не выполняется.
- **Ссылки** (аннотации `Link` с действием URI) проверяются теми же правилами, что `<a href>` страницы (`inspectHtml`): `SignalCollector.address` — похожие домены брендов и страницы входа на чужих сайтах — и `link()` фильтра содержимого. Сигналы сохраняются в `revisions.phishing_signals`, и ссылка на PDF решается при выдаче так же, как ссылка на страницу (`isSuspicious`, `decideContent`). `moderation.ts recheck --fraud` читает PDF заново.
- **Модель-ревьюер** получает текст и список адресов ссылок («Ссылки в PDF»).
- **Обложка** — жанр «Документ», заголовок и первые строки текста, как у заметки. Картинки первой страницы нет: рендерер PDF не рисует (и в облаке не развёрнут). PDF без текста (скан) — карточка «Документ» с названием.
- **Контекст агента** — `source.pdf` как есть и `source.txt`, текст pdf.js, для агентов, которые не читают PDF ([AGENT_CONTEXT_TEMPLATES](AGENT_CONTEXT_TEMPLATES.md)). Без текста — только `source.pdf`.

### Показ на домене просмотра

Страница ([apps/server/single-file-view-pdf.ts](../../apps/server/single-file-view-pdf.ts)) отдаётся по `/static/:token` той же цепочкой грантов, что статичный просмотр (60 секунд, сессия владельца или grant получателя, корзина, отзыв, блокировка — при каждом чтении, только во фрейм приложения). В ней:

- сам PDF — base64 в блоке данных `<script type="application/pdf;base64">`, который браузер не выполняет (в base64 нет `<`, закрыть блок нельзя): у фрейма нет сети, поэтому файл приходит внутри страницы, а не запросом;
- скрипт Полки `pdf-view.mjs` и два модуля pdf.js (`pdf.min.mjs`, `pdf.worker.min.mjs`, legacy-сборка — она работает и в старом Safari) с самого домена просмотра, по пути `/__polka/pdf/<версия pdf.js>/`. CDN нет. Файлы отдаются только как скрипт (Fetch Metadata), с `access-control-allow-origin: *` (модули грузятся в режиме CORS, а у песочницы origin `null`) и кэшем на год — путь меняется с версией.

CSP страницы — CSP статичного просмотра плюс ровно то, что нужно pdf.js:

```
sandbox allow-scripts; default-src 'none'; script-src <VIEWER_ORIGIN>/__polka/pdf/<версия>/;
style-src 'unsafe-inline'; img-src data: blob:; font-src data:; connect-src 'none'; worker-src 'none';
child-src 'none'; frame-src 'none'; object-src 'none'; manifest-src 'none'; form-action 'none';
base-uri 'none'; frame-ancestors <APP_ORIGIN>
```

- `script-src` — только путь pdf.js на домене просмотра: ни inline-скриптов, ни `'unsafe-eval'`, ни `'wasm-unsafe-eval'`.
- `worker-src 'none'` остаётся: парсер pdf.js работает в потоке страницы (`globalThis.pdfjsWorker`), отдельный worker не создаётся. Для PDF до 5 МБ это незаметно, а песочнице не нужен ни `blob:`-worker, ни worker с чужого origin.
- `img-src blob:` — pdf.js передаёт декодированные картинки на canvas так.
- `sandbox allow-scripts` без `allow-same-origin`, `allow-forms`, `allow-popups` и навигации верхнего окна.

JavaScript и формы PDF не выполняются: модуль песочницы скриптов pdf.js (`pdf.sandbox`) не загружается вовсе (`enableScripting: false`), XFA выключен, аннотации рисуются картинкой без полей форм (`AnnotationMode.ENABLE`). Ссылки в PDF не кликабельны (слоя аннотаций нет); текст поверх страниц выделяется и копируется (текстовый слой pdf.js).

Страницы рисуются по мере прокрутки (`IntersectionObserver`, за 1 200 px до экрана) по ширине фрейма, с учётом плотности экрана, не больше 16 Мп на canvas; дальше 12 нарисованных страниц самые далёкие освобождают память и рисуются снова при возврате. Поворот телефона перерисовывает страницы под новую ширину. Работает на ширине 390 px.

Без шрифтов из сети: используются шрифты, встроенные в PDF, а стандартные 14 шрифтов — системными. Картинки JPEG 2000 и JBIG2 (им нужен wasm) не рисуются.

Комментарии к PDF — на всю работу: оверлей цитат в PDF не добавляется.

### Без домена просмотра

PDF никогда не показывается с домена приложения. Без домена просмотра (`HTML_LIVE_ENABLED=false`) владелец видит карточку «PDF, размер» с кнопкой «Скачать PDF» (`/api/revisions/:id/bytes`, `content-disposition: attachment`), ссылка на PDF не выпускается (422, как у проекта), `polka_publish` сохраняет работу и объясняет, почему ссылки нет. Получатель оригинал не скачивает: `/api/view/bytes` для PDF отвечает 404 на любой установке.

### Остальное

- **Сравнение версий:** «Версия N — PDF: версии PDF не сравниваются построчно».
- **Перенос полки** переносит PDF как любой одиночный файл; на новой полке текст снова читается для поиска.
- **Полка:** чип «Документы», слово «PDF»; агенту `kind` работы — `file`; `polka_read_file` отдаёт PDF в base64.
