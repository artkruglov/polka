# Эксперимент импорта опубликованного Claude artifact

> **Статус:** историческое. Итог: сервер Полки не может сам забрать артефакт по ссылке Claude; см. [FAQ](../faq.md#почему-нельзя-вставить-ссылку-на-артефакт-claude-или-chatgpt).

Дата: 20.09.2026. Проверка с локальной машины; cloud fetch и автоматическое извлечение исходников пока не подтверждены. Цель остаётся прежней: публичная ссылка → независимая копия артефакта с ресурсами. Ручное сохранение файла не закрывает эту приёмку.

## Объект и метод

Выбран узкий кандидат: опубликованный chat artifact по адресу `https://claude.ai/public/artifacts/<uuid>`.

Проверенная ссылка: [минимальный React test artifact](https://claude.ai/public/artifacts/8b241cc8-6938-4ace-97f0-05fa098b296c). Автор публично разместил её как минимальный 15-строчный пример для воспроизведения ошибки в [anthropics/claude-code #42064](https://github.com/anthropics/claude-code/issues/42064). Это источник тестового URL, а не подтверждение текущего состояния сервиса или лицензии на включение кода в наш corpus.

Выполнен обычный HTTPS GET через curl без cookies и Authorization, без следования redirects; timeout 20 секунд, максимальный ответ 5 MiB. Сначала просмотрены headers, затем отдельным GET прочитан полный body в память. Последующая отдельная проверка разобрала script-теги и искала UUID; файлы провайдера не сохранялись в репозиторий и не исполнялись.

## Наблюдения

- HTTP `200`, `Content-Type: text/html`, `Cache-Control: private, no-store`.
- Полный body одного ответа: **123 943 bytes**, SHA-256 `34d6ca1aa6e87c7b93fa77cc70fe7442e1d8d37ea8e5e9016f4e1b79df7a9a62`. Это hash конкретного ответа оболочки, не артефакта и не обещание стабильных bytes между запросами.
- HTML содержит пустые `div#root` и `div#portal-root`, внешний module script `https://assets-proxy.anthropic.com/claude-ai/v2/assets/v1/index-CxJWxBM9.js`, ссылки на CSS и fonts провайдера. В разобранном ответе iframe-тегов и UUID выбранного артефакта не найдено.
- Один inline bootstrap содержит шаблон `/api/published_artifacts/${e}`. Этот API endpoint **не запрашивался**; его доступность, авторизация, формат и содержимое не установлены.
- Источник пользовательского React-компонента и полный набор его ресурсов не извлечены. Наблюдаемый ответ соответствует оболочке приложения Claude; его нельзя принимать за автономный HTML/bundle и выдавать успешный capture receipt.

## Публичная документация и ограничения вывода

[Официальная справка о публикации и sharing](https://support.claude.com/en/articles/9547008-publish-and-share-artifacts) различает published chat artifacts, доступные для просмотра без аккаунта, и artifacts нового Share dialog, для открытия которых аккаунт требуется. Она описывает ручное копирование кода опубликованного chat artifact. Это не документированный контракт серверного source-export API.

При отдельном GET [robots.txt](https://claude.ai/robots.txt) наблюдались `Disallow: /api/*` для общего crawler и `Disallow: /` для перечисленных OpenAI user agents. **Это crawler guidance, а не установленный этим экспериментом юридический запрет или доказательство технической недоступности API.** Юридическая оценка и согласование автоматического доступа не проводились. Из обходов доступа, подмены fingerprint или использования пользовательских cookies эксперимент не состоит.

Не проверены: браузерный runtime самого repro, его текущая работоспособность, содержимое API, разрешённый автоматический экспорт, полнота зависимостей, fetch из будущего cloud и автономное выполнение импортированной копии. Публичность repro не устанавливает лицензию на его дальнейшую публикацию в составе Полки.

## Результат и следующий шаг

**Автоматический source capture по Claude URL пока не подтверждён.** Получение оболочки с HTTP 200 не закрывает R07. Следующий эксперимент требует собственного опубликованного артефакта с известными bytes/правами и проверки разрешённого способа получить его source/resources, затем cloud fetch и автономного воспроизведения без обращений к Claude/CDN. При оболочке или недоступном источнике adapter должен вернуть явную ошибку без artifact receipt. Shared conversation, embed и screenshot независимую копию не заменяют.

## Повторная проверка ведущим

20.09.2026 обычный urllib HTTPS GET того же публичного URL с этой машины, без cookies/Authorization и без изменения User-Agent, вернул HTTP403. API в этом запросе не проверялся. Fingerprint и cookies для обхода отказа не подбирались. Различие с предыдущим200 означает, что успешную доступность нельзя предполагать по одному запросу; это не доказательство недоступности источника для всех пользователей. Source capture по-прежнему не подтверждён.

## 21.09.2026: проверка через новый public-fetch

Без cookies/Authorization: исходный URL вернул text/html, 123943 bytes, пустой div#root и ссылку на published_artifacts API. Запрос указанного публичного /api/published_artifacts/8b241cc8-6938-4ace-97f0-05fa098b296c вернул HTTP403. Это не source capture. Никакие данные источника не внесены в corpus. Новый fetch закрепляет проверенный публичный IP в соединении и не передаёт авторизационные данные. Ограничение источника сохраняется; оно не блокирует разработку общего importer и автономного HTML adapter.
