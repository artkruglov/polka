# Полки отделов

> **Статус:** спека, 25.09.2026. Первый пункт пакета для корпоративного пилота ([roadmap](../roadmap.md), этап 6). Решение о модели принято 25.09.2026: полка отдела — отдельное пространство компании, а не каталог поверх личных полок.

Полка отдела — общее место, где работают несколько сотрудников. У неё есть участники с ролями. Сотрудник или его агент сохраняет туда работу, и все участники её видят и находят поиском. Работы принадлежат полке, а не автору: сотрудник уходит — работы остаются.

## Модель

Полка отдела — такая же запись `tenants`, как личная полка. Поэтому всё, что уже привязано к `tenant_id`, работает без изменений: работы, версии, папки, корзина, квота, поиск, обложки, ссылки.

| | Личная полка | Полка отдела |
|---|---|---|
| `tenants.kind` | `personal` | `team` |
| `tenants.owner_id` | аккаунт владельца, как сейчас | `NULL` |
| `tenants.name` | — | «Отдел продаж» |
| Кто имеет доступ | владелец (роль `owner` в `tenant_members`) | участники `tenant_members` с ролями |
| Удаление аккаунта | удаляет полку, как сейчас | удаляет только участие |

`owner_id` полки отдела пустой, поэтому все места, где полку ищут по владельцу (`tenants.owner_id = account`, 22 места), по-прежнему находят ровно одну личную полку. Уникальность `owner_id` сохраняется: `NULL` в Postgres не нарушает `UNIQUE`. Ограничение `CHECK ((kind = 'personal') = (owner_id IS NOT NULL))`.

### Роли

| Роль | Читать, искать, открывать | Сохранять и править свои работы | Править любые, папки, корзина, ссылки наружу | Участники и настройки полки |
|---|---|---|---|---|
| `reader` | да | — | — | — |
| `author` | да | да | — | — |
| `curator` | да | да | да | — |
| `admin` | да | да | да | да |
| `owner` (только личная) | да | да | да | — |

Роли упорядочены: `reader < author < curator < admin`. `owner` личной полки проходит любую проверку роли. В полке отдела всегда есть хотя бы один `admin`, как в библиотеках шаблонов (`ensureAnotherActiveAdmin`).

### Кто создаёт полки отделов

Флаг установки `TEAM_SHELVES=off|on` (по умолчанию `off`, на polochka.app — `off` до пилота). Создавать полки отделов может администратор компании: `accounts.company_admin = true`. Флаг ставит оператор скриптом (`npm run company:admin -- <логин или почта>`). Для своей установки установка = компания; отдельной сущности «организация» в этом срезе нет.

## Схема (миграция 042)

- `tenants`: `kind text NOT NULL DEFAULT 'personal'`, `name text` (1–80 символов, только у `team`), `state text NOT NULL DEFAULT 'active' CHECK (state IN ('active','archived'))`, `created_by uuid REFERENCES accounts`, `created_at`. `owner_id` становится `NULL`-able с `CHECK` выше.
- `tenant_members(tenant_id, account_id, role, state active|revoked, joined_at, revoked_at, invited_by)`, первичный ключ `(tenant_id, account_id)`. Для каждой личной полки миграция записывает владельца с ролью `owner`. История изменений — в журнале.
- `tenant_member_events` — журнал только на добавление, по образцу `template_library_events`: `member_added`, `member_role_changed`, `member_revoked`, `shelf_created`, `shelf_renamed`, `shelf_archived`.
- `accounts.company_admin boolean NOT NULL DEFAULT false`.
- Удаление аккаунта: `terminal_erase_account_metadata` дополнительно отзывает участие аккаунта во всех полках отделов (`state='revoked'`) и не трогает данные полок отделов. Слияние аккаунтов переносит участие.

## Как запрос выбирает полку

- **Веб.** Клиент передаёт текущую полку заголовком `X-Polka-Shelf: <tenantId>`. Без заголовка — личная полка, как сейчас. `identity(req)` проверяет активное участие и активную полку и возвращает `actor = { id, tenant, role }`. Чужая или отозванная полка — 404, как у чужой работы.
- **Агент (этап 3).** Подключение агента привязано к одной полке: на странице «Разрешить» сотрудник выбирает личную полку или полку отдела. Внешние ключи `(tenant_id, account_id) → tenants(id, owner_id)` у `agent_connections`, `oauth_authorizations` и `url_import_jobs` переходят на `tenant_members(tenant_id, account_id)`. Проверка живого подключения добавляет условие «участие активно». Отзыв участника отзывает его подключения к этой полке.

## Проверки прав

`lockActiveOwnerTenant(c, actor)` сейчас требует `owner_id = actor.id`. Вместо неё — `lockShelf(c, actor, minRole)`: блокирует полку, проверяет, что она активна, и что у `actor` активное участие с ролью не ниже `minRole`. Для личной полки владелец — `owner`, поэтому поведение личных полок не меняется. Вызовы переводятся по файлам, каждый с тестом на личную полку (как было) и на полку отдела (роли).

«Владелец» в местах, где сейчас берётся `tenant.owner_id` (ссылки, заметки к ссылке, письма о комментариях, аналитика открытий, модерация), для полки отдела означает «полка активна», а письма и события получает автор версии или создатель ссылки. Эти места переводятся на этапе 5; до этого ссылку наружу из полки отдела выпустить нельзя (честная ошибка «Ссылки из полок отделов появятся позже»).

## Этапы

1. **Основа.** Миграция 042, `tenant_members` с владельцами личных полок, `lockShelf`, выбор полки в `identity`, флаг `TEAM_SHELVES`, скрипт `company:admin`. Личные полки работают как прежде: весь текущий набор тестов проходит без изменений.
2. **Полки отделов в вебе.** Создать полку (администратор компании), участники и роли по образцу библиотек шаблонов (приглашение по почте, журнал), переключатель полок в навигации, сохранение, папки, корзина и поиск на полке отдела с проверкой ролей.
3. **Агенты.** Выбор полки на «Разрешить», подключение к одной полке, `polka_context` называет полку и роль, роль `reader` не может сохранять.
4. **Уход сотрудника и администрирование.** Страница администратора компании: все полки отделов и участники, отключение сотрудника (участие и подключения отзываются, работы остаются). Удаление аккаунта отзывает участие.
5. **Ссылки, заметки и модерация на полках отделов**, затем ссылки только для сотрудников ([roadmap](../roadmap.md)).

## Не в этом срезе

Организация как отдельная сущность с несколькими компаниями на одной установке, SCIM и SAML, перенос работ между личной полкой и полкой отдела (кроме копии через «Сделать свою версию» позже), квоты по компании.
