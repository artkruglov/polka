# Получатель → своя полка

> **Статус:** реализовано 24.09.2026. Страница получателя (`/s#<токен>`) и страница материала Ленты (`/discover/<slug>`) предлагают гостю завести свою полку, не мешая читать работу. Код: `apps/web/src/features/recipient-convert`, `entities/recipient-convert`, `pages/recipient`, `pages/discover`, `apps/server/recipient-cta.ts`, миграция 035. Снимки: `docs/design/2026-09-24-recipient-convert/`.

## Что видит гость

1. **Полоса под работой** (только гостям; не на состояниях «на проверке», «недоступна», «не отвечает»; на страницах Редакции тоже): «Эту страницу сделали с ИИ и сохранили на Полку» + «Попробовать бесплатно» (основная) + «Сделать такую же». Полоса стоит в потоке страницы (`position: sticky; bottom: 0`), поэтому работа уменьшается на её высоту и никогда не перекрывается. На 390 px — одна строка: значок, основная кнопка, «Сделать такую же» значком с `aria-label`; отступ снизу учитывает `safe-area-inset-bottom`. Обе кнопки — обычные `Button`, доступны с клавиатуры.
2. **Карточка** (не модальное окно, страница не блокируется; `role="dialog" aria-modal="false"`, Escape и «Закрыть», фокус на заголовок при открытии и обратно на кнопку при закрытии). Открывается сама **один раз на браузер**: через 15 с просмотра или при первом взаимодействии с работой (pointer/wheel/touch/keydown на сцене, прокрутка страницы, уход фокуса в iframe работы; сообщения из iframe не используются — протокола для этого нет). Кнопки полосы открывают её всегда. Скрытие запоминается в `localStorage` (`polka:recipient-card:*`, try/catch; без хранилища карточка просто покажется снова).
   - «Попробовать»: «Сохраняйте свои работы с ИИ так же» → (a) «Скопируйте своему агенту» — фраза `Подключи Полку: <origin>/connect?ref=share` с кнопкой копирования; (b) «Войти с Яндекс ID» одним нажатием — только когда провайдер настроен (`/capabilities.signInProviders`); (c) «или по почте» → `/signup?next=/s`.
   - «Сделать такую же»: готовый запрос агенту `Сделай похожую <вид работы в двух словах> и сохрани на Полку. Если Полка не подключена — подключи: <origin>/connect?ref=share-remix`. Вид — «интерактивную страницу», «статичную страницу», «изображение», «текстовый документ»; **название работы никогда** (в нём может быть имя или компания).
3. **Возврат на работу после регистрации.** Токен ссылки остаётся во фрагменте и в `sessionStorage` вкладки (`shared/lib/share-return.ts`); в `?next=` уходит только `/s`, для провайдера — `start?next=/s&ref=share`. После входа `/s` восстанавливает фрагмент и показывает строку «Полка создана. Подключите агента одной фразой» (для аккаунта старше 30 минут — «Вы вошли в Полку»; возраст берётся из `createdAt` в `/api/session`) с фразой, копированием и ссылкой «Моя полка».
4. **Первые шаги на полке** для аккаунта, пришедшего с чужой работы (`ref` вкладки `share`/`share-remix`): заголовок «Подключите агента — и он будет сохранять работы сам», фраза первой, «Загрузить файл» вторым (открывает панель загрузки, а не `/bring`).

Имя автора не показывается нигде (часто это часть почты).

## Страница материала Ленты (`/discover/<slug>`)

Тот же принцип «документ главный»: тонкая шапка («← Лента», название, раздел бейджем, «Открыть на весь экран» — `requestFullscreen` сцены), одна строка задачи, затем **сам материал** в том же изолированном фрейме, что у получателя редакционной ссылки (`client.resolve(<токен из recipientUrl>)` → `Preview`), на всю ширину и высоту. Лицензия ушла из шапки в строку подвала «Лицензия материала: Apache-2.0 · Редакция Полки». Гость видит ту же полосу и карточку с `ref=feed` / `feed-remix`; возврат после регистрации — по обычному пути `?next=/discover/<slug>` (в нём нет секретов), метка возврата — `entities/recipient-convert/return.ts` (sessionStorage, 30 минут, один раз).

## Аналитика (без персональных данных)

`POST /api/recipient-cta` принимает два-три слова: `{event:"view", surface: bar|card}` или `{event:"click", action: try|remix|copy_phrase|yandex|email}`, необязательно `page: share|feed`. Считается только для гостей (без сессии) с браузерным User-Agent; лимит по хешу IP; ответ всегда 204. События `recipient_cta_view` и `recipient_cta_click` — анонимные строки `analytics_events` (`actor`/`subject` NULL, `path=/s` или `/discover`), счётчики в `analytics_daily`. Регистрация, начатая здесь, получает источник `ref:share`, `ref:share-remix`, `ref:feed` или `ref:feed-remix` через обычный механизм источника вкладки (`shared/lib/visit-source.ts`, `setVisitSourceRef`).

Отчёт `/ops/metrics`, `GET /api/ops/metrics` (`recipients`) и `npm run metrics`: блок «Получатели → регистрации» по неделям — открытия ссылок (`share_opened`), показы полосы, открытия карточки, нажатия по действиям, регистрации с этих источников и отношения между ними. Это отношения счётчиков, не долей людей: гость не идентифицируется.

## Что не делаем (пока)

- **«Сохранить копию себе»** — нужна явная разрешительная настройка автора (по умолчанию работа приватна, ссылка даёт только просмотр). Следующий шаг: флажок в диалоге «Кто может открыть» («Читатели могут сохранить копию»), после него кнопка на странице получателя и учёт `recipient_cta_click{action: copy_work}`.
- Не показываем автора, не подставляем название работы в подсказки, не отправляем никаких сообщений из iframe работы.
