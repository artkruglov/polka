# Запуск и распространение

Позиционирование первого входа: «Сохраните результат агента и поделитесь своей ссылкой». Второй вход: «Соберите красивый отчёт из примера». Для компании: «Те же работы и разрешённые агенты внутри вашей инфраструктуры». Формулировки описывают поддержанные форматы/сети, а не обход ограничений исходного ИИ-сервиса.

Исследование владельца о росте OSS использовано для гипотезы короткого пути к ценности; цифры/звёзды из него не выдаются за доказательство спроса Полки. До запуска важнее собственный результат и повтор, чем число функций и лайков.

## До первого внешнего трафика

1. Принятый M1: свой поддержанный файл/HTML, просмотр/обновление, понятный доступ и ссылка. S01–S09, S10 для закрытых приглашений; реальные ограничения и инфраструктура. M2/recipe/copy проверяются следующим срезом.
2. Русский README со скриншотами реального интерфейса, короткая демонстрация, проверенный quickstart, synthetic fixtures и пример корпоративной конфигурации без секретов.
3. LICENSE/attribution, CONTRIBUTING, CODE_OF_CONDUCT, SECURITY/contact, issue template и назначенные maintainer/triage роли. Проверка лицензий перенесённых fonts/assets/code; не заявлять готовность файлов, которых нет.
4. GitHub remote, название/домен/metadata, deploy/rollback и help channel. В текущем проходе создан локальный репозиторий; remote, домен, тарифы и публичный сервис ещё не созданы.
5. Для публичного file hosting: оператор, rate/size/storage quotas, abuse report/takedown, safe content handling, минимальное наблюдение, retention и доступный restore. Числовые условия закрепить до приглашения пользователей.

## Проверка пользы

Пригласить 10 реальных людей с готовым поддержанным HTML; для рецепта B провести отдельный опыт после M2. Записывать исходную работу, альтернативу, помощь и время до результата; получателя и возврат в 14 дней. Ориентиры: 7 самостоятельных результатов, 5 за 5 минут, 4 возврата, 3 реальных передачи. Полезная независимая копия — следующая гипотеза после её реализации. Это ориентиры малого опыта, не статистически доказанные показатели.

Проверять получение ссылок в целевых сетях/устройствах, unfurl/preview и понятность разрешений. Не считать автора/бота самостоятельным получателем. Если люди используют только скачивание, выяснить, нужен ли им rich viewer; если не возвращаются — проверить повторяемую работу, не добавлять социальную ленту автоматически.

## Корпоративный путь

Лендинг продукта может индексироваться с первого выпуска. Работы, профили с закрытым содержимым, unlisted links и технические preview не включаются в sitemap/каталог. Индексируемая библиотека M5 требует явной публикации и проверок S12 по [SHARING_AND_DISCOVERY](SHARING_AND_DISCOVERY.md); переключение в private закрывает доступ сразу по принятому контракту, удаление из внешнего поиска наблюдается отдельно.

Три кандидата сценария: еженедельный отчёт отдела; обсуждение продуктового решения с прототипом; библиотека результатов внутренних агентов. Для каждого нужны sponsor, 3–8 пользователей, оператор/допуск, разрешённые источники и агент, задача следующей недели. Яндекс и Т-Банк — примеры желаемых площадок без договорённостей.

Компания может начать сразу внутри. Перед передачей своих данных проверяются P10/P12/P23, затем выбранные J12–J18. После двух-трёх повторяемых рабочих циклов фиксируется решение о расширении, ограничениях и поддержке. Число аккаунтов и восторг от демо не заменяют полезное использование.

## После запуска

Публиковать небольшие проверенные изменения, разбирать препятствия первых пользователей, давать воспроизводимые задачи контрибьюторам. При расширении — рецепты и разрешённые интеграции, затем подборки и полезные сигналы. Возможные услуги: внедрение, адаптер, дизайн-рецепт и сопровождение. Базовое самостоятельное использование и корпоративное размещение остаются открытыми; коммерческая модель не требует скрыть основные права или экспорт.
