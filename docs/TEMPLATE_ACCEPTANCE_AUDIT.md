## Следующий один результат

Без MCP передать реальному агенту экспортированный приватный пакет оформления и отдельный пакет фактов; задача и период уже заданы. Проверить прочитанные исходники, точные версии, замену демонстрационных данных, отсутствие повторного вопроса и визуально просмотреть результат. Затем отдельное явное поручение сохранить новый результат через capture; не revise исходного шаблона. Это закроет пункты 4, 6–8 одним ограниченным сценарием, без нового исследования продукта.

После этого: безопасное локальное обновление (backup/preflight/проверка запуска), если входит в текущую поставку, и финальная приёмка. Реальные интервью не проведены; симуляции и модельные тесты ими не называем. Внешний релиз не объявляем. Рабочую БД в этом аудите не меняли.

## Инцидент запуска теста и исправление

Luna сначала запустила `npx tsx --env-file=.env --test tests/single-file-agent-context.test.ts` напрямую, минуя изолированный runner. В рабочей schema21 остались три синтетических аккаунта и две ревизии до отказа на отсутствующей template_libraries. Root сопоставил точные ID, тестовые имена и SHA256 с fixture, удалил только эти записи и две точные версии S3-объектов транзакционной процедурой. Схема не менялась. Нельзя утверждать, что рабочая БД в этом этапе совсем не затрагивалась.

В начало теста добавлен assert имени disposable БД до создания аккаунтов. Правильная команда: `node --env-file=.env --import tsx scripts/test-isolated.ts tests/single-file-agent-context.test.ts`.

### Файловая приёмка завершена

`offline-agent-result.json`, `offline-agent-report.html`, `offline-agent-report.png`: реальный агент без MCP использовал два экспортированных пакета; desktop просмотр без обрезаний. Отдельное сохранение через capture остаётся следующим одним результатом. При первом запуске fixture экспорт удался, но регистрация frontend после app.inject вызвала Fastify boot error; порядок исправлен. Временная БД была удалена wrapper-ом; два оставшихся S3-объекта удалены отдельно после проверки точного tenant prefix и SHA256 fixture. Повторный запуск завершён штатно с очисткой. Рабочая БД этим проходом не изменена.

### Явное сохранение завершено

`explicit-capture-result.json`: результат файлового сценария сохранён в личную Полку читателя отдельным HTTP MCP capture, source:read/capture/context без revise/share. После сохранения прочитаны реальные bytes, исходный библиотечный контекст и bytes совпадают до/после, повтор capture не создал дубликат. Check/build прошли. Временная БД и токен удалены.

## Завершение локального объёма цели

Исходные функциональные критерии SPEC §7 и корпоративные роли/отзыв подтверждены указанными доказательствами. Локальная установка обновлена до schema26; резервная копия с ограниченными правами находится вне репозитория, путь и SHA256 в local-upgrade-result.json. Восстановление проверено на отдельной БД до обновления. Количество аккаунтов, материалов и ревизий сохранено. HTTP healthz/readyz успешны; анонимная /templates отрисована. Авторизованные сценарии проверены ранее на идентичной schema26 в disposable установке, вход от имени настоящего пользователя не выполнялся.

Ограничения поставки: приглашения отправляются вручную; корпоративная библиотека не владеет независимой копией файлов; скачанное не отзывается; PDF не поддержан; журнал с >50 строками визуально не проверен (API pagination покрыта); реальные пользовательские интервью и внешний/cloud релиз не выполнялись. Эти ограничения раскрыты, а не представлены как выполненные возможности. Полный enterprise-продукт и автоматический запуск при перезагрузке компьютера не входят в эту цель.

Приложение запущено локально, лог /tmp/polka-local-server.log. Завершённые модельные/браузерные прогоны повторять без нового изменения не нужно.
