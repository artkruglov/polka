# Редизайн Полки: Codex и Claude Code Opus 5

13 сентября 2026. Пользователь попросил независимое ревью и улучшение интерфейса, затем план перехода к масштабируемому open-source продукту. Проведены два настоящих запуска Claude Code с `--model claude-opus-5`, доступом только на чтение. Основная модель подтверждена результатами CLI. Это не симуляция пользовательских интервью.

## Что посмотрели

В первом раунде Opus сообщил о просмотре четырёх PNG и прочитал макет/документы; во втором — семи новых PNG и кода новой модели/UI. Codex отдельно проходил сценарии в браузере, делал скриншоты и вносил изменения. [Первое ревью](../../reviews/2026-09-13-design-opus/round-1-result.md), [второе ревью](../../reviews/2026-09-13-design-opus/round-2-result.md), [запись запусков](../../reviews/2026-09-13-design-opus/evidence.json).

Второй раунд оценил визуальное направление заметно выше, особенно положение работ на полке, просмотр без sidebar, последовательность действий в share и разные типы содержимого. Это экспертная оценка двух агентов, не доказательство востребованности продукта.

## Что изменилось

| Проблема | Изменение | Задача пользователя |
|---|---|---|
| Полка состояла из одинаковых зелёных плашек; работы далеко внизу | Нейтральная оболочка, компактные папки, сетка работ с различимым содержанием, единые токены | J04 — быстро найти работу |
| Переключатель вида был надписью, недавние не фильтровались, квота выдумана | Реальные список/сортировка/фильтры/избранное/недавние; убрана псевдоквота | J04 |
| Все типы работ открывали почти одинаковый отчёт | Отдельные доверенные примеры: отчёт, интерактивный сервис, три слайда, страница и заметки | J01/J05 — увидеть свой результат |
| Просмотр был зажат навигацией, новая версия спрятана снизу | Компактная верхняя панель, новая версия сверху, фокус с видимым выходом, статус отправленной версии | J05/J06 |
| Можно скопировать ссылку до сохранения доступа | Копирование появляется после явного включения; расширение доступа не применяется черновиком формы | J01/J05, S02 |
| Сохранение настроек оживляло отозванную ссылку | Отдельные операции настроек/отзыва/повторного включения; повторное включение меняет адрес | S07 |
| Отмена могла сохранить приглашённого | Отдельный draft формы; отмена и Escape не меняют список | S10, будущий сценарий |
| Сужение доступа имело разное поведение и неправильную подпись | Понятное подтверждение; после выбора владельца — «Только я», а не статус прежней ссылки | S09 |
| Перерисовки теряли фокус, переключение загрузки теряло ввод | Возврат фокуса, стрелки клавиатуры, сохранение названия/папки/HTML при смене вкладки | F18/S09 |
| CAS использовал значение, прочитанное в момент клика | Ожидаемая опубликованная версия берётся из показанного состояния | F09/S06 |
| Не было удобной мобильной навигации | Меню разделов, нижняя панель share, увеличенные touch-контролы | J05/S09 |

После второго ревью Codex исправил найденные ошибки форм и фокуса, разделил подписи доступа и отзыва, добавил обновление версии в share, убрал дублирующую кнопку копирования и перекрытие подписи обложки на телефоне. Desktop-пример слайдов получил пропорцию 16:9; на телефоне он адаптируется для чтения. Новые изменения проверены Codex; отдельного третьего ревью Opus не было.

## Что приняли не буквально

- Папки оставлены компактными chips как быстрый ориентир. Их дублирование с sidebar и плотность мобильных карточек ещё стоит проверить с пользователем.
- Версии пока отдельная простая поверхность. Drawer и полное слияние панелей не являются обязательными до проверки сценариев.
- Закреплённая версия осталась в дополнительных настройках. Нужна отдельная задача в пользовательском тесте, иначе настройку следует убрать из первого выпуска.
- Обложки макета — оформление наших вымышленных примеров. Реальному сервису нужны снимки настоящего содержимого и честные placeholder. Проверка разнообразного плотного HTML ещё открыта.
- React выбран для продуктового UI, но весь макет не переносится до первого реального сценария. `model.mjs` — демонстрация, не реализация ACL.
- Не делаем конкретное S3-хранилище или wildcard DNS обязательными для любого self-hosted профиля. Отдельный origin исполнения обязателен; нужные DNS/TLS и provider выбираются и проверяются для конкретного viewer. Файловый режим и networkless runtime имеют разные условия поставки.

## Архитектура и следующий срез

[PROTOTYPE_TO_PRODUCT](PROTOTYPE_TO_PRODUCT.md) описывает компоненты, договор клиента, состояния ошибок, границу demo/HTTP, структуру репозитория и приёмку hosted/self-hosted. Общая реализация UI/API, PostgreSQL для метаданных, закрытое объектное хранилище, отдельные workers и принятый runtime. Обычная выдача файлов не запускает тяжёлое исполнение на каждого читателя.

Следующий результат: один реальный путь вход → файл → просмотр → доступ → другой получатель → новая версия по той же ссылке → отзыв. Затем проверенная установка, обновление и восстановление. Точные этапы остаются в [DELIVERY_PLAN](DELIVERY_PLAN.md), без новой параллельной очереди.

## Доказательства и ограничения

[Браузерные наблюдения и снимки](../../design/review-v2/checks.json). Семь тестов модели проверяют default-private, отсутствие адреса до активации, save/publish, stale CAS, revoke/options/rotation, private/pinned и фильтры. Проверка модели не заменяет реальные тесты с двумя аккаунтами и хранилищем.

В первых desktop-снимках было несоответствие масштаба/viewport. Новые основные снимки сделаны при измеренных 1280×900/DPR=1; мобильные размеры записаны отдельно. Скриншоты второго раунда сохранены в `reviews/2026-09-13-design-opus/round-2-images/`. Во время ревью читался рабочий код, а не неизменяемый commit; результат не следует выдавать за аудит финального commit.

Настоящих файлов, приглашений, серверной авторизации, проверки производительности, корпоративного пилота или публичного релиза в этом проходе не было. UI-макет по-прежнему явно помечен как демонстрационный.
