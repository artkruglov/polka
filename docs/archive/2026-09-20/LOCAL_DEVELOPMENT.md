# Запустить рабочую Полку локально

Первый рабочий срез, **не публичный релиз**. Нужны Node.js ≥22.16, npm и работающий Docker Compose. Команды выполняются из корня нового репозитория `polka`; Lanka не требуется.

```bash
npm ci
npm run local:setup
npm run infra:up
npm run db:migrate
npm run account:create -- artem --generate
npm run build
npm run dev
```

Открыть **http://127.0.0.1:4390/**. Публичная витрина демонстрационных работ доступна без входа по адресу **http://127.0.0.1:4390/discover**. Логин и случайный пароль находятся в `.local/artem-account.txt`. Не публикуйте этот файл. Уже созданный аккаунт не нужно создавать повторно. Чтобы остановить приложение, завершите его процесс; `npm run infra:stop` останавливает только контейнеры Полки, сохраняя их тома.

`local:setup` создаёт уникальные секреты и сохраняет существующий `.env`. Локальная конфигурация и данные не коммитятся. Для этой сборки аккаунт создаёт оператор, а не произвольный посетитель; это настоящая проверка пароля и сессия сервера, **не подтверждение email и не корпоративный SSO**. Другой оператор может создать второй аккаунт тем же способом.

## Что попробовать

Сначала откройте `/discover`: переключите категорию, откройте карточку и нажмите «Открыть демо». Это локальный редакционный UI-срез с безопасными демонстрационными данными; он не читает private tenant и не выдаёт пользовательские публикации. «Сохранить после входа» ведёт в личную полку. Настоящая загрузка своей работы в очередь модерации — следующий M1.1.

1. Создать папку и добавить PNG/JPEG/WebP или TXT в UTF-8 до 5 МиБ. Можно вставить обычный текст. Перезагрузить вкладку — материал останется.
2. Открыть работу, включить доступ по ссылке на 1/7/30 дней. До включения адреса для отправки нет. Проверить в другом браузере без входа.
3. Добавить новую версию. По прежней ссылке остаётся предыдущая; «Обновить ссылку до v2» явно переключает новые просмотры.
4. Открыть историю, выбрать старую версию. Это не меняет текущую работу или отправленную ссылку.
5. Закрыть доступ. Повторное открытие недоступно. Новое включение создаёт другой адрес. Уже скачанные/показанные байты отозвать нельзя.

**Адрес 127.0.0.1 доступен только на этом компьютере.** Ссылка рабочая локально; для отправки другому человеку через интернет нужны домен, HTTPS и эксплуатационный допуск. Их эта команда не создаёт.

## Поддержанный объём

- React UI; HTTP API; PostgreSQL; private S3-compatible storage с versioning. В локальном стенде используется закреплённый MinIO image как compatibility fixture. Он не объявлен поддерживаемой production-поставкой.
- Отдельная личная полка каждого аккаунта. Пока один personal tenant на пользователя; organization/workspaces/membership модель остаётся следующим этапом.
- Создание плоских папок (до 100), фильтр по папке, поиск названия, карточки/список, страницы по 24 работы. Иерархия, move/rename/trash/restore ещё не реализованы. История показывает последние 100 версий.
- Один файл до 5 МиБ, квота 100 МиБ на аккаунт с учётом всех версий, до 8 незавершённых загрузок. Одновременно передаются до 4 файлов на процесс. До нескольких API replicas нужен распределённый admission, не копирование этого локального счётчика.
- Begin → binary upload → finalize → receipt; повтор не создаёт новую работу. Нет передачи файла через base64 в JSON. Gateway буферизует ограниченный файл в памяти; presigned direct upload/multipart/resume/Range/CDN пока отсутствуют.
- Изображение отдаётся как изображение, текст экранируется React. HTML/CSS/JS, ZIP, PDF, SVG и PPTX в этом профиле отклоняются заранее и сервером. **HTML не заменён текстовым форматом в продуктовой цели.** Для него нужен следующий принятый viewer.
- Секрет ссылки в URL fragment; сервер получает его в теле resolver-запроса. Grant ограничен одной версией и 60 секундами; доставка повторно проверяет отзыв и expiry. Все ответы no-store/noindex/nosniff/no-referrer. Это проверенные границы локального сценария, а не гарантия конфиденциальности ссылки «для всех, у кого она есть».
- Нет сторонних шрифтов, аналитики или генеративного провайдера. После установки зависимостей обычная работа не требует агента. Выполнения HTML тоже нет.

## Проверка и обслуживание

```bash
npm run check
npm test
npm run build
npm run maintenance
```

Интеграционные тесты работают с настоящими PostgreSQL и S3 этой **локальной тестовой установки**, создают отдельные synthetic accounts/fixtures и оставляют их для диагностики. Не запускать против ценных данных. 15 проверок: изоляция двух аккаунтов, приватные байты/receipt, реальный S3, checksum/type, повтор/обрыв/гонки, stale version, quota, live pointer, grant pinning, expiry, отзыв/rotation, CSRF-origin/logout, пагинация, reconciliation. Это не нагрузочный тест и не полный аудит.

`maintenance` обрабатывает до 100 завершённых по времени/отменённых загрузок за запуск, удаляет их недоступные версии S3, хранит tombstones для idempotency и очищает истёкшие сессии/grants. Приёмочные receipts и их объекты не удаляются. Периодический запуск и retention audit/outbox ещё нужно оформить в эксплуатационной поставке. Миграции применяются отдельной командой, транзакционно и под advisory lock.

Данные живут в Docker volumes `polka-local_metadata` и `polka-local_objects`. Не удаляйте volumes. `.env`/`LINK_KEY` также нужны для сохранения работоспособности установки. **Перезапуск проверен; backup/restore, обновление с rollback и восстановление отозванных прав ещё не приняты.**

Для изменений UI повторить `npm run build` и перезагрузить браузер; для изменений сервера перезапустить `npm run dev`. Эта команда обслуживает собранный frontend, HMR здесь нет.

Локальные зависимости: PostgreSQL 16, MinIO fixture 2025-04-22 (оба digest закреплены в Compose). Лицензия Полки Apache-2.0 не меняет лицензий внешних сервисов (PostgreSQL License / MinIO AGPLv3). Runtime vendor/образы для внешнего релиза нужно выбрать и проверить отдельно; MinIO не встраивается в библиотеку Полки.
