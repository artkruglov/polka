# Команды и корпоративный пилот Полки

Редакция 14 сентября 2026 ([Opus review «community frame»](../../reviews/2026-09-14-opus-community-frame/review.md)). Полка не должна продаваться команде или компании как ещё один диск. Для личного автора ценность — цикл «агент → работа → витрина → ремикс». Для команды и компании — **«разрешённый агент → сохранённый артефакт → общая библиотека лучших работ → безопасный обмен и ревью»**, без случайного выхода работ наружу.

> **Уточнено 2026-09-14.** Прежний документ описывал один корпоративный пилот M4. Теперь две ступени: **Team в Light (M1.3)** — hosted, 20–40 человек, простой вход; **Enterprise (M4)** — self-hosted с SSO, внутренними агентами, egress, аудитом и offboarding. Прежние jobs, обязательный срез и сценарий приёмки ниже сохранены и относятся к Enterprise. Подтверждённых команд и компаний-кандидатов нет.

## Две ступени

| | Team в Light (M1.3) | Enterprise (M4) |
|---|---|---|
| Поставка | Hosted Light, серверы в России | Self-hosted в контуре компании |
| Размер | Ориентир 20–40 участников, лимит виден до приглашения | По профилю установки |
| Вход | Простой вход, приглашение по email | OIDC/SSO, server-side membership |
| Роли | owner, member | member, reviewer, admin, security admin, auditor |
| Пространство | Библиотека команды (team tenant) | Библиотека компании (organization tenant), workspaces |
| Доступ | «Только я», «В команде»; «По ссылке» — если владелец включил | «Только я», «В компании», приглашённые; внешнее — по политике |
| Агенты | Агент по поручению ([матрица](AGENT_CAPTURE_AND_IMPORT.md#capabilities-агента-self-ask-deny)); владелец задаёт потолок в команде: выключены / «Только сохранять» / «Помощник»; «В команде» — с подтверждением участника; работы команды агент в витрину не подаёт | Внутренние adapters по разрешению admin; тот же контракт `self/ask/deny` + потолки по classification, подтверждение reviewer, kill switch; дополнительно `comments.read`, `proposal.submit` для review |
| Публичная витрина | Нет пути для работ команды (F36) | Не подключена по умолчанию |
| Offboarding | Исключение участника: доступ и подключения к команде отозваны, работы остаются команде | Полный: сессии, токены, runs, продолжатель, аудит |
| Аудит | Журнал значимых действий для владельца (минимум) | Audit UI/export, отдельно от аналитики |
| Egress / классификация | Не заявляется | Egress profile, классификация, запрет внешних моделей |
| Review | M3 по сигналу E8 | Входит в пилот |
| Перенос | Экспорт пакета (F40) | Импорт пакета из Light |

Team в Light — ступень для команд, которым достаточно hosted-сервиса. Он **не** называется корпоративно готовым и не предлагается компаниям, которым нельзя хранить данные во внешнем сервисе: для них сразу Enterprise или отказ до его готовности. Утверждения о соответствии законодательству о персональных данных не делаются без юридической проверки.

## Jobs команды в Light

| Job | Роль | Что нужно доказать (E8) |
|---|---|---|
| Собрать лучшие работы команды в одном месте | Владелец команды, участники | Участники открывают работы коллег каждую неделю; библиотека не превращается в свалку файлов |
| Сохранить результат агента сразу в команду | Участник + агент | Capture в пространство команды, receipt, работа принадлежит команде |
| Не выпустить работы команды наружу случайно | Владелец команды | Ни одного пути в витрину; «По ссылке» и копирование в личное — только по решению владельца |
| Не потерять работы ушедшего | Владелец команды | Исключение участника не удаляет работы |
| Взять за основу работу коллеги | Участник | Ремикс внутри команды с Origin |
| Перейти во внутренний контур, когда вырастем | Владелец команды + IT | Экспорт пакета проверяется dry run |

## Большие jobs Enterprise

| Job | Что хочет человек или компания | Что нужно доказать |
|---|---|---|
| Сохранить результат агента | Сотрудник говорит агенту «положи это на Полку» и получает private receipt | MCP/connector сохраняет точные байты, provenance и новую версию; агент не публикует |
| Поделиться внутри | Автор отправляет коллеге ссылку, коллега открывает её под корпоративной учётной записью | Workspace, identity, ACL и отзыв доступа работают на каждом маршруте |
| Довести до решения | Reviewer оставляет замечание к версии, автор или агент выпускает следующую версию | Комментарий привязан к revision/якорю; diff виден; старый выпуск не меняется |
| Не потерять работу | Сотрудник ушёл или агент отключён, материалы должны остаться компании | Owning tenant, offboarding, продолжатель, backup/restore и аудит доказаны |
| Не выпустить секрет | Security admin запрещает внешний egress, внешние модели и публичные ссылки для закрытых материалов | Policy enforcement на сервере; UI и MCP не обходят ограничение |
| Развернуть без внешнего сервиса | IT ставит Polka в своём контуре и подключает разрешённый storage/IdP/agent | Воспроизводимый профиль установки, конфигурация S3/MinIO, OIDC, egress и health checks |
| Найти полезное | Команда возвращается к прошлым отчётам и шаблонам | Поиск и метаданные соблюдают ACL; каталог не раскрывает private работы |
| Перенести работы из Light | Команда выросла из hosted | Импорт пакета с отчётом о непереносимом ([J39](PRODUCT_AND_STORIES.md#j39-миграция-light--enterprise)) |

## Что обязательно для Enterprise-пилота (M4)

1. **Организация и рабочая область.** Organization tenant для пилота. У работы есть owning tenant и автор; папка не является границей безопасности сама по себе.
2. **Корпоративный вход.** OIDC/SSO на выбранном провайдере, server-side membership и базовые роли `member`, `reviewer`, `admin`. Локальный пароль остаётся для development.
3. **Внутренняя ссылка.** По умолчанию private; режим «В компании» открывает только членам workspace. Invite и unlisted — отдельные проверяемые режимы, не замена membership.
4. **Разрешённый agent capture.** Один реальный внутренний MCP adapter, scoped token, receipt, provenance; `share` — только через подтверждение principal или reviewer по политике, `publish/approve` — `deny` для агента. Агент может создать candidate и запросить доступ, человек — подтвердить доступ и выпустить.
5. **Версии и простой review.** Комментарий к revision/page/anchor, статус open/resolved, ответ автора, новая версия и явное переключение ссылки. Совместное редактирование в реальном времени не нужно.
6. **Безопасность и эксплуатация.** Egress profile, классификация, запрет внешних моделей по policy, audit событий capture/share/revoke/review, backup/restore и offboarding.
7. **Установка.** Docker Compose для малого пилота, внешний S3 или MinIO, Postgres, OIDC и отдельный домен для доставляемых артефактов. Hosted и self-hosted используют один application contract.
8. **Импорт из Light.** Подписанный пакет, сопоставление участников с SSO, продолжатель для несопоставленных, отчёт о непереносимом.

## Что не добавлять ни в Team, ни в Enterprise-пилот

- универсальный редактор уровня Figma;
- зеркалирование внешнего чата или собственный чат-агент;
- все модели и все MCP-провайдеры сразу;
- публичную витрину, реакции и рекомендации для закрытого контура;
- публикацию работ команды в публичную витрину (Light);
- наследование сложных прав на сотнях уровней папок;
- DLP, legal hold и SCIM как видимость функции без реальной интеграции;
- Brand Library и Publisher workflow ([отложены](DELIVERY_PLAN.md#отложенные-решения)).

## Сквозной сценарий приёмки Team (M1.3)

1. Владелец создаёт команду в Light, видит лимит участников и приглашает коллег по email.
2. Участник подключает агента к пространству команды; экран согласия показывает «может / не может».
3. Агент сохраняет HTML-артефакт; работа появляется во «Входящих» участника в пространстве команды, затем добавляется в Библиотеку команды.
4. Коллега находит работу в библиотеке, сохраняет её и берёт за основу внутри команды.
5. Попытка подать работу команды или её копию в витрину недоступна в UI и отклоняется API/MCP.
6. Владелец исключает участника: доступ и подключения к команде отозваны, работы остались.
7. Владелец выгружает экспорт; пакет проходит проверку целостности (dry run импорта — на тестовой Enterprise-установке).

## Сквозной сценарий приёмки Enterprise (M4)

1. Оператор разворачивает Polka внутри тестового контура, подключает Postgres, S3/MinIO и OIDC.
2. Сотрудник входит через корпоративную учётную запись и открывает workspace.
3. Разрешённый агент по MCP сохраняет HTML/ZIP-артефакт в папку «Входящие от агента»; в чате появляется receipt, а в Полке — private revision.
4. Сотрудник отправляет внутреннюю ссылку reviewer. Reviewer открывает версию, оставляет замечание, но не видит закрытый prompt trace и источники без права.
5. Агент или автор создаёт candidate v2. Reviewer видит diff и принимает его вручную; ссылка переключается только явным действием.
6. Администратор отключает сотрудника. Новые сессии, grants и agent runs прекращаются, а работа остаётся у owning tenant и доступна продолжателю.
7. Аудит показывает actor, agent delegation, operation, revision, share/review и результат без секретов.
8. Администратор импортирует тестовый пакет из Light и получает отчёт о перенесённом и непереносимом.

Пока этот сценарий не пройден на одном реальном внутреннем агенте и на реальных правилах egress, нельзя называть продукт корпоративно готовым. Личный Light и публичная витрина остаются более короткими входами для первых пользователей.
