## Что уточнено по корпоративному ревью

В первоначальных PRD были tenant hierarchy, Publisher, agent actor/scopes, brand certification, egress/classification, audit, snapshot provenance и immutable release. При упрощении плана они оказались распределены по общим пунктам. F02/F03/F10–F16 возвращают их в явный контракт. Offboarding с сохранением собственности компании — новое практическое уточнение исходной модели, а не найденная дословная US.

Основу F02/F03/F04/F10/F11/F12 нужно закладывать до персонального публичного выпуска. При этом интерфейс не заставляет одиночного автора создавать компанию, получать три согласования или выбирать агента. Один и тот же пользователь может быть автором и публикующим в личном tenant; организация может потребовать разделения обязанностей.

## Разделение распространения и утверждения

Подробный контракт аудитории, индексации, обновления ссылки и проверок S01–S12 — [SHARING_AND_DISCOVERY](SHARING_AND_DISCOVERY.md). Только явно public работа может попасть в каталог и получить разрешение индексирования; «По ссылке» не называется приватным режимом.

«Поделиться» создаёт доступ в пределах policy. «Утвердить/выпустить» — отдельный корпоративный workflow. Ссылка на draft не выдаётся за официальный утверждённый выпуск. Изменение текста, данных, asset или design dependency создаёт новую revision и требует нового approval для неё; старый release остаётся своим неизменяемым снимком.

## Границы обещаний

Фразы «любой агент», «все данные в контуре», «мгновенный отзыв», «полная синхронизация» и «редактор как Figma» допускаются только в доказанном конкретном смысле. Система не является desktop sync client первого выпуска. Статичный preview явно отличается от интерактивного; медленный runtime нельзя скрывать под вечным спиннером.

| Организовать личное и подготовить | self | `library.organize`, `bookmark`, `remix.create`, `publication.prepare` |
| Снизить доступ | self | `access.reduce` (свои ссылки и неотнимающие сужения) |
| Расширить аудиторию | ask (+ Delegation, где разрешено) | `share.link`, `share.retarget`, `share.invite`, `share.team`/`share.company`, `publication.submit`, `share.discovery` |
| Чужое для агента или необратимое | ask | `library.read`, `access.reduce_other`, `library.trash` |
| Решения человека | deny всегда | права на материал, модерация и жалобы, реакции, понижение sensitivity, участники, собственные права агента, финальное утверждение корпоративной ревизии, purge/account |

| ID | Контракт и отрицательная проверка | Этап / задача |
|---|---|---|
| F43 | **Режимы capabilities.** У каждой capability потолок `self \| ask \| deny` в поставке; effective mode = min(потолок, политика workspace, preset, ужесточение объекта), затем `ask → self` только по активной Delegation для делегируемой capability. Сервер вычисляет режим на каждом вызове, для UI/API/MCP одинаково. Неизменяемый `deny`-список не поднимается ничем. Отрицательно: агент с «Помощником» не создаёт ShareGrant `link` без receipt/Delegation; вызов `reaction.*`, `membership.*`, `sensitivity.lower`, `delegation.create`, `intent.approve`, `review.approve` отклоняется при любых preset/политике/клиенте; payload с `actor=human` не меняет actor | Модель M0, M1 / P03,P10,P34 |
| F44 | **ActionIntent, dry-run и подтверждение.** Любая мутация агента поддерживает `dryRun` без побочных эффектов и раскрытия объектов вне scope. `ask` создаёт ActionIntent с dry-run и fingerprint; выполнение — только после ApprovalReceipt человека на тот же fingerprint и повторной проверки прав. Изменение revision/параметров/policy → `stale`; intent истекает; одинаковые открытые intents схлопываются, частота новых ограничена. Для `publication.submit` права на материал подтверждает человек на странице подтверждения. Отрицательно: подтверждение старого intent не публикует новую revision; агент не создаёт и не подтверждает receipt; `pending_approval` не выдаётся за успех | M1 (ссылки), M1.1 (публикация) / P34 |
| F45 | **Delegation.** Ограниченное поручение создаёт только человек (со страницы подтверждения или подключения; в Enterprise — политика). Обязательны scope, лимиты и `expiresAt`; Light: только личные не-sensitive работы, срок ≤ 30 дней, срок создаваемой ссылки ≤ 7 дней, ≤ 10 расширений аудитории в день (предлагаемые пороги до E12). В Light делегируются только `share.link`, `share.retarget` и `library.read`; никогда не делегируются `publication.submit`, `share.discovery` и весь `deny`-список; `share.invite`, `share.team`/`share.company` — только политикой Enterprise. Отрицательно: исчерпанная, истёкшая или отозванная Delegation не выполняет действие; Delegation не действует на sensitive/team-origin объект; пауза подключения отзывает все его Delegation | M1.1 Light, M4 политика / P35 |
| F46 | **Audit и журнал агента.** AuditEvent агента: actor `agent_connection`, `on_behalf_of`, connection, capability, effective mode, basis (`preset \| delegation \| approval`), intent, requestId, target/revision, result, policy version; атомарно с результатом (F11). Журнал для доверителя — человеческая проекция: «сам», «по поручению», «с вашим подтверждением», «отклонено»; обратимые `self`-действия отменяются из журнала. Отрицательно: в audit, журнале, событиях и логах нет token, URL ссылки, содержимого и prompts; отказ не раскрывает объекты вне scope | M0 envelope, M1 журнал, M4 export / P11,P34 |
| F47 | **Отзыв и emergency stop.** Уровни: отозвать ссылку → отменить Delegation → отозвать AgentHandoff → пауза/отключение подключения → «Остановить всех агентов» одним действием: подключения `paused`, открытые intents `cancelled`, Delegation и AgentHandoff `revoked`, незавершённые мутации отклоняются при commit; опция по умолчанию закрывает ссылки и приглашения, открытые по поручению; ссылки по разовому подтверждению и опубликованные снимки перечислены отдельно. Возобновление — вручную, поручения не восстанавливаются. Оператор Light и `security_admin` Enterprise имеют свои выключатели. Отрицательно: после stop ни один вызов агента не выполняется (измерить задержку); восстановление backup не возвращает отозванные Delegation | M1 / P34, P07, P12 |
| F48 | **Ужесточение и presets.** Sensitive: расширение аудитории только `ask` без делегирования с предупреждением J38, index opt-in `deny`, названия скрыты от `library.organize`. Team-origin: публикация `deny` (F36), «По ссылке» и копия в личное — по настройке владельца, без делегирования. Enterprise classification: потолки администратора, маршрут подтверждения reviewer, разделение обязанностей, повторный вход. Light — три presets («Только сохранять», «Помощник», «Помощник с поручениями») без поштучных галочек; владелец команды задаёт потолок для команды; Enterprise — политики workspace/admin/reviewer поверх того же контракта. Отрицательно: ужесточение не повышает режим; повышение preset требует повторного согласия человека; понижение — сразу | M1 presets 1–2, M1.1 preset 3, M1.3 команда, M4 / P30,P31,P34,P35 |
| F49 | **Секрет ссылки не уходит к агенту.** Token/полный URL ShareGrant не возвращаются агенту ни в receipt, ни в `share.inspect`, ни в ActionIntent, ни в событиях; агент получает grant ID, аудиторию, срок и адрес работы для владельца. Токен подключения и код связывания не вводятся в чат. Отрицательно: поиск token в ответах MCP, логах клиента-заглушки, audit и журнале по тестовым ссылкам даёт ноль совпадений | M1 / P07,P25,P34 |

| F50 | **Сохранение из всех входов.** Ссылка, HTML/ZIP и `artifact.capture` создают одну сущность — личную копию (owner-only Artifact с provenance/Origin); интерфейс называет результат «Сохранённый артефакт», а основное действие — «Сохранить на Полку». «Взять за основу» создаёт такую же копию только для разрешённого публичного снимка и остаётся вторичным действием. Отрицательно: сохранение не создаёт внешнюю аудиторию автоматически | M1 / P18,P25 |

Для копии внешней работы публикация требует подтверждения прав и поля «Основано на» с источником. Отрицательно: строка не показывает «включено»/«на проверке» без соответствующего объекта; копия чужой работы без подтверждения прав не отправляется на проверку | M1 (копия, ссылка), M1.1 (витрина) / P07,P18,P28 |
