# Требования MVP и продолжения

Актуальные R-ID заменяют смешанный backlog F/P/M. Старые PRD остаются в архиве; ниже — критерии, а не обещание текущей реализации. Состояние: [STATUS](STATUS.md).

| ID | Требование | Критерий приёмки | Этап |
|---|---|---|---|
| R01 | Самостоятельный вход | Новый email → одноразовый код → личный tenant; expiry/replay/rate limits; возврат к начатому действию | B1 |
| R02 | Первое сохранение | URL/файл/MCP не требуют профиля компании и папки; ошибка оставляет понятный retry и входные данные | B1–B3 |
| R03 | Надёжная копия | Hash + idempotency + manifest; повтор/обрыв не создаёт дубли; данные переживают restart | B2 |
| R04 | MCP | Два реальных клиента проходят connect → capture → receipt → открыть; revoke блокирует следующий вызов | B3 |
| R05 | Авторизованный обмен агентом | Scope ограничивает tenant/действия/TTL; разрешённый share возвращает URL агенту; нет scope — приватное сохранение | B3 |
| R06 | Живой HTML | Принятый корпус отчёта, калькулятора, графика, слайдов и planner работает; тесты изоляции проходят; unsupported явно указан | B2 |
| R07 | Ссылка из исходного сервиса | Минимум один adapter проходит корпус разрешённых публичных ссылок; сохраняет зависимости; получатель не обращается к исходному провайдеру | B2/B3 |
| R08 | Версии и доступ | Private по умолчанию; unlisted pin vN; новая версия не переключает ссылку без команды; revoke/expiry закрывают новые запросы | B2–B4 |
| R09 | Найти и организовать | Личный поиск/пагинация/минимальные папки; rename/move/trash минимум без потери версий и с tenant-check | B4 |
| R10 | Полезная витрина | 12–20 законченных примеров, авторство/происхождение/демометка, открытие с телефона, темы и похожие | B4 |
| R11 | Публичное сообщество | Submission → moderation конкретной версии → publication; removal; аккаунтные likes/bookmarks; счётчики без демонакрутки | C1 |
| R12 | Облачная эксплуатация | HTTPS, закрытая DB/S3, readiness, deployment/rollback, DB+blob restore, бюджетные лимиты, обработка жалоб | B4–B5 |
| R13 | Self-hosted | Из чистого checkout установка с конфигом; те же storage/auth adapters, миграции, экспорт и restore; без обязательной внешней модели | B5 base / C3 enterprise |
| R14 | Командные права | Membership/ownership/offboarding, запрет чужого workspace, приглашения по личности | C2 |
| R15 | Review с агентом | Комментарий привязан к revision; кандидат/конфликт/принятие видны, устаревшая версия не перетирается | C3 |
| R16 | Источники и корпоративный контроль | Источники и licenses в manifest, audit actor/on_behalf_of; enterprise SSO/classification/egress по политике | B2 минимум / C3 |

| R17 | Забрать данные и уйти | Автор скачивает исходный файл/bundle выбранной версии с manifest; private export проверяет tenant; удаление аккаунта сообщает сроки очистки blobs/backups и отменяет доступ | B4 экспорт / B5 lifecycle |
| R18 | Контроль обнаружения | Private/unlisted не попадают в каталог, sitemap и содержательные OG; noindex не заменяет auth. Публичная публикация и индексация — отдельные настройки, снятие закрывает новые просмотры | B4 минимум / C1 публикации |
| R19 | Поделиться конкретному человеку | Приглашение связано с подтверждённой личностью; пересланная ссылка не открывается постороннему; отзыв приглашения не удаляет артефакт | C2; beta предлагает только явно обозначенный unlisted |
| R20 | Быстрое сохранение из мессенджера | Telegram: ссылка/файл → статус → готовая ссылка; привязка аккаунта одноразовая, повтор update идемпотентен; токен бота не получает артефакт прав вне пользователя | После B5, до enterprise; тот же capture service |

Общие NFR: keyboard/focus и 390/768/1440 px; HTML не получает секреты приложения; приватные bytes не доступны через public bucket/CDN; quotas/rate limits не только в UI; нет тяжёлого серверного браузера на каждый просмотр. Targets и capacity — [LAUNCH](LAUNCH.md).

Сохранены из Lanka: immutable releases, provenance, версии, права, recovery, свои агенты, корпоративная изоляция. Изменены: универсальный HTML/bundle вместо DeckDoc, внешние агенты вместо встроенного chat runner. Отложены: PPTX-конверсия, co-editing и корпоративная сертификация шаблонов. Таблица исторических требований: [REQUIREMENTS_TRACE.csv](REQUIREMENTS_TRACE.csv).
