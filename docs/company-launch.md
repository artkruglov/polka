# Полка в компании: запуск за один день

Гайд для того, кто запускает Полку в компании: руководителя, ИТ-администратора, специалиста по ИБ. Здесь по порядку: какой вариант выбрать, что подготовить, как поставить, настроить и подключить людей. Команды для сервера подробно разобраны в [deploy/hosted/README.md](../deploy/hosted/README.md). Здесь — путь целиком и решения, которые нужно принять.

## 1. Выберите вариант

| | Облако polochka.app | Своя установка (открытое ядро) | Коммерческая редакция |
|---|---|---|---|
| Что делать | Ничего не ставить: сотрудники входят на polochka.app | Поставить на свой сервер по этому гайду | Своя установка и расширение по договору |
| Где данные | Yandex Cloud, Россия | На ваших серверах | На ваших серверах |
| Полки отделов, роли, сервисные доступы, вебхуки | Есть, по организации компании | Есть | Есть |
| Вход через IdP компании | Яндекс ID, почта | OpenID Connect (Keycloak, Avanpost, AD FS), Яндекс ID, VK ID, почта | Плюс SAML 2.0 и каталог сотрудников по SCIM 2.0 |
| Центр управления агентами для ИБ | — | — | Есть: секреты, адреса и MCP, опасные команды, расход, выгрузка в SIEM |
| Цена | Бесплатно на время пилота | Бесплатно, AGPL-3.0 | По договору |

**Хотите попробовать за 10 минут** — облако. Напишите на hello@polochka.app название компании, почтовый домен и кто будет администратором: мы заведём организацию, дальше администратор сам создаёт полки отделов и зовёт коллег.

**Данные не должны уходить из компании** — своя установка, дальше по этому гайду.

## 2. Что подготовить

| Что | Зачем | Кто обычно делает |
|---|---|---|
| VM на Linux: от 4 ГБ RAM (спокойнее 6), 2 vCPU, диск от 20 ГБ, публичный IP | Приложение, база, бэкапы и TLS — на одной машине | ИТ |
| Docker с плагином compose | Всё запускается в контейнерах; Node.js и git не нужны | ИТ |
| Два домена с A-записями на IP машины, без прокси CDN | Приложение (`polka.company.ru`) и отдельный сайт для показа HTML (`polka-view.company.net`, **другой** регистрируемый домен). Чужие скрипты из работ выполняются только там, вдали от сессий сотрудников | ИТ, DNS |
| Входящие 80 и 443 из интернета | Бесплатный сертификат Let's Encrypt и доступ людей | Сеть, ИБ |
| S3-хранилище: два приватных бакета с версионированием | Работы и дампы базы. Подходит Yandex Object Storage; нужна условная запись (`If-None-Match`) | ИТ |
| Три ключа S3: приложения, бэкапа (только запись дампов), чтения дампов (хранится вне машины) | Даже взломанное приложение не сотрёт бэкапы | ИТ, ИБ |
| SMTP (желательно) | Коды входа по почте | ИТ |
| IdP компании по OpenID Connect (желательно) | Вход «как везде» и закрытие доступа при увольнении | ИТ, ИБ |
| Адрес для обращений и свои политика и условия | По 152-ФЗ оператор данных на вашей установке — ваша компания | Юрист |

Время: 2–4 часа, если домены и S3 уже есть; около дня вместе с почтой и IdP.

## 3. Поставьте

На VM, под пользователем с `sudo`:

```sh
curl -fsSLo polka-install.sh https://raw.githubusercontent.com/artkruglov/polka/main/deploy/hosted/install.sh
less polka-install.sh   # прочитайте, что он сделает
S3_ACCESS_KEY=… S3_SECRET_KEY=… BACKUP_S3_ACCESS_KEY=… BACKUP_S3_SECRET_KEY=… \
sudo -E sh polka-install.sh --app-host polka.company.ru --viewer-host polka-view.company.net \
  --s3-endpoint https://storage.yandexcloud.net --s3-region ru-central1 \
  --s3-bucket company-polka-objects --backup-bucket company-polka-backups \
  --operator-contact privacy@company.ru \
  --set ACCOUNT_TRUST=company --set OPERATOR_NAME="ООО «Компания»"
```

Установщик проверит Docker и DNS обоих доменов, скачает готовые образы, создаст `/opt/polka/deploy/hosted/hosted.env` (пароли и ключи генерирует сам, на экран их не выводит) и запустит Полку. Чего не хватает, спросит. Почта — `--smtp-host … --smtp-user … --mail-from …` и `SMTP_PASS` в окружении; IdP — `--oidc-discovery-url … --oidc-client-id …` и `OIDC_CLIENT_SECRET`. Все ключи: `sh polka-install.sh --help`.

Сохраните `hosted.env` в менеджере секретов компании. Без `LINK_KEY` из него перестанут открываться все ссылки.

## 4. Первый администратор и проверка

```sh
cd /opt/polka/deploy/hosted
# одноразовая ссылка входа на час, без почты и SSO
docker compose --env-file hosted.env run --rm -T --no-deps app \
  node --import tsx scripts/admin.ts account bootstrap anna@company.ru
# проверка: DNS, TLS, база, бакеты, бэкап, почта, IdP — ✓ или ✗ с подсказкой
docker compose --env-file hosted.env run --rm -T --no-deps app \
  node --import tsx scripts/admin.ts ops doctor
```

Откройте ссылку из первой команды: вы вошли администратором компании. Пока проверка показывает ✗, исправьте по подсказке и запустите её снова.

## 5. Настройте под компанию

Настройки — в `hosted.env`, после правки: `docker compose --env-file hosted.env up -d`.

| Настройка | Рекомендуем | Что даёт |
|---|---|---|
| `ACCOUNT_TRUST` | `company` | Сотрудники сразу «свои»: без недельных ограничений ссылок для новых аккаунтов, как в публичном облаке. Ставьте, только если вход закрыт для посторонних (две строки ниже) |
| `EMAIL_SIGNUP`, `EMAIL_SIGNUP_ALLOW` | `invite`, `@company.ru` | Новую полку по почте получают только адреса компании |
| `OIDC_*`, `OIDC_ALLOWED_DOMAINS` | ваш IdP, `company.ru` | Кнопка «Единый вход компании» и вход только для своих |
| `OPERATOR_NAME`, `OPERATOR_CONTACT`, `PRIVACY_URL`, `TERMS_URL` | ваши | Страницы «Политика» и «Условия» ведут на ваши документы. Без адресов показывается короткая страница: установка принадлежит вашей компании, ниже контакт |
| `TEAM_SHELVES`, `SERVICE_ACCOUNTS`, `WEBHOOKS` | `on` | Полки отделов, доступы для cron и CI, уведомления в ваши системы |
| `AGENT_SESSION_QUOTA_BYTES`, `AGENT_SESSION_NOTICE` | по решению ИБ | Сессии Claude Code и Codex сотрудников и текст, который люди читают до отправки |
| `HTML_LIVE_MODE` | `production` | Интерактивные страницы и React у получателей (на домене просмотра) |

## 6. Подключите людей

1. **Полки отделов.** Администратор компании создаёт полку отдела и добавляет коллег: с подтверждённой почтой — сразу, остальных — ссылкой-приглашением с ролью и сроком.
2. **Агенты.** Каждый сотрудник пишет своему агенту одну фразу:

   > Подключи Полку: https://polka.company.ru/connect

   Агент сам выполнит команду и подключится к **вашему** серверу; сотрудник войдёт и нажмёт «Разрешить». В Claude.ai и ChatGPT коннектор добавляют вручную — шаги на странице `/settings/agents`.
3. **Первая неделя.** Попросите 3–5 человек сохранять на Полку всё, чем делятся с коллегами: отчёты, прототипы, дашборды. Через неделю соберите, что мешало.

## 7. Эксплуатация

- **Бэкапы** — дамп базы в бакет раз в сутки по умолчанию (`BACKUP_INTERVAL_SECONDS=3600` — раз в час). Работы хранятся в бакете с версиями. Восстановление отработайте заранее: [раздел в README](../deploy/hosted/README.md#восстановление-из-дампа). Потеря не больше минуты — профиль `pitr` (архив журнала базы), копия работ, которую не удалить ключом приложения, — профиль `mirror`: [README](../deploy/hosted/README.md#восстановление-на-момент-времени).
- **Обновление** — `sudo -E sh install.sh --release <версия> --force` в `/opt/polka/deploy/hosted`. Перед версией с миграцией базы — дамп. Что изменилось — в [CHANGELOG](../CHANGELOG.md).
- **Уход сотрудника** — на странице «Полки компании»: «Убрать» снимает человека со всех полок отделов и отключает его агентов; работы остаются у отдела. С IdP вход закрывается там же, где у остальных систем.
- **Мониторинг** — `GET /api/ops/status` с `OPS_STATUS_TOKEN` отвечает 503, когда что-то не так: база, обслуживание, возраст бэкапа, диск.
- **Лицензия** — AGPL-3.0: пользоваться без изменений можно бесплатно и без договора. Если меняете код и даёте пользоваться изменённой Полкой — публикуете изменения (`SOURCE_URL`) или берёте коммерческую лицензию ([COMMERCIAL.md](../COMMERCIAL.md)).

## Чего пока нет

- Работы в закрытом контуре без интернета: сертификат выпускается только через Let's Encrypt. Свой сертификат и установка без интернета — в планах.
- Встроенного хранилища: S3 нужен внешний.
- Отказоустойчивой конфигурации: одна VM. Восстановление — из дампа и версий в бакете.
