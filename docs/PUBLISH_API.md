# HTTP API публикации и CLI

22.09.2026, обновлено 27.09.2026. Для агентов и скриптов, которые не говорят на MCP: внутренний агент компании, CI-задача, cron, любой код, который умеет отправить HTTP-запрос. Один запрос сохраняет HTML-страницу на Полку владельца токена и, если токену разрешено, сразу возвращает ссылку. Внутри это тот же `publishFromAgent`, что у инструмента `polka_publish`: одинаковые лимиты, профили HTML, идемпотентность и интерактивная версия там, где она включена.

Машиночитаемое описание — `/openapi.json` (OpenAPI 3.1, собран из zod-схем этих маршрутов), краткая справка для агентов — `/llms.txt` ([подробнее](connect-agents.md#агенту-без-подсказок-llmstxt-openapi-скилл)).

## Токен

Создайте токен на странице **Агенты** (`/settings/agents`) в разделе «Для разработчиков», вариант «Скрипт или HTTP API». Токен показывается один раз.

| Разрешение | Scope | Что даёт API |
|---|---|---|
| Сведения и статус | `context` | всегда; `GET /api/v1/status/:id` для своих публикаций |
| Сохранять новые работы | `capture` | **обязательно** для `POST /api/v1/publish` |
| Управлять ссылками | `share` | ссылка в ответе; без него работа сохраняется приватно, `url: null` |
| Читать список | `read` | статус любой работы полки, а не только своих; `GET /api/v1/works`, `/works/:id`, `/events` |

Агент в Claude Code или Codex может не просить человека о токене: инструмент `polka_project_upload` выдаёт токен загрузки на 30 минут с теми из разрешений `capture`, `revise` и `share`, что есть у его подключения. Им работают этот маршрут и маршруты проектов; `/api/v1/status`, правки, `/api/v1/sign-in-link` и MCP его не принимают. В ответе инструмента есть готовая команда `pageCommand` для этого CLI. Так страница или компонент с диска уходят на Полку без вставки файла в аргумент инструмента.

Токен передаётся только заголовком `Authorization: Bearer …`. Не вставляйте его в чат, аргументы командной строки и логи; держите в секрет-хранилище и переменной окружения `POLKA_TOKEN`. Отзыв подключения на странице «Агенты» действует сразу; уже выданные ссылки он не отзывает.

## `POST /api/v1/publish`

```
POST https://polochka.app/api/v1/publish
Authorization: Bearer <токен агента>
Content-Type: application/json
```

| Поле | Тип | |
|---|---|---|
| `key` | UUID | Ключ идемпотентности: новый на каждую публикацию, тот же — только для повтора того же запроса |
| `title` | строка 1–160 | Название на полке |
| `html` | строка | Одна самодостаточная HTML-страница, до 5 МБ в UTF-8 |
| `component` | строка | Вместо `html`: исходник React-компонента как есть. Только если на установке включён интерактивный просмотр, иначе `422 unsupported`. Нужно ровно одно из `html` и `component` |
| `componentLanguage` | `jsx` или `tsx` | Необязательно, только вместе с `component`; по умолчанию `jsx` |
| `expiresInDays` | 1, 7 или 30 | Срок ссылки, по умолчанию 30. Новому аккаунту ссылка выдаётся не больше чем на 7 дней: 30 превращается в 7, и об этом говорит `expiresNote` |
| `folderId` | UUID | Необязательно: папка на полке |
| `artifactId`, `baseRevisionId` | UUID | Необязательно, только вместе: новая версия уже сохранённой работы, `baseRevisionId` — её последняя версия (иначе `409`). Нужно разрешение `revise`, без него — `403`. Открытая ссылка работы переходит на новую версию: адрес и обсуждение те же, в ответе `linkMoved: true`. `folderId` с ними не передаётся |

Страница показывается в изолированной песочнице без сети: CSS в `<style>`, картинки и шрифты как `data:` URI, никаких внешних адресов. Если на установке включён интерактивный просмотр, скрипты из inline `<script>` работают в отдельной песочнице на другом домене; иначе получатель видит статическую страницу. Markdown и текст сначала превратите в HTML. CLI оборачивает любой файл не `.html`/`.htm` (если он не начинается с `<`) в `<pre>` как есть, Markdown не размечает; stdin всегда считается HTML.

Ответ `200`:

```json
{
  "artifactId": "…",
  "revisionId": "…",
  "state": "shared",
  "url": "https://polochka.app/s#…",
  "expiresAt": "2026-09-29T12:00:00.000Z",
  "shelfUrl": "https://polochka.app/works/…",
  "interactiveReady": false,
  "scriptsRunForRecipients": false
}
```

- `state: "saved"` и `url: null` — работа сохранена приватно; причина в `linkUnavailableReason` (нет разрешения `share`, страницу нельзя показать без скриптов, ссылка из этого ключа уже отозвана, у нового аккаунта уже открыто предельное число ссылок или исчерпан дневной лимит новых ссылок).
- `claimUrl` — работа сохранена на временной полке (подключение «Начать без регистрации»): ссылок она не выдаёт, пока владелец не закрепит полку по этому адресу (Яндекс ID, VK ID или почта). Передайте адрес человеку.
- `moderation: "held"` (или `"paused"`) и `moderationMessage` — ссылка выпущена, но ждёт проверки модератора Полки: до одобрения получатель видит экран «Ссылка на проверке», без названия и содержимого. Так бывает с первыми ссылками нового аккаунта (если оператор включил такой режим), со страницами, похожими на фишинг, и с тем, что фильтр запрещённого содержимого отправил на проверку. `moderation: "blocked"` — фильтр ([CONTENT_FILTER](specs/CONTENT_FILTER.md)) заблокировал содержимое: получатель ссылку не откроет, пока модератор не снимет блокировку. Передайте человеку `moderationMessage`, не выдавайте ссылку за готовую. Поле есть только пока ссылка ждёт или заблокирована; у обычной ссылки его нет. Правила — в [specs/ABUSE_PROTECTION.md](specs/ABUSE_PROTECTION.md).
- `expiresNote` — срок ссылки короче запрошенного (новый аккаунт).
- Новый аккаунт (моложе `NEW_ACCOUNT_DAYS`, по умолчанию 7 дней) держит не больше `NEW_ACCOUNT_MAX_LINKS` (5) открытых ссылок и создаёт не больше `NEW_ACCOUNT_DAILY_LINKS` (10) ссылок в сутки, закрытые тоже считаются. Сверх лимита работа сохраняется приватно с `linkUnavailableReason`.
- `linkMoved: true` — новая версия (`artifactId`), и открытая ссылка работы теперь показывает её.
- `interactiveUnavailableReason` — только там, где включён интерактивный просмотр: почему скрипты не будут работать у получателя.
- Повтор с тем же `key` и тем же телом возвращает ту же работу и ту же ссылку, второй ссылки не создаётся. Тот же `key` с другим содержимым — `409`.

### curl

```sh
# Токен вводится без эха и не попадает в историю.
read -r -s POLKA_TOKEN && export POLKA_TOKEN

jq -n --rawfile html report.html \
      --arg title "Отчёт за квартал" \
      --arg key "$(uuidgen)" \
      '{key: $key, title: $title, html: $html, expiresInDays: 7}' |
  curl -sS https://polochka.app/api/v1/publish \
    -H "Authorization: Bearer $POLKA_TOKEN" \
    -H "Content-Type: application/json" \
    --data-binary @-
```

При сетевой ошибке или ответе `429`/`5xx` повторяйте запрос **с тем же `key`**, выдержав паузу из заголовка `Retry-After`, если он есть.

## `GET /api/v1/status/:artifactId`

Метаданные работы без байтов и без секретов ссылок: название, папка, последняя версия, профиль HTML (`static`/`limited`/`unsupported`), состояние интерактивной сборки, корзина, `shelfUrl`. Токен без `read` видит только работы, сохранённые через это же подключение. Некорректный id — `400`.

```sh
curl -sS https://polochka.app/api/v1/status/$ARTIFACT_ID \
  -H "Authorization: Bearer $POLKA_TOKEN"
```

## Чтение полки: `GET /api/v1/works`, `GET /api/v1/works/:artifactId`, `GET /api/v1/events`

Нужно разрешение `read`. Ответы без байтов и без секретов ссылок; токен видит только полку, к которой подключён (и папки, если расширение его ограничило).

- `GET /api/v1/works` — список и поиск, сначала новые. Параметры: `query` (название и текст последней версии; совпадение в названии выше совпадения только в тексте), `since` (ISO 8601 с поясом: только работы, изменённые позже), `limit` (1–100, по умолчанию 25), `cursor` (`nextCursor` прошлого ответа), `folderId`, `state` (`active` или `trashed`), `shelfIds` (через запятую: искать и на полках отделов, которые владелец разрешил токену при выдаче; каждый элемент называет свою `shelfId`; несовместимо с `folderId` и корзиной). Элемент: `id`, `shelfId`, `title`, `kind`, `folderId`, `ownerAccountId`, `acceptedRevisionId`, `revision`, фрагмент `snippet` при поиске.
- `GET /api/v1/works/:artifactId` — то же об одной работе плюс `revisions`: версии от новых к старым (до 100), у каждой `number`, `size`, `createdAt`, `accepted`.
- `GET /api/v1/events?after=<курсор>&limit=` — что случилось с работами, по порядку, для опроса: `revision.saved`, `revision.accepted`, `owner.changed`, `artifact.metadata_updated`, `artifact.moved`, `artifact.trashed`, `artifact.restored`; в событии `id` (он же курсор), `action`, `artifactId`, `revisionId`, `actorType` (`human` или `agent`), `at`. Без `after` ответ пуст, а `nextCursor` — текущий конец ленты, с него и начинайте; `after=0` — с начала истории. Событие появляется, когда завершились его транзакция и все более ранние, так что курсор ничего не пропускает.

```sh
# что изменилось за ночь
curl -sS "https://polochka.app/api/v1/works?since=2026-10-01T00:00:00Z" \
  -H "Authorization: Bearer $POLKA_TOKEN"
```

- `GET /api/v1/works/:id/file?path=&revisionId=` — один файл версии по пути, JSON: текст как UTF-8, остальное base64, до 256 КиБ (право `source:read`; больше — по номеру файла через `…/files/:index` или `polka pull`).
- `POST /api/v1/works/:id/changes` — следующая версия с изменённым набором файлов: `{key, baseRevisionId, put: [{path, encoding, data}], remove: [path]}`; тип файла по расширению, остальные файлы копирует сервер, точку входа удалить нельзя, ссылка не двигается; чужая база — `409` с `currentRevisionId`, повтор с тем же ключом и телом даёт ту же версию (право `revise`). Только для работы-папки (проект, `project-v1`): страницу и пакет сохраняйте через `edits` или публикацию. То же по MCP: `polka_list_files`, `polka_read_file`, `polka_change_files` ([AGENT_WORKSPACE](specs/AGENT_WORKSPACE.md)).
- `GET /api/v1/snapshot?at=<ISO 8601>` — полка на тот момент: работы, версия, бывшая последней, и версия, принятая тогда ([SHELF_SNAPSHOT](specs/SHELF_SNAPSHOT.md)).

## Сервисные доступы и токены задач

Для расписания и CI без человека. Включаются на установке флагом `SERVICE_ACCOUNTS=on`; на polochka.app выключены. Куратор полки отдела создаёт сервисный доступ в диалоге «Участники полки» («Сервисные доступы»): название, права (`context`, `read`, `source:read`, `capture`, `revise` или `share`, но `read` и `share` вместе нельзя; `manage` и `sign_in` нельзя), срок до 90 дней. За доступ отвечает создавший его человек, и его роль на полке ограничивает доступ. Если человек уходит с полки или его аккаунт стирают, доступ замораживается, пока администратор не назначит другого ответственного (при этом выдаётся новый токен, старые перестают работать).

Закреплённую ссылку сервисный доступ не двигает (ни публикацией новой версии, ни `moveShareId`): куратор включает «Ссылка следует за новыми версиями» в меню работы «Принятая версия».

`POST /api/v1/task-token` — токен на одну задачу, его просит сам сервисный доступ: `{"scopes": [...], "minutes": 5..60, "taskId": "..."}`. Права — подмножество прав родителя; токен умирает вместе с родителем, не выдаёт других токенов, не больше 20 живых одновременно; лимит запросов общий с родителем. Выдача пишется в аудит с `taskId`.

## `POST /api/v1/works/:artifactId/edits`

Правка сохранённой работы патчем — те же правила и путь сохранения, что у `polka_revise` с `edits` (scope `revise`; для `moveLink` — ещё `share`).

```json
{
  "key": "<новый UUID>",
  "baseRevisionId": "<последняя версия>",
  "edits": [{ "oldText": "выручка выросла на 12%", "newText": "выручка выросла на 14%" }],
  "path": "index.html",
  "moveLink": true
}
```

- Каждый `oldText` должен встречаться в файле (по умолчанию — HTML-странице) ровно один раз: сначала точно, затем после нормализации (NFKC по символу, типографские кавычки и тире, особые пробелы, CRLF и пробелы в конце строк). Меняются только найденные места; остальные байты файла сохраняются.
- `200`: `revisionId`, `number`, `previousRevisionId`, `htmlProfile`, `shelfUrl`; для страницы со скриптами — `interactiveReady` (сборка запускается в том же вызове); с `moveLink` — `link`: `moved` и новая ссылка или причина, почему не перенесена. Ссылка переносится вместе с её обсуждением.
- **Проект** (`project-v1`): `path` — любой текстовый файл проекта (Markdown, HTML, CSS, JavaScript, JSON, SVG, текст), по умолчанию точка входа. Остальные файлы хранилище копирует в новую версию само, их не нужно передавать, и размер проекта не важен ([PROJECTS](specs/PROJECTS.md#правка-одного-файла)). Картинку или новый файл добавляют новой версией проекта целиком.
- `422` `{"code": "edit_failed", "editIndex", "reason", "message"}`, `reason` — `not_found`, `ambiguous` (+ `occurrences`), `overlap` (+ `otherEditIndex`), `empty_old_text`, `no_change`.
- `409` `{"code": "conflict", "currentRevisionId"}` — правки написаны к другой версии. Тот же `key` с другим телом — `409` без `currentRevisionId`. Повтор с тем же `key` и телом возвращает ту же версию.

Прочитать замечания получателей можно инструментом MCP `polka_comments`.

## `POST /api/v1/sign-in-link`

Ссылка владельцу обратно в его полку — то же, что инструмент `polka_open_shelf`. Только на своей полке (для полки отдела — `403`), не больше 5 ссылок в час на подключение. Тело пустое (`{}`), ответ `200`:

```json
{ "kind": "hint", "url": "https://polochka.app/signin?shelf=…", "expiresAt": "…", "expiresInSeconds": 86400, "instructions": "…" }
```

- `kind: "hint"` — закреплённая полка: страница входа без секрета, человек входит как обычно.
- `kind: "link"` — временная полка: одноразовая ссылка `/enter#…` на 5 минут (`expiresInSeconds: 300`). Только для OAuth-подключения с разрешением `sign_in` («Давать ссылку для входа»); иначе `403`.

Передайте `url` человеку как есть и не открывайте его сами.

## Проекты: `/api/v1/projects`

Папка связанных страниц загружается одной работой по файлам ([specs/PROJECTS.md](specs/PROJECTS.md)). Обычно это делает CLI `polka-publish-project.mjs` (установка отдаёт его по адресу `/api/v1/cli/polka-publish-project.mjs`) с токеном из `polka_project_upload`; подходит и токен агента со scope `capture` (новая работа) или `revise` (новая версия).

| Маршрут | |
|---|---|
| `POST /api/v1/projects` | Начало загрузки: `key`, `title`, манифест (пути, MIME, размеры, SHA-256), `folderId`; для новой версии — `artifactId` и `baseRevisionId`. Возвращает `uploadId` |
| `PUT /api/v1/projects/:uploadId/files/:index` | Байты одного файла, `Content-Type: application/octet-stream` (иначе `415`), до 5 МиБ. Отдельный лимит частоты: вдвое больше файлов, чем помещается в проект |
| `PUT /api/v1/projects/:uploadId/media/:index` | Видео (`video/mp4`, `video/webm`) потоком, до 200 МиБ, с `Content-Length`. Полка кладёт байты в хранилище по мере поступления и принимает файл, только если он совпал с манифестом (размер, SHA-256, заголовок MP4/WebM), иначе ничего не остаётся ([PROJECT_VIDEO](specs/PROJECT_VIDEO.md)). Видео в проекте включается для полки оператором; без этого `POST /api/v1/projects` отвечает `403` |
| `POST /api/v1/projects/:uploadId/reuse` | Только для новой версии: файлы, у которых путь, тип, размер и SHA-256 совпадают с файлом базовой версии, хранилище копирует само. Ответ — `reused` (их индексы); остальные файлы отправляются как обычно |
| `POST /api/v1/projects/:uploadId/finalize` | Сохранение версии; ответ — квитанция и `shelfUrl` |

### `polka pull` и `push`

Скачать сохранённую версию в папку, поменять её и сохранить следующую версию (scope `source:read` для скачивания, `revise` для новой версии):

```sh
curl -fsSLO https://polochka.app/api/v1/cli/polka-pull.mjs
POLKA_TOKEN=… node polka-pull.mjs <artifactId или адрес работы> ./report
# …правки в ./report…
POLKA_TOKEN=… node polka-publish-project.mjs ./report
```

- `polka-pull.mjs` пишет файлы версии (по умолчанию последней, `--revision` — другой) и `.polka.json`: адрес установки, `artifactId`, `revisionId`. В непустую папку пишет только с `--force` и ничего в ней не удаляет. Каждый файл сверяется с SHA-256.
- `polka-publish-project.mjs` видит `.polka.json` и сохраняет следующую версию того же проекта: изменённые и новые файлы отправляет, остальные копирует Полка (`reuse`). Потом записывает новую версию в `.polka.json`. `--new` сохраняет папку новым проектом. Если на Полке уже есть более новая версия, сохранение отказывает (`409`): скачайте её заново.
- Маршруты: `GET /api/v1/works/:artifactId/files[?revisionId=]` — список файлов версии; `GET /api/v1/works/:artifactId/revisions/:revisionId/files/:index` — байты одного файла (заголовок `X-Polka-Sha256`).
- Токен из `polka_project_upload` скачивает, если у подключения, которое его попросило, есть `source:read`; тогда в ответе инструмента есть `pullCommand`.
- Синхронизации нет: версия меняется, только когда вы её сохраняете.

## Перенос полки: `GET /api/v1/export` и `polka-export.mjs`

Вся личная полка — для своей установки Полки или просто чтобы забрать данные ([SHELF_TRANSFER](specs/SHELF_TRANSFER.md)). Токен с правами `read` и `source:read`, на всю полку (не ограниченный папками).

```sh
curl -fsSLO https://polochka.app/api/v1/cli/polka-export.mjs
read -r -s POLKA_TOKEN && export POLKA_TOKEN
node polka-export.mjs ./polka-export
# на своей установке: npm run shelf:import -- --dir ./polka-export --account <почта>
```

- `GET /api/v1/export?cursor=&limit=` — опись: каждая работа (с корзиной) со всеми версиями, их датами, манифестами и списками файлов, папки и карточка полки; формат `polka-shelf-export/1`, `nextCursor` до последней страницы.
- `GET /api/v1/export/revisions/:revisionId/files/:index` — байты одного файла любой версии полки (`X-Polka-Sha256`); заблокированная модератором — `410`. Лимит — 3000 файлов за 10 минут на подключение, отдельно от 120 запросов.
- CLI пишет `polka-export.json` и `blobs/<sha256>`, каждый файл один раз; повторный запуск продолжает с места. Ссылки и комментарии не выгружаются.

## Сессии агентов

Для `polka-sessions.mjs` ([AGENT_SESSIONS](specs/AGENT_SESSIONS.md)); токен с правом `sessions`, только личная полка, на которой оператор включил сессии.

- `GET /api/v1/sessions/key` → `{ key }`: ключ HMAC для отпечатков секретов (64 hex), один на полку.
- `POST /api/v1/sessions`, тело `application/octet-stream` — gzip JSON индекса `polka-session-index/1` с отчётом о секретах и `transcript: {sha256, bytes}` → `{ id, created, transcriptNeeded, secretsStatus, alerts, url }`. Та же сессия (источник и её id) заменяет прежнюю.
- `PUT /api/v1/sessions/:id/transcript`, тело — gzip расшифровки `polka-session-transcript/1`, если `transcriptNeeded`.
- Ответы: 403 `sessions_disabled` (сессии на полке не включены), 413 `quota` (место для сессий кончилось), 400 — неверный индекс.

CLI: `GET /api/v1/cli/polka-sessions.mjs`, команды `login`, `list`, `preview`, `upload`, `sync`, `hook`.

## Ошибки

Всегда JSON `{"code": "…", "message": "…"}`; `message` — по-русски, для человека.

| HTTP | `code` | Когда |
|---|---|---|
| 400 | `invalid` | Поля не прошли проверку (`message` перечисляет их), некорректный UTF-8 или `html` длиннее 7 000 000 символов |
| 401 | `unauthorized` | Нет заголовка `Authorization`, токен неверный, истёк или отозван (`WWW-Authenticate: Bearer`) |
| 403 | `forbidden` | Нет разрешения (`capture`; для новой версии — `revise`), или запрос пришёл из браузера с чужим `Origin` |
| 404 | `not_found` | Статус или правка: работы (или файла) нет, она не ваша или в корзине |
| 409 | `conflict` | Тот же `key` уже использован для другого содержимого; у правок — ещё и другая базовая версия (`currentRevisionId`) |
| 422 | `edit_failed` | Правку не применить: `editIndex` и `reason` называют её |
| 413 | `quota` / `invalid` | Страница больше 5 МБ, тело запроса больше 8 МБ или закончилось место на полке |
| 415 | `invalid` | Файл проекта (`PUT /api/v1/projects/…/files/…`) прислан не как `application/octet-stream` |
| 422 | `invalid` | Не похоже на HTML или содержит NUL |
| 422 | `unsupported` | Прислан `component`, а интерактивный просмотр на установке выключен |
| 429 | `quota` | Лимит частоты: 120 запросов на подключение за 10 минут. Лимит 300 на IP-адрес считает только запросы без токена или с неверным токеном: агенты на хостинговых платформах делят адреса. Пауза — в `Retry-After` |
| 503 | `busy` / `conflict` | Полка занята параллельным действием с теми же работами (`busy`, `Retry-After: 5`) или транзакция пересеклась с другой (`conflict`, `Retry-After: 1`). Ничего не сохранено; повторите с тем же `key` |

## Как устроено

- Cookies не читаются и не выставляются: браузерная сессия владельца здесь не работает. Поэтому общая проверка `Origin` для браузерных маршрутов к `/api/v1/publish` не применяется (как к `/mcp` и машинным OAuth-адресам), но запрос с `Origin` другого сайта отклоняется. Исключение — `chrome-extension://<32 буквы a–p>`: так Chrome подписывает запросы расширений, в том числе [«На Полку»](../extensions/chrome/README.md); это не веб-страница, токен у него свой.
- Токены те же, что у `/mcp` (audience `…/mcp`), включая OAuth-подключения чатов.
- Лимит частоты: запросы без токена или с неверным токеном считаются по IP (за прокси нужен верный `TRUST_PROXY`, иначе все клиенты делят один адрес прокси), запросы с действующим токеном — по подключению.
- Код: `apps/server/publish-api.ts`; тесты: `tests/publish-api.test.ts`. Схемы ответов (`publishResponseSchema`, `statusResponseSchema`) лежат там же: тесты сверяют с ними настоящие ответы, а `/openapi.json` (`apps/server/openapi.ts`) строится из них и из схем входа; тест `tests/agent-discovery.test.ts` проверяет, что каждый маршрут модуля описан.

## CLI без зависимостей

`scripts/polka-publish.mjs` — один файл для Node 22+, только встроенный `fetch`. Установка Полки отдаёт его по адресу `/api/v1/cli/polka-publish.mjs`. Скачанная с установки копия по умолчанию отправляет работы на эту же установку. Копии из репозитория адрес обязательно передают через `POLKA_ENDPOINT` или `--endpoint`: адреса по умолчанию у неё нет, чтобы работа случайно не ушла на чужую установку:

```sh
export POLKA_ENDPOINT=https://polochka.app
curl -fsSLo polka-publish.mjs "$POLKA_ENDPOINT/api/v1/cli/polka-publish.mjs"
read -r -s POLKA_TOKEN && export POLKA_TOKEN

node polka-publish.mjs report.html --title "Отчёт за квартал" --share 7
# → https://polochka.app/s#…   (ссылка в stdout, пояснения в stderr)

cat report.html | node polka-publish.mjs - --title "Из пайплайна" --json

node polka-publish.mjs App.jsx --title "Прототип"      # React-компонент, интерактивно
node polka-publish.mjs App.jsx --artifact <id> --base-revision <revision>   # новая версия по той же ссылке
```

Из репозитория: `POLKA_ENDPOINT=… node scripts/polka-publish.mjs …`; `npm link` поставит команду `polka-publish`.

| Параметр | |
|---|---|
| `<file>` или `-` | HTML-файл или stdin. Файл не `.html`/`.htm`, который не начинается с `<`, публикуется как текст без разметки в `<pre>`; stdin всегда считается HTML |
| `--title` | По умолчанию `<title>` страницы или имя файла |
| `--share 1\|7\|30` | Срок ссылки |
| `--folder <uuid>` | Папка |
| `--component` | Отправить файл как исходник React-компонента; для `.jsx`/`.tsx` включено само |
| `--artifact <uuid>` `--base-revision <uuid>` | Новая версия работы; открытая ссылка переходит на неё |
| `--key <uuid>` | Свой ключ идемпотентности (по умолчанию новый) |
| `--endpoint <url>` | Адрес Полки (или `POLKA_ENDPOINT`). Для копии из репозитория обязателен. Только https, кроме localhost |
| `--json` | Весь ответ API и использованный `key` |

Токен читается только из `POLKA_TOKEN`; `--token` отклоняется. При сетевой ошибке, `429` и `5xx` CLI делает до трёх попыток с тем же ключом (паузы 2 и 4 с). Коды выхода: `0` — сохранено (со ссылкой или приватно), `1` — отказ сервера, сети или чтения файла, `2` — неверный вызов.
