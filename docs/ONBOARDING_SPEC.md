# Первый результат и подключение MCP

Спецификация MVP, 20.09.2026. /signup и /start реализованы с локальным тестовым входом; /settings/agents — демонстрационный мастер. /bring работает с файлами, импорт ссылки пока демонстрационный. Остальные состояния и маршруты ниже — требования, а не подтверждение реализации. Статус: [STATUS](STATUS.md).

## Навигация

Лендинг: «Сохранить артефакт», «Посмотреть примеры», «Войти». Личная полка: «Добавить», «Агенты», поиск и папки. Пункт «Агенты» ведёт прямо в /settings/agents, без Telegram и матрицы enterprise-прав. /connections оставить исторической демонстрацией до замены; не использовать как конечный onboarding.

| Экран | Пользовательская история и действие | Состояния / приёмка |
|---|---|---|
| /signup | Хочу получить личную полку без администратора: email → код из письма → войти | Код истёк/неверен, повтор с cooldown, лимит, письмо не пришло, существующий аккаунт. Одноразовый код хранится хешем, короткий TTL; никаких обязательных компании/профессии/агента |
| /start | Хочу сохранить первый результат: «Вставить ссылку», «Подключить агента», менее заметно «Загрузить файл» | После верификации возвращаем URL/источник/намерение; не загружаем файл и не делимся автоматически. Если файл потерян при перезагрузке — объяснить и попросить выбрать повторно |
| /bring | Вставляю публичную ссылку и вижу, удалось ли сохранить | checking/downloading/packaging/preview/failed. Показывать реальные этапы job; поддержанные провайдеры, что перенесено, чего не хватает. Неизвестный формат даёт файл/MCP fallback; не фальшивый success |
| /settings/agents | Хочу подключить своего агента | Клиенты: Claude, Codex, другой MCP. Для каждого дата/версия проверки совместимости, доступный способ установки. Краткие шаги вместо общей матрицы |
| /settings/agents/connect | Выбираю клиента → авторизую → разрешаю действия в моей полке | Два простых набора: «Сохранять приватно»; «Сохранять и создавать ссылки по моему поручению». Второй явно объясняет получателей URL и TTL. Список прав и срок доступны до разрешения |
| Connection callback | Хочу знать, что всё действительно подключилось | Connecting/connected/denied/expired/offline; connected появляется после реального авторизованного запроса, не после копирования инструкции |
| Проверка | Говорю агенту «Сохрани тестовую страницу на Полку» | Полка получает capture, показывает receipt и «Открыть». Агент возвращает owner URL или share URL по scope. Проверить второй клиент независимо |
| Первая страница | Хочу посмотреть результат и отправить другу | Большой live preview, видимость, «Поделиться», «Новая версия». Первый результат без обязательного названия папки, тэгов и профиля |
| Настройки подключения | Хочу отозвать доступ или посмотреть последнее действие | Клиент, scope, последнее успешное сохранение, ошибка, revoke. Отзыв запрещает следующие операции; файлы остаются. Отзыв подключения и закрытие уже созданных ссылок — разные понятные действия |
| /settings/account | Хочу управлять своим аккаунтом | Активные сессии, выход, удаление аккаунта с понятным сроком очистки/backup retention, экспорт |

## Контракт MVP для агента

Имена предлагаемые, закрепить SDK/schema до реализации:

- `polka.context`: выбранное пространство, scopes, лимиты, поддержанные форматы, короткий guide, версия API. Не выгружать всю библиотеку в контекст.
- `polka.list`: пагинация разрешённых артефактов/папок.
- `polka.capture`: файл/bundle, title, idempotency key; возвращает artifactId, revisionId, состояние обработки и ownerUrl. Чтение локального файла выполняет клиентский adapter, облачный сервер не читает путь на ноутбуке.
- `polka.capture_status`: receipt или этап/ошибка; после таймаута можно продолжить по idempotency key.
- `polka.share`: фиксированная версия + TTL + granted scope. Возвращает shareUrl, кто откроет, expiry. «Создай и пришли ссылку» исполняется целиком, если scope разрешает.
- `polka.revise`: baseRevisionId, новый bundle; конфликт не перетирает чужую версию. Существующая share-ссылка не обновляется молча.
- `polka.revoke_share`: только разрешённые ссылки.

MCP — интерфейс к корпоративному/личному агенту, не встроенная модель Полки. Не просим API key провайдера модели. Для remote MCP использовать проверенный SDK и совместимый auth-flow (OAuth discovery/PKCE по поддерживаемой версии); для CLI beta допустим узкий отзываемый токен в конфигурации клиента, не в промпте. Не обещать поддержку любого клиента без теста; минимум два реально проверенных клиента. Все серверные проверки tenant/scope/idempotency одинаковы для HTTP и MCP.

## Шесть сценариев приёмки UI

1. Новый посетитель за 10 секунд называет пользу и находит добавление ссылки.
2. После регистрации продолжает то же сохранение без поиска страницы заново.
3. Пользователь Claude подключает Полку по инструкции без помощи разработчика; тестовая квитанция видна в двух местах.
4. Получатель без аккаунта провайдера открывает ссылку на телефоне и использует калькулятор.
5. Ошибка источника/ограничение HTML не выглядит как успешно сохранённый интерактив.
6. Владелец отзывает MCP и отдельно ссылку; UI не смешивает результаты.

Проверить клавиатуру, focus, screen reader labels, 390px/768px/1440px, loading/empty/error, refresh/back/retry. Макет красивого connected состояния не является приёмкой подключения.
