# Полка: проверка прототипа и симуляция пользователей

Дата: 2026-09-20. Это экспертная симуляция, не интервью и не доказательство спроса. Новые модели Fable/Opus в этом проходе не вызывались.

## Метод и границы

В браузере открыты /landing, /bring, /connections, /discover, карточка mortgage-calc, экран входа и /s без токена. Проверены переключение вкладок, распознавание синтетической Claude-ссылки и изменение слайдера калькулятора. Просмотрены скриншоты /bring и /connections. Изучены GOAL.md, DELIVERY_PLAN.md, код Bring, main, Recipient, агентского демо и точки версий/папок App.

Не выполнены в этом проходе: вход в аккаунт, новый upload/share/revoke в браузере, личные папки/версии через UI, реальный MCP, извлечение настоящей Claude-ссылки, доступ из российских сетей, проверки нескольких браузеров. Прежние 31 тест не объявляются повторно пройденными. Это обзор основных путей и документов, а не полная E2E-приёмка всех состояний.

## Вердикт

Сохраняем продуктовую идею и визуальную основу. Утверждать прототип целиком для реализации рано: он всё ещё проектирует загрузку файлов, а свежая договорённость — ранний MCP плюс живой просмотр. Нужна одна ограниченная корректировка сценариев и документации, затем реализация первого сквозного пути.

## Что означает «вживую»

1. Просмотр HTML/CSS с расчётами и переключателями: обязательный первый выпуск.
2. Сохранение личных отметок между посещениями: отдельная функция; не следует из возможности выполнить JavaScript.
3. Совместно изменяемые данные, серверные API, авторизация самого мини-приложения: отдельный объём, не обещать как следствие загрузки HTML.

Текущие пользовательские страницы статичны. Демо калькулятора в витрине реагирует: при смене досрочного платежа с 10 000 на 20 000 срок изменился с 9 лет 4 месяцев на 6 лет 7 месяцев. Это подтверждает только встроенный пример. Его описание «Загружен HTML-файлом» создаёт ошибочное ожидание идентичного пути для собственной страницы.

Это гипотезы препятствий, а не цитаты участников или количественные оценки.

## Приоритетные расхождения

- GOAL.md запрещает возвращать токен ссылки агенту; AgentDelegationDemo пишет «вы копируете их в Полке». Это противоречит принятому сценарию MCP. Разрешённый sharing должен возвращать адрес агенту; токены подключения при этом остаются секретными и не попадают в логи.
- DELIVERY_PLAN оставляет E4 необязательным; свежий scope включает импорт поддержанных ссылок. Приоритеты нужно синхронизировать, не теряя ранний MCP.
- /bring по умолчанию открывает файл; /connections начинает с Telegram. Для принятого scope первыми должны быть ссылка и подключение агента.
- Бейджи real/demo/plan делают макет честным, но интерфейс объясняет устройство разработки вместо решения задачи. В production оставить только доступные действия; карту будущих функций вынести отдельно.
- Экран входа говорит «С возвращением» и «внешняя регистрация не нужна», хотя новый человек не может начать самостоятельно. Для публичного пилота нужен вход/регистрация либо понятное приглашение.
- Нет проверенного контракта состояния интерактивной страницы: отметки только в текущем открытии, личное постоянное состояние или совместные данные.

## Ограниченная корректировка перед реализацией

A. Сохранить: публичная ссылка, файл и «Подключить агента», одно место результата — сохранённая версия.
B. Подключить агента: выбор клиента → ограниченные права → инструкция → реальная проверка → пример фразы. Не три длинных режима с корпоративным ревью.
C. Результат: название, предпросмотр, работает ли интерактив, кто имеет доступ, создать/скопировать ссылку, открыть как получатель.
D. Получатель: страница занимает основной экран; название/версия/жалоба компактны. Объяснить сохранение введённых данных.
E. Моя Полка: найти → открыть → новая версия → явно обновить ссылку; доступ не меняется от сохранения версии.

## Задание для первого инженерного среза (кандидат, ещё не выполнено)

Сохранение HTML и ресурсов через MCP → неизменяемая версия → изолированный интерактивный просмотр → ссылка возвращается агенту по поручению пользователя → получатель открывает → новая версия → отзыв.

Приёмка: два клиентских подключения проверены отдельно; калькулятор и график действительно реагируют из сохранённых байтов, а не React-демо; недостающие ресурсы названы; результат не теряется при повторе запроса; чужие данные недоступны; runtime не получает полномочия приложения; отзыв действует; артефакт не зависит от доступности исходного чата. Не обещать произвольный серверный мини-продукт.

Следующий срез: адаптер публичных ссылок на корпусе настоящих страниц, самостоятельный вход, стабильная поставка и закрытый облачный пилот. MCP остаётся обязательным первым входом, а не переносится после сообщества.

## Реальная проверка с людьми после среза

Пять участников: два автора с разными агентами, автор с публичной ссылкой и два получателя. Дать им собственную страницу и задачу отправить её; не инструктировать по кнопкам. Записать места остановки, время, работу интерактива, понимание доступа и результат повторного открытия. Не выводить прогноз роста или ретеншна из симуляции.
