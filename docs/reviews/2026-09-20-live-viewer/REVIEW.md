# B2 и проверка восстановления B1

Astra подготовила контракт изолированного viewer. Реализация backend делегирована Sol, frontend — Luna с непересекающимися файлами. Источник требований: [LIVE_VIEWER_SPEC](../../LIVE_VIEWER_SPEC.md).

B1 browser: старый listener отдавал 404 на /api/auth/email/current; подтверждены PID и command, затем перезапущен именно процесс Полки. В актуальном сервере через браузер создан запрос для вымышленного .test email, после reload восстановились шаг «Введите код», тот же challenge ID и оставшийся cooldown. Реальное письмо не отправлялось, сессия пользователя не менялась. Это закрывает проверку восстановления формы, но не SMTP и приёмку пятью новыми пользователями.

## Реализация и повторное ревью

Sol: отдельный backend listener, owner/recipient capabilities, migration 005, reauthorization, pinned storage и 5 integration tests. Luna: отдельный LivePreview с явным запуском, остановкой, abort/generation guards и compact opt-out. Ведущий исправил найденные Astra expiry/fallback states, добавил disabled regression, maintenance cleanup и self-navigation fixture. Runtime только loopback; флаг по умолчанию false. .env не изменён: локальный проверочный процесс запущен с переменной HTML_LIVE_ENABLED=true.

Astra: блокеров для локального среза не найдено; замечания про доступ после 60 секунд и недостаточную проверку выключенного режима учтены. Проверка ранее выданного capability после перезапуска с false ещё отдельный runtime сценарий; код повторно проверяет флаг.

Проверки: npm run check pass; npm test **38/38** ([протокол](tests-default.txt)); npm run test:live **5/5** ([протокол](tests-enabled.txt)); build pass. Новые tests проверяют HTTP/schema/права, а не браузерную изоляцию. Default suite использует выключенный режим; live suite запускается отдельно с явным флагом.

## Браузерная проверка

Через реальные upload/finalize/share созданы пять собственных synthetic HTML материалов; новые аккаунты/данные только тестовые. Существующая пользовательская сессия не заменялась.

- Получатель: калькулятор открылся в iframe на localhost:4391 из приложения 127.0.0.1:4390; 3 × 100 → 300 подтверждено accessibility tree. Остановка удалила живой frame.
- Получатель: график переключён 30 → 60, подтверждено UI. Исходный сервис не нужен, JS взят из сохранённого blob.
- UI tools не смогли надёжно кликать по дробным координатам iframe; взаимодействия доведены клавиатурой. Это ограничение автоматизации, а не доказательство недоступности кнопок человеку.
- Self-navigation: нажатие в оригинальном синтетическом примере изменило frame на chrome-error с названием self-navigation.invalid и сообщением content blocked. Нет записи сети/CSP violation, объясняющей причину: **egress-приёмка не доказана**. Во внешнем адресе не было данных/токенов, только фиксированная строка synthetic.
- Добавлен явный «Обновить доступ» в live и fallback; текущий браузерный DOM подтверждает наличие. Повторный запуск после expiry, весь отрицательный корпус, responsive и все 20 файлов ещё не приняты.

Следующие задачи: завершить browser corpus с наблюдением сети/навигации, проверить grants при перезапуске/отключении, определить исполнимую модель для hosted; затем bundle/manifest и внешний URL adapter. Локальный эксперимент не закрывает R06 и не заменяет безопасный конечный продукт.
