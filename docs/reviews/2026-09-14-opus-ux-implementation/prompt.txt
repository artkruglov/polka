Продуктовая задача:
Polka — место, куда попадает работа внешнего или корпоративного агента и откуда её можно открыть, проревьюить и расшарить. Это не обычный диск и не встроенный чат. Главный job: «работа агента превращается в ссылку, которую откроет коллега». Второй: «положи работу на Полку» через API/MCP. Для компаний важен узкий путь: SSO/внутренний агент → private revision → внутренняя ссылка → замечание → v2 → принятие.

Критика текущего UI, которую нужно исправить:
1. Не показывать отдельный путь «вставить код». Главные входы — «Вставить ссылку» и «Загрузить файл»; код/HTML является содержимым файла.
2. Нельзя обещать «без VPN» или «за 5 минут» как доказанный факт. Формулировки должны объяснять копию и отсутствие обращения к исходному сервису.
3. После private save нельзя сразу показывать экран получателя. Сначала явный шаг «Только я» → «Открыть доступ по ссылке»/«В компании» → только затем preview получателя.
4. UI должен показать, что агент не публикует и не принимает работу за человека.
5. Нужна видимая минимальная коллаборация: комментарий к конкретной версии/месту, статус открыто/решено, candidate v2, сравнение и принятие человеком. Не делать Figma, полноценный редактор, real-time co-editing или встроенный чат.
6. Нужно показать корпоративную границу без тяжёлой админки: «внутренний workspace», разрешённый агент, что он может/не может, аудит и offboarding как отдельные состояния/карточки.

Что реализовать:
- Перепроектируй `/bring` как современный 2026 интерфейс: один ясный hero, ссылка как основной вход, файл как равноправный fallback без code tab, аккуратные состояния checking/ready/unsupported/private/saved/share/review.
- Добавь в этот же UX-поток после сохранения явный доступ и мини-preview получателя.
- Добавь интерактивный review slice (можно внизу `/bring` или отдельным `/review` route): выбранная версия, 1–2 якоря/страницы, комментарий, статус, candidate v2, before/after и кнопка «Принять v2». Все данные демонстрационные и помечены как прототип.
- Добавь компактную карточку «Подключение агента» с capability chips `Сохранять`, `Читать замечания`; отдельно явно покажи `Публиковать — запрещено` и `Принимать — только человек`.
- Сделай public gallery/login/shelf CTA согласованными с новым языком («ссылка или файл», «принести работу»), но не переписывай весь продукт.
- Сохрани русские тексты, responsive desktop/mobile, keyboard/focus, reduced motion. Используй существующие lucide-react и CSS; новые зависимости не добавляй.
- Не симулируй реальный import/MCP/backend: рядом с демо напиши, что это UI-прототип и серверные операции пока не подключены. Не показывай фиктивную успешную сетевую квитанцию как реальную.

Рабочий процесс:
1. Сначала осмотри текущий код и запущенный UI.
2. Сам выбери минимальные изменения, не переписывай сервер.
3. Внеси изменения в файлы.
4. Запусти `npm run check`, `npm run build`, `npm test`.
5. Проверь `/bring` и ключевые состояния браузерной проверкой, если доступно.
6. В финальном ответе перечисли конкретные UX-решения, изменённые файлы, тесты и оставшиеся ограничения.

Не создавай новый репозиторий, не меняй лицензию, не добавляй маркетинговые обещания, не реализуй backend/import/MCP и не возвращай только план: изменения UI должны быть внесены в рабочее дерево.
