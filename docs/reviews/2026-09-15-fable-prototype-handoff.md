# Fable → Opus: handoff прототипной итерации

Дата: 15 сентября 2026. Продуктовый и UX-лид: Fable 5.1.

## Контекст

Главная рамка: публичная ссылка на работу из Claude/ChatGPT/другого агента → независимая копия Полки → ссылка, открывающаяся у получателя без входа в исходный сервис. Интерактивный HTML должен работать безопасно в networkless runtime в будущем. Пока URL import и runtime отсутствуют; рабочий путь — загрузка HTML/TXT/PNG/JPEG/WebP, receipt, ссылка, `/s`, отзыв и жалоба. MCP, Telegram, чат, витрина и enterprise — последующие ускорители.

## Вердикт Fable

Текущий прототип ещё file-first. URL-карточка — мок, сервер ничего не скачивает; интерактивный runtime не включён. Главный дефект — реальный upload, URL demo, MCP, Telegram, review и company controls смешаны на одной странице. Получатель не должен видеть демо как собственную сохранённую страницу.

## Цель итерации

Сделать прототип честным и понятным:

1. автор с публичной ссылкой понимает, что URL-импорт пока демо, и за один клик переходит к рабочему пути «сохранить файлом»;
2. получатель видит независимую копию, её профиль (`static`/`limited`), версию и статус интерактивности;
3. администратор видит, что сегодня работает, что демо и что планируется, без ложного enterprise-обещания.

## Приоритетные изменения интерфейса

### Landing

- H1: «Сделали в чате — отправьте ссылку, которая откроется у получателя.»
- Поле «Вставьте публичную ссылку на работу», CTA «Проверить ссылку · демо».
- Рядом явный рабочий CTA «Загрузить HTML-файл».
- Статус: «Импорт по ссылке ещё не подключён: сейчас ссылку распознаём, а копию сохраняем файлом».
- Не обещать VPN, работающие кнопки или интерактив до runtime.
- В блоках «Что откроется» разделить `real`, `plan`, `unsupported`.
- MCP/Telegram/команды — компактный плановый блок без инструкций подключения.

### `/bring`

- Одна верхняя лента статусов: сохранение файла — `real`; URL-распознавание — `demo`; интерактивный runtime — `plan`.
- Вкладки «По ссылке» (`demo`) и «Файлом» (`real`), по ссылке активна только для демонстрации распознавания.
- URL-ветка: классифицирует `not_https`, `closed`, `unsupported_host`, `ready`; не показывает receipt, чужой дашборд или ссылку, как будто импорт выполнен.
- Единственный основной CTA из URL demo: «Сохранить файлом».
- Реальный FileSave: показывать профиль «Сейчас» и «В плане», создавать ссылку на 30 дней, дать «Открыть как получатель».
- Остальные демо вынести на `/connections` под явной лентой «Прототип будущих функций: ничего не отправляется на сервер».

### `/s`

- Бейдж «Статичный просмотр» или «Ограниченный просмотр: кнопки не работают».
- Ясно писать: «Это копия с Полки; вход в Claude/ChatGPT не нужен».
- Для limited: «Интерактивный просмотр без сети — в плане».
- «Сохранить себе» оставить обычным текстом со статусом `plan`, не нерабочей кнопкой.
- Сохранить настоящую жалобу; после отзыва — нейтральный отказ без названия работы.

### `/discover`

- Только редакционные примеры с вымышленными данными и бейджем `demo`.
- Убрать фиктивные счётчики реакций; лайки, закладки и ремикс — план.
- «Взять за основу» — статус `plan`, не рабочая кнопка.

## Мок URL import

Добавить чистый `importMock.classify(url)` и `UrlImportCard`, но не делать сетевого импорта и не выдавать `artifactId`/receipt. Типы `ImportPreview`, `ImportStatus`, `ImportProvenance` можно добавить в contracts с пометкой server not implemented. `/api/capabilities` должен явно содержать `urlImport:false`, `htmlRuntime:false`.

Классификация: не-https; закрытые пути/login; `claude.ai/public/artifacts/*`; `chatgpt.com/share/*` и `canvas/shared/*`; прямые `.html`/`.zip`; остальное unsupported_host. В результате всегда объяснение и переход к файлу.

## Runtime-прототип

Серверную интерактивность не включать. В `profileView` добавить поля `now` и `plan`; показать ожидаемое состояние для inline calculator/chart. Добавить фикстуры `static-report`, `inline-calculator`, `inline-chart`, `checkbox-planner`, `fetch-weather`, `cdn-dashboard`, `form-feedback`, `password-login`, `meta-refresh`, `script-only`. Не ослаблять CSP и не добавлять `allow-scripts`.

## Технические файлы для Opus

- новый `Status.tsx` и `StatusRibbon`;
- новый `importMock.ts` и `UrlImportCard.tsx`;
- новый `Bring.tsx` для `/bring`, перенести будущие демо в `Connections.tsx`;
- обновить `Landing.tsx`, `FileSave.tsx`, `format.ts`, `Recipient.tsx`, `PublicGallery.tsx`, `App.tsx`, `main.tsx`, `entry.css`;
- добавить unit tests для `importMock` и HTML profiles, интеграционные проверки capabilities/routes;
- не менять `html.ts`, `artifacts.ts`, storage, migrations, CSP, share schema и server importer.

## Acceptance criteria

1. Главный CTA лендинга не выдаёт демо за сохранение.
2. URL demo не показывает чужие данные и не выдаёт receipt.
3. Один CTA из URL demo ведёт к рабочему FileSave.
4. FileSave создаёт receipt, ссылку и открывает `/s`.
5. `/s` показывает профиль, версию, дату и честный статус интерактивности.
6. Unsupported HTML сохраняется только для владельца без кнопки ссылки.
7. Все agent/MCP/Telegram/review/company controls находятся на `/connections` и имеют `demo/plan`.
8. Витрина не показывает фиктивные числа реакций.
9. Landing и `/bring` не обещают VPN, runtime или регистрацию.
10. `npm run check`, `npm run build`, unit/integration tests проходят.

Не делать в этой итерации: серверный URL fetch/proxy, SSRF worker, интерактивный runtime, ZIP, регистрацию, MCP endpoint, Telegram bot, встроенный чат, enterprise SSO/admin и социальные рейтинги.
