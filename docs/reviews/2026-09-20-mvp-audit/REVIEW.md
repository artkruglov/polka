# Полка: сверка продукта, экранов и реализации

Дата: 20 сентября 2026. Решение: **готовый локальный срез хранения + UI-прототип, не готовый публичный MVP**. Новый дизайн не закрыл регистрацию, MCP, импорт и исполнение HTML. Процент готовности не вычисляем: эти пробелы блокируют основной пользовательский результат.

## Основание и границы ревью

Просмотрены текущие маршруты main.tsx/frontend.ts, App, Login, Bring, Connections, AgentDelegationDemo, Explore2026, Preview, HTML policy, API routes, SQL migrations, contracts, deployment scripts и тесты. Сопоставлены GOAL, REQUIREMENTS, INTERFACES, PRODUCT_AND_STORIES, API_AND_AGENTS, ARCHITECTURE, LAUNCH, DELIVERY_PLAN, DOMAIN_MODEL, COMMUNITY_PUBLICATION, SHARING_AND_DISCOVERY, PROTOTYPE_2026, прежний production-план и original requirements review.

Исходные требования Lanka представлены сохранённым реестром reference/lanka-requirements.json и REQUIREMENTS_TRACE.csv. Ранее 195 строк двух PRD классифицированы как 99 preserved, 74 adapted, 19 deferred, 3 retired. Это решения о переносе смысла, **не 173 выполненных требования**. В этом проходе не перечитывались все 447 исторических документов и не проводился полный security audit. Реальных интервью не было.

## Ошибки согласованности

1. GOAL/API/AgentDelegationDemo всё ещё запрещают выдавать ссылку агенту. Это ломает «положи и дай ссылку». Новый launch-план заменяет запрет scoped sharing: владелец может разрешить выдачу unlisted URL для выбранного пространства/объекта и срока. Нет права — сохранить приватно и вернуть owner URL, не делиться автоматически.
2. В M1 накопилась большая enterprise-модель поручений, а элементарного «подключить клиента → тестовый файл» нет. Сначала один работающий capture-путь; общий движок approvals позже.
3. Старый UI-тест запрещает слово «артефакт» во всех TSX. Владелец вернул это слово в позиционирование; новое UI закономерно нарушает устаревший тест. Нужно заменить запрет проверкой правдивости возможностей, не возвращать прежний нейминг ради зелёного теста.
4. Две витрины/лендинга: PublicGallery и LegacyLanding остаются в исходниках, активны Explore2026/NewLanding. Изменение неактивного файла не изменит сайт. При следующей разработке удалить/архивировать неиспользуемый UI после проверки зависимостей.
5. Запрет индексации распространяется глобально в API hook. Лендос должен индексироваться в production; private/unlisted — нет. Нельзя просто убрать заголовок везде.
6. Локальные likes/bookmarks не общие между аккаунтами и устройствами; автора из query можно вывести как заголовок без реального профиля. Подпись demo обязательна до API.
7. Одинаковые обложки и общие графики создают впечатление множества материалов, но после открытия не дают обещанной пользы. 12 законченных артефактов лучше 24 переименованных графиков.
8. Связь «локальный сервер стартовал» ≠ «продукт работает»: процесс может слушать порт при недоступных DB/S3. Нужен readiness и управляемый запуск. В этом проходе отсутствие Docker привело к ошибке страницы входа.

## Чего не хватает в новых прототипах

См. ONBOARDING_SPEC.md: /signup, подтверждение/ошибка письма, /start, /settings/agents, мастер MCP, тестовое сохранение, восстановление импорта, first-success, операторская moderation. Входы нужны из главной, пустой полки и после просмотра примера. Состояния expired/revoked/unsupported должны быть визуально согласованы с reader, а не только положительный экран.

## Какие старые идеи сохраняем

Независимая копия с manifest/provenance, immutable revision, права и версии ссылок, источники внутри исследований, собственные агенты организации, audit, экспорт исходного bundle, развёртывание внутри, доступность и мобильный просмотр. PPTX-редактор, DeckDoc, внутренний чат, Figma-подобное редактирование и общий агентный orchestration не нужны для первого выпуска Полки. Ремикс — вторичная возможность с лицензией, не первая фраза лендинга.

## Вывод

Не переписывать хранилище с нуля. Переиспользовать транзакции upload/revision/share и UI reader. Добавить application services, чтобы MCP и web использовали один контроль доступа. Публичный запуск блокируют реальные onboarding + capture + viewer + cloud operations. Наполнение и красивая витрина усиливают этот путь, но не заменяют его.
