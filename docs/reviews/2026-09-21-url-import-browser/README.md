# URL import: браузерная приёмка первого сквозного сценария

Дата: 21.09.2026. Отдельная временная база с миграциями001–019; сервер и viewer на loopback. Рабочая база/процесс на4390 не мигрировались и не перезапускались. Запуск: `node --env-file=.env --import tsx scripts/test-url-import-runtime.ts --browser`; нужен свободный localhost:4599 для viewer. При завершении дочернего процесса SIGTERM удаляются точные записанные S3-версии, затем runner удаляет временную БД. Тестовая учётная запись из browser-check не используется настоящим приложением.

## Проверено через интерфейс

- Без входа: попытка сохранить URL → сообщение401. Исправление: кнопка входа, черновик ссылки в sessionStorage без помещения его в URL входа. После входа браузер вернулся в форму с прежней ссылкой, дополнительный импорт сам не запускался.
- Реальный публичный источник `https://mdn.github.io/learning-area/javascript/building-blocks/events/random-color-addeventlistener.html`: форма → очередь → «Сохранено. Можно открыть» → материал → явный запуск viewer на другом origin → действие Change color меняет цвет страницы. Проверено при1280×900 и390×844.
- Для кнопки внутри iframe использовался Enter через CUA: автоматизация мыши отклонила fractional iframe coordinates. Это доказательство действия с клавиатуры, не полноценный touch-тест.
- `javascript-label.html` из того же MDN learning-area загрузился, но prompt() блокируется sandbox и возвращает null. В интерфейс добавлено явное ограничение системных диалогов/внешних запросов. Нельзя считать любую собранную страницу полностью функционально совместимой.

## Найдено и исправлено

- `.app nav {height:calc(100% - 80px)}` воздействовал на общий mobile tabbar. При844px высоты меню занимало764px и перекрывало reader. Старый селектор ограничен `.app aside nav`, общие компоненты явно имеют height:auto. Проверено повторным рендером: панель снова компактна внизу.
- Успешно сохранённый bundle использовал `.preview-error` с коричневым цветом. Введён общий shared StatusPanel, использован в Preview (обычный/компактный), кнопка экспорта использует общий ui-button.

## Единый актуальный браузерный проход (schema21)

На одной disposable-установке с текущим dist выполнено: вход → создание папки «Приёмка MVP» → переход в bring → вкладка «По ссылке» → реальный MDN random-color-addeventlistener.html → выбор папки → ready → reader (папка указана в контексте) → запуск → Change color → включение share → logout → гостевой просмотр при390×844 → Change color → вход владельцем → отзыв → logout → тот же адрес недоступен. Запросы импорта и доступов шли через интерфейс, snapshot не внедрялся.

Клик по iframe CUA отклонил из-за дробных координат; стандартный keyboard Enter по кнопке внутри iframe сработал и изменил фон и у владельца, и у гостя. Screenshots: current-owner-interactive.png, current-guest-mobile.png, current-revoked.png. Это keyboard-приёмка интерактива, не доказательство pointer/touch.

Выявлен UX-gap: переход «Сохранить работу» из выбранной папки не переносит folderId в bring; её пришлось выбрать повторно. Импорт после явного выбора сохранился в нужную папку. Нужна правка переноса контекста. Ошибки/retry и MCP на той же установке в этот проход не входили. Рабочая4390 и её данные не изменены; публикации наружу не было.

## Приёмка переноса папки

На текущей сборке/schema21 браузером создана папка «Контекст папки». Переход с её экрана на bring включил folder в query. File-вкладка автоматически выбрала папку; url-вкладка сохранила тот же выбор; возврат к file не потерял его. Через системный file chooser загружен синтетический TXT102байта. Сохранение прошло; открытый reader показывает «Контекст папки / Материал» и точный текст файла. Screenshot: folder-file-saved.png. Шаги выполнялись в disposable-базе, рабочая установка не менялась. Реальная загрузка по URL в этом проходе не повторялась; проверен автоматический выбор её destination. Login-return с folder и недоступная папка остаются отдельными проверками.
