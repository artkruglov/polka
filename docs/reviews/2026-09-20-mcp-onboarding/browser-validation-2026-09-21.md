# Проверка формы MCP — 21.09.2026

Реальный Codex in-app browser, существующая авторизованная локальная сессия, `/settings/agents`. После reload актуальной сборки:

- Отправка имени из трёх пробелов показывает «Введите имя подключения от 1 до 80 символов»; список не пополняется. В коде эта ветка возвращается до вызова API.
- Сведения/статус отмечены и недоступны для снятия. Capture отмечен; list/revise/share/manage по умолчанию не отмечены.
- UI прямо объясняет, что scopes относятся ко всей Полке, а list не включается автоматически.
- Прежнее тестовое подключение context показано как отозванное; поясняется, что отзыв подключения не отзывает прежние ссылки.
- После reload форма снова пустая и сообщение валидации исчезает. Новые credentials не выпускались, прежние permissions не менялись.

Это проверка формы и отображения текущего состояния. Сетевые ошибки, полный UI-issued token → native client → seen/capture и второй native клиент здесь не принимались.


Следующий тест подготовлен, ожидает подтверждения создания доступа: UI выдаёт context-only подключение на1день → Codex CLI с process-local `-c` overrides и токеном через `bearer_token_env_var` → один context запрос → refresh списка показывает seen → revoke → повтор должен отказать. Глобальный config не менять, токен не помещать в prompt/argv/отчёт. Local `codex exec --help` подтверждает разовые `-c` overrides; [официальная MCP документация](https://learn.chatgpt.com/docs/extend/mcp?surface=cli) подтверждает bearer token из env. Пока это подготовленный сценарий, не выполненный результат.
