# Opus: корпоративные jobs и порядок первого пилота

Дата: 14 сентября 2026. Claude Code Opus прочитал актуальные планы и UI в режиме только чтения; код не менял.

## Вердикт

Направление «агент → своя копия → ссылка» правильное, но порядок всё ещё начинался с хранилища. M1 и M1.2 следует свести в один узкий срез, где первым техническим риском является безопасный viewer для HTML/ZIP-артефактов. Папки, корзина, поиск на 10 000 работ и сложные приглашения не должны опережать эту ценность.

«Вставить ссылку» нельзя считать доказанным главным входом: многие артефакты собираются JavaScript, а Team/Enterprise-ссылки закрыты. Основное обещание должно быть про результат — «работа агента превращается в ссылку, которую откроет коллега» — с двумя входами: ссылка и файл. MCP/API capture нужен раньше сложного runner и надёжнее импорта внешней ссылки. В корпоративном контуре ссылка, вероятно, будет только распознаванием с инструкцией скачать файл.

## Jobs (экспертные гипотезы силы 1–5)

| Job | Роль | Сила | Место |
|---|---|---:|---|
| Отдать результат агента человеку без доступа к агенту, VPN или workspace | Сотрудник → получатель | 5 | Ядро первого среза; вход через ссылку и файл |
| Сохранить результат, не выходя из чата агента | Сотрудник + агент | 3→4 при повторе | Первый срез: API и MCP capture |
| Довести артефакт до решения с коллегами | Автор + reviewer | 4 для компаний | Корпоративный срез, без зависимости от редактора |
| Пользоваться агентами без выхода закрытых данных наружу | Security + IT | 5 как допуск | Узкий корпоративный профиль |
| Исправить работу по замечаниям агента | Автор + агент | 3 | Тонкий слой после ручного review |
| Сохранить работу после ухода сотрудника | Admin | 3 как допуск | Corporate ownership/offboarding |
| Найти прошлые работы команды | Сотрудник | 2 | После пилота, иначе это снова диск |

## Минимальный корпоративный vertical slice

1. IT поднимает Docker Compose с приложением, Postgres, S3/MinIO, OIDC и отдельным доменом артефактов; внешний трафик закрыт по умолчанию.
2. Admin создаёт workspace и регистрирует один разрешённый agent adapter с capability `capture` и чтением замечаний. Публикация, share и approval агенту запрещены.
3. Сотрудник один раз связывает агента через SSO и экран согласия, затем говорит «положи на Полку» и получает private receipt v1.
4. Сотрудник включает доступ «Участники пространства» и отправляет внутреннюю ссылку reviewer.
5. Reviewer оставляет минимальное замечание к работе целиком или месту/странице. Автор или агент создаёт v2, связанную с v1.
6. Reviewer сравнивает v1/v2, сам закрывает замечания и отмечает v2 принятой. Автор явно обновляет ссылку.
7. Admin отключает сотрудника; сессии и токен агента отозваны, работа остаётся организации и передаётся продолжателю. Журнал хранит actor, delegation, operation, revision, review и результат.

Нужны экраны: статус установки, участники, подключения агентов, согласие, «От агента», работа с происхождением и версиями, share, режим review, сравнение v1/v2, offboarding/передача, журнал. Не нужны в этом срезе: Brand Library, SCIM, DLP, Publisher, сложное наследование прав папок, публичная витрина, встроенный чат и real-time co-editing.

## Изменения в этапах

- **M1 + M1.2:** объединить в «Принести и отправить»: P08 viewer, file upload, API/MCP capture, private/unlisted share, update pointer, revoke и список «От агента». Ссылочный import оставить экспериментом до проверки реальных провайдеров.
- **M3a:** человеческое review immutable revision: comment/open-resolved, ответ, candidate v2, diff. Редактор и runner не требуются.
- **M3b:** агент читает разрешённые замечания и сохраняет v2 тем же capture API.
- **M4:** узкий профиль SSO/ACL/egress/offboarding/audit и один внутренний agent adapter. Не включать туда P15/P16, Publisher и SCIM.

## Go/no-go

1. Корпус из 30–50 реальных HTML/ZIP от нескольких агентов: содержание открывается на desktop/mobile без неожиданного внешнего доступа.
2. 20–30 реальных публичных ссылок: измерить, какая доля импортируется без JS. При низкой доле главным путём остаются файл и MCP, ссылка — распознавание с fallback.
3. Walkthrough с IT, Security и одной командой: установка, SSO, agent capture, внутреннее review и offboarding проходят без обязательной DLP/SCIM программы.

UX-приёмка: человек за 10 секунд называет входы «ссылка, файл, агент»; от входа до отправленной ссылки не больше пяти шагов, включая явное включение доступа; замечание ставится за три действия и всегда показывает revision; автор отличает появление v2 от публикации v2; admin объясняет capabilities агента.

## Несогласие Opus

Opus не согласился делать ссылочный импорт главным входом до эксперимента: это самый хрупкий путь и почти бесполезный в закрытом корпоративном контуре. Рекомендация — принимать ссылку и файл в одном первом действии, а ставку делать на результат, API и MCP capture.
