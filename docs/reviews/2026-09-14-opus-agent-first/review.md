# Opus: agent-first интерфейсный срез

Дата: 14 сентября 2026. Ревью выполнено Claude Code Opus в режиме чтения; код и документы не изменялись агентом.

## Вердикт

Текущий продуктовый интерфейс всё ещё воспринимается как файловое хранилище: главным действием остаётся «Добавить работу», а витрина показывает идеи, но не решает конкретную боль. В документах позиционирование уже исправлено, однако порядок реализации и первый экран не показывали этот вход.

### Боли для первого прототипа

| Боль | Сила (экспертная гипотеза) | Роль |
|---|---:|---|
| Получатель не может открыть артефакт Claude/GPT из-за VPN, логина или рабочего пространства | 4–5 | Основной вход: сохранить самостоятельную копию и открыть её обычной ссылкой |
| Автору не хочется скачивать и загружать вручную | 3 на первом касании, 4 при повторной работе | Удержание: «Положи на Полку» через MCP и receipt |
| Нужен контроль версии и аудитории ссылки | 3 | Обязательное качество в связке с первой болью, не отдельный крючок |

Витрина, лайки, папки и чат — каналы знакомства или table stakes, а не доказанная первичная боль. Уникальность появляется только в связке «артефакт агента → самодостаточный снимок → ссылка получателю без исходного сервиса» и в сохранении с provenance через MCP.

## Рекомендованный UX-срез

Добавлен интерфейсный маршрут `/bring`:

1. Один вход «Вставить ссылку» или «Загрузить файл».
2. Безопасная проверка с демонстрационными ветками: публичный источник, сборка на JavaScript, закрытая ссылка.
3. Preview с источником, названием и пояснением «после сохранения видите только вы».
4. Снимок с датой, версией и owner-only ссылкой.
5. Экран получателя без исходного сервиса и логина.
6. Отдельная карточка receipt для команды агенту «Положи этот отчёт на Полку».

Это пока UX-прототип: серверный `import.preview/commit` и MCP `artifact.capture` не подключены. В интерфейсе это написано явно, чтобы макет не выдавался за готовый импорт.

## Что отложено

Дерево папок, корзина, лайки/закладки, приглашения, внешний proxy-link, встроенный чат, редактор, PPTX и полноценная витрина не должны блокировать тест первой боли. После живого теста с реальными ссылками нужно проверить: процент успешного забора публичных страниц, точность snapshot/hash через MCP и открываемость собственного домена в российских сетях.

## UX-критерии

- человек за 10 секунд понимает, что принимает ссылку или файл работы агента;
- от вставки до готовой ссылки не больше пяти шагов;
- при JS-only или private ссылке сам находит fallback и не считает систему сломанной;
- правильно отвечает, нужен ли получателю VPN и что увидит получатель после изменения источника;
- receipt ясно говорит «сохранено приватно», а не «опубликовано»;
- получатель на телефоне видит содержимое и дату копии без входа.

Полный текст задания Opus сохранён в `prompt.txt`; результат зафиксирован здесь в виде решений, использованных для прототипа.
