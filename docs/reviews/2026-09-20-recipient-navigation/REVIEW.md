# Получатель: смена ссылки и мобильный просмотр

20.09.2026. Luna исправила Recipient.tsx, ведущий проверил исходник и браузер.

Причина: resolve вызывался только при mount, тогда как жалоба читала актуальный location.hash. При переходе между /s#token экран и действие могли относиться к разным материалам.

Теперь hashchange запускает новый resolve, generation guard отбрасывает устаревший ответ; keyed экран сбрасывает preview/grant/жалобу. Жалоба использует token своего экрана. TypeScript и build прошли.

## Реальная проверка в локальном браузере

- Планировщик → открыть жалобу → ввести тестовый текст, не отправлять → перейти только новым hash к графику. Заголовок стал chart, диалог исчез.
- Перейти на заведомо ошибочный hash: показан отказ без прежнего артефакта. Вернуться новым hash: заголовок planner восстановился без reload.
- На viewport 390×844 document clientWidth=scrollWidth=390. После обновления истёкшего grant live-планировщик запущен; checkbox изменил status 0/1 → 1/1. Это проверка одного материала, не всего мобильного корпуса; подпись и счётчик в тестовом fixture расположены тесно.
- Самостоятельный статичный report показал заголовок, текст и таблицу План 10 / Факт 7. Вместе с calculator/chart/slides/planner проверен представитель каждого из пяти типов; не весь корпус и не hosted runtime.
- Viewport восстановлен. Жалоба не отправлялась; гонка ответов искусственно не задерживалась — её защита проверена чтением кода.
