## CopyText: отказ и устаревший результат

Dev-каталог использует тот же компонент с подставленным writer. При rejected Promise браузером проверено: details открыт, textarea в фокусе, selectionStart0/selectionEnd64 при длине64, кнопка остаётся «Скопировать». Это имитация отказа API, не изменение настоящих browser permissions.

Добавлена защита от устаревших результатов: статус привязан к тексту и номеру попытки, незавершённая запись отображает busy, результат после unmount игнорируется. Проверен управляемый Promise: старт v1 → изменение на v2 → завершение v1; v2 не получает сообщение «Скопировано». Оба примера доступны только в dev-каталоге, production использует navigator.clipboard.writeText.
