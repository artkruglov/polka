## Три независимых пакета реализации

1. **Числа и сравнения: №1–4.** Отдельные файлы в `content/editorial/{team-report,travel-budget,mortgage,home-energy}/`; сохранить исходный team-report fixture нетронутым. Проверки расчётов и согласованности таблиц/итогов — часть готовности. Никаких актуальных рыночных тарифов без источника.
2. **Обучение и исследовательский шаблон: №6–9.** Отдельные `school-day`, `fractions`, `city-observation`, `hypothesis-board`. Проверять полноту урока/слайдов, правильные/ошибочные ответы и честное отделение вымышленных карточек от исследования. Независим от первого пакета.
3. **Личные сценарии и творческий прототип: №5,10–12.** `week-priorities`, `bakery-menu`, `habit-week`, `weekend-route`; отдельные поведенческие задачи, не четыре варианта одного React Planner. Независим от остальных.

Каждый пакет сдаёт original HTML или manifest+локальные файлы, собственную source/license запись, notices, задачу/ключевое действие/ожидаемый результат и mobile390/desktop evidence через настоящий capture→accepted runtime→recipient. Captured revision/hash фиксируются отдельно от описания. Лицензия кода и происхождение текстов/данных указываются явно; публикационные даты берутся из реального действия. Persistent data/remote API не добавлять ради эффекта: текущий профиль этого не обещает.

Ведущий объединяет metadata и решает включение конкретных готовых версий в каталог отдельным шагом; исполнители этих пакетов не меняют общий discover/runtime и не публикуют сами. Критерий12–20 beta — число законченных полезных оригиналов после этой приёмки, без demo likes, фиктивных отзывов, авторских профилей и статистики использования. Этот аудит не подтверждает внешние права или hosted runtime и не объявляет коллекцию опубликованной.
