# Доступ к работе, ссылки и поисковики

Редакция 13 сентября 2026. Это целевое поведение Полки, не уже реализованная защита. Связано с F03/F07/F10/F12/F18/F21/F22 и P03/P07/P08/P18/P21/P22. Исходный вопрос владельца: кому доступна ссылка, можно ли её передать другому и будет ли она проиндексирована.

## Продуктовое решение

Новая работа доступна **только владельцу**. Для распространения человек отдельно выбирает аудиторию. Сохранение, получение адреса работы и публикация не являются одним действием. Передача ссылки сама по себе не добавляет человека в список приглашённых или сотрудников компании.

| Режим в интерфейсе | Кто откроет | Если ссылку переслали | Внешние поисковики | Этап |
|---|---|---|---|---|
| Только я | Авторизованный владелец | Другой человек не увидит содержимое | Содержимое закрыто авторизацией; дополнительный noindex | M1, умолчание |
| Приглашённые | Явно добавленные подтверждённые пользователи | Другому нужен собственный доступ; ссылка приглашения не является вечным bearer-доступом | Содержимое закрыто; noindex | Отдельный законченный срез M1 до обещания закрытого обмена |
| По ссылке | Любой, у кого есть действующая ссылка | Получатель сможет переслать её дальше | Запрашиваем исключение из поиска, не публикуем в каталоге/sitemap; это не секретность | M1 |
| В компании | Разрешённые сотрудники после входа через выбранную организацию | Внешний человек не получает доступа от ссылки или совпадения email-домена | Нет внешнего содержимого для робота; внутренний поиск только по ACL | M4 |
| Публично | Любой посетитель | Может свободно распространяться | Индексация разрешена после отдельного согласия; попадание/позиция не гарантируются | M5, отдельный допуск |

M1 можно пригласить первых пользователей на уже принятые «Только я / По ссылке». Пока authenticated sharing не реализован и не проверен, режим «Приглашённые» не выдаётся за доступную возможность. Для конфиденциального обмена этот срез обязателен. Папки M1 организуют работы; перенос в папку не меняет аудиторию. Наследование корпоративных folder ACL появляется с отдельной приёмкой M4.

## Что означает «не показывать в поиске»

`noindex` — правило для поддерживающих его поисковиков, **не проверка права доступа**. Google описывает его как meta tag или HTTP header; для прочтения правила робот должен получить ответ страницы. Один `Disallow` в robots.txt не заменяет noindex: робот может знать URL по чужим ссылкам. [Google: noindex](https://developers.google.com/search/docs/crawling-indexing/block-indexing).

Яндекс также поддерживает robots meta и `X-Robots-Tag` с noindex. Реализация проверяется на внешнем ответе сервиса, включая ресурсы, а не только по тегу, написанному автором HTML. [Яндекс: метатеги](https://yandex.ru/support/webmaster/ru/controlling-robot/metatags).

Закрытое содержимое защищается серверной авторизацией. Не открываем private страницу роботу ради демонстрации noindex. Google отдельно различает доступ по ссылке с noindex и защиту конфиденциальных материалов входом. [Google: управление доступностью содержимого](https://developers.google.com/search/docs/crawling-indexing/control-what-you-share).

Полка не обещает, что неизвестный бот выполнит правило, что уже опубликованная копия исчезнет из интернета или что исключение из выдачи произойдёт мгновенно. Для пользователя точная подпись: **«Мы просим поисковики не показывать работу. Любой получивший ссылку сможет её открыть».** Для секретного материала нужен режим с проверкой личности.

## Четыре независимых настройки

1. **Аудитория:** владелец / приглашённые / по ссылке / компания / публично.
2. **Обнаружение:** скрыта из каталогов либо явно опубликована в библиотеке/разрешена для индексации. В M1 это фиксировано: все работы excluded; лендинг продукта может индексироваться.
3. **Версия:** обычная живая ссылка или закреплённый снимок. Сохранение новой версии не переключает читателей автоматически.
4. **Разрешённые действия:** просмотр, комментарий, копирование исходника в свою полку, скачивание. Выключенная кнопка скачивания не является DRM и не запрещает снимок экрана/сохранение уже доставленных байтов.

UI показывает сначала аудиторию и адрес. Срок/версия/copy/download находятся в «Настроить ссылку». Индексация не прячется в этом списке маленьким checkbox рядом с обычным share: в M5 это отдельное действие «Опубликовать для всех» с просмотром ровно того, что получат люди и поисковик.

Адрес для копирования появляется только после успешного включения доступа. Изменение выбора в форме не включает ссылку; отмена не меняет приглашённых. Отключённая ссылка не включается от сохранения срока или других настроек. Для повторного включения — явное действие с новым адресом. Операции проверяются и в модели, и отдельно на реальном backend.

## Живая ссылка и версии

ShareLink хранит artifact, `targetMode = published_pointer | pinned`, `publishedRevisionId` либо `pinnedRevisionId`, `shareGeneration`, audience, capabilities, expiry и revoke. Каждая Revision остаётся неизменяемой. Новая приватная версия не становится публичной от autosave.

Автор видит: **«На полке — версия 4. По ссылке — версия 3»**. «Обновить по ссылке» проверяет выбранную ревизию, права, готовность viewer и допустимость распространения; compare-and-swap защищает от конкурирующего переключения. Для официального выпуска approvals относятся к точной версии и её зависимостям.

При открытии resolver закрепляет viewer session/grant на одной revision. Если автор обновил ссылку, уже открытая страница не смешивает старый HTML и новые assets: можно показать «Доступна новая версия» и предложить перезагрузку. Старые private revisions, prompts, комментарии и sources не становятся доступными через перебор ID. По ссылке отдаётся читательский bundle, прошедший проверку состава.

## Отзыв, пересылка и боты мессенджеров

- Отозванная/истёкшая ссылка больше не выдаёт grants. Прежние короткие grants действуют не дольше принятого TTL; строгий gateway имеет отдельно измеренную задержку отзыва. Уже полученные байты невозможно отозвать у адресата.
- Ротация token делает прежний адрес недействительным; это отдельная команда, не простое «снять noindex». Возврат ссылки из revoked не происходит сам после восстановления backup.
- Для «Приглашённых» конкретный человек подтверждает identity. Одноразовый invite имеет срок/привязку/ограничение повторов; доступ хранится в ACL. Отзыв membership/приглашения применяется и к новым sessions/grants.
- Читатель без права получает нейтральную страницу без названия, обложки, имён коллег, пути папки или признака «здесь секретный документ». По возможности безопасно различаем «войти под другой учётной записью» и ошибку для самого владельца.
- Для private/invited/company мессенджер получает общую обложку Полки. Для unlisted — тоже общую по умолчанию: сервис мессенджера, читающий ссылку, является ещё одним получателем. «Показывать обложку в мессенджерах» — явная дополнительная настройка; её выключение не удалит старый кеш мессенджера.
- Для public используются отдельные очищенные заголовок/описание/постер. Авторский JS не выполняется ради OG preview; preview worker и домен доставки имеют отдельные ограничения.

## Технические обязательства

| Поверхность | Требование |
|---|---|
| App/API/download/runtime/assets | Авторизация на каждом пути; bucket закрыт. Непрозрачный ID не заменяет ACL. Нельзя открыть оригинал обходом viewer |
| Ссылка и grants | Не менее 128 бит случайности, digest token в БД; непрогнозируемый адрес отдельно от временного разрешения доставки; ограничение перебора |
| Ответы неиндексируемых режимов | Серверный `X-Robots-Tag: noindex, nofollow` для shell/HTML/PDF/обложок/скачиваемого содержимого и redirects там, где применимо; app не доверяет meta/canonical/sitemap из авторского архива |
| Закрытые ответы | Нейтральный deny; private/no-store для закрытых оболочек и чувствительных ответов. Авторизация проверяется и на cache hit; public cache не содержит private title/source |
| URL и наблюдение | Token/grant не попадают в analytics, referrer, trace, crash report и access logs; у читательского shell `Referrer-Policy: no-referrer`; без сторонних трекеров/виджетов по умолчанию |
| Маршруты HTML bundle | Решить на spike: origin/path/cookie/grant, относительные пути и storage isolation. Все файлы одного просмотра закреплены на revision; пользовательский код не видит app session/cross-artifact данные |
| Каталог и sitemap | Только явно public записи с действующим разрешением. Unlisted/private IDs не перечисляются. SEO-разрешение не создаётся импортом HTML, действием агента или переносом папки |
| Возврат public → private | Сначала закрыть доступ и выдачу grants, убрать каталог/sitemap/публичный кеш; затем операции удаления из поиска. Известность адреса не равна текущему доступу |

Доступ к работе и сетевые возможности кода внутри неё — разные границы. Ни ссылка с логином, ни noindex не решают открытый вопрос исполнения недоверенного HTML из обсуждения Opus. Пока профиль не принят, не выдавать произвольному JS данные/секреты и не обещать отсутствие исходящей сети.
