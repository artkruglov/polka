## Решение по архитектуре

Используем подход, близкий к Feature-Sliced Design, без обязательного копирования всех его соглашений. Дорабатываем текущий продукт: модель артефактов, immutable revisions, scopes, storage и изолированный viewer полезны и сохраняются.

| Слой | Ответственность |
|---|---|
| app | маршруты, провайдеры, подключение стилей, композиция оболочки |
| pages | сборка конкретного экрана без собственной версии глобального меню |
| widgets | Navigation/AppShell, ArtifactGrid, ViewerFrame |
| features | capture-url, capture-file, share-artifact, connect-agent, manage-folder |
| entities | account, artifact, folder, agent-connection: модели и отображение |
| shared | UI-примитивы, API transport, типы общего назначения, токены, утилиты |

Зависимости идут вниз. Соседние features/entities не импортируют друг друга напрямую: их соединяет page/widget. Общие контракты сервера остаются в packages/contracts. Корневые re-export мосты удалены после перевода маршрутов и тестов. Новые модули вне слоёв запрещены, кроме mount/dev entry и Vite declarations. Проверка check:layers входит в npm run check. Она проверяет синтаксически обычные, динамические, type imports и re-export мигрированных модулей; вычисляемые пути и выход в серверный код запрещены. Внешние относительные зависимости разрешены только для общих contracts/editorial. Оставшиеся общие CSS требуют отдельной миграции; проверка импортов не подтверждает визуальную приёмку.

### 2. Проверка возможности URL-импорта — следующий продуктовый приоритет

- Собрать воспроизводимый корпус: публичный Claude artifact, ChatGPT artifact/shared conversation, автономная HTML-страница, страница с локальными assets, закрытая/удалённая ссылка, страница с внешним API.
- Для каждого источника проверить фактическое получение содержимого без cookies и чужого аккаунта. Страница чата не равна артефакту; HTML-обёртка без контента не считается успехом.
- Зафиксировать матрицу supported / partial / unsupported с доказательствами, а не по расширению URL.
- Проверять из будущего облачного окружения отдельно от локального Mac. «Без VPN для получателя» требует сохранения необходимых зависимостей на стороне Полки и проверки сетевого доступа к хостингу.

Приёмка: хотя бы один реальный приоритетный artifact-source скопирован с работающим интерактивом либо документирована конкретная техническая преграда. Не обещать универсальный импорт GPT/Claude до этого теста.

### 3. Единый сервис импорта URL для UI и MCP

- Общий контракт create/status/cancel: idempotency key, source URL, destination folder, import job ID, structured result.
- Асинхронный worker: validate → fetch → extract → localize dependencies → existing bundle validation/storage → preview → receipt.
- Состояния queued/fetching/processing/ready/partial/unsupported/failed/cancelled. Повтор не создаёт дубликаты; пользователь может вернуться к операции после закрытия страницы.
- SSRF: публичные HTTPS адреса, проверка DNS/IP при соединении и на каждом redirect, запрет private/link-local/metadata, ограничения размера/времени/redirects/числа assets. Без пересылки cookies/credentials.
- Политика исполнения: извлечение не запускает недоверенный код в основном процессе. Интерактивность только через существующий изолированный viewer. Внешние API и удалённые assets выявляются и отражаются в результате.
- Сохранённая копия по умолчанию приватна. Source URL/время/режим копирования в provenance, секретные параметры URL не пишутся в журналы.
- UI capture-url и MCP polka_import_url вызывают один service. capabilities=true только после включения рабочего importer; status/recovery и права проверяются одинаково.
- Закладку можно предложить отдельно, но не выдавать за сохранённый артефакт. При невозможности импорта дать конкретную причину и альтернативу file/MCP capture.

Приёмка: вставить URL → дождаться receipt → открыть без исходного сервиса; то же через MCP. Проверки редиректов/private IP, таймаутов, повторов, revoked scope, tenant isolation и missing dependencies.

### 4. Сквозной UX

Сценарии: первый вход; сохранить ссылку; агент сохраняет ссылку; ошибка/повтор; открыть и запустить интерактив; найти в папке; поделиться/отозвать; получатель без аккаунта; мобильное открытие. Для каждого нужны понятные loading/empty/error/permission states. Скриншоты фиксируют одинаковое меню, шрифт и контролы. Публичная витрина и приватная полка не смешиваются, демонстрации подписаны.

### 5. Облачная beta — отдельная приёмка

Домен/HTTPS, основной и viewer origins, выбранный hosting/storage region, email delivery, фоновые jobs, backup/restore, квоты/rate limits, наблюдаемость, второй MCP-клиент, 10–20 пилотных авторов. Сохраняются требования LAUNCH/SELF_HOST_BASE_SPEC. Никаких заявлений о размещении в России до реального развёртывания.

## Что не входит в эту цель

Переписывание всего backend, встроенный агентный чат, универсальный браузерный конвертер любого сайта, обход авторизации источника, новая соцсеть. Они не должны отодвигать работающий перенос артефакта и целостный UX.

### Подготовка HTML-пакета

Query/fragment не попадают в provenance. Нет записи в БД или публикации на этом шаге. Нет выполнения исходного JS. Провайдерские страницы не выдаются за автономный HTML.

Проверено: CSS и изображения локализуются и дедуплицируются, manifest проходит существующий validateAgentCapture; простой интерактивный HTML проходит bundle builder; missing asset даёт ошибку, iframe не даёт previewReady. ### CSS-ресурсы в сборке v3

bundle-inline-v3 разрешает только проверенные локальные CSS url() изображения и WOFF2: превращает их в data URI, применяет существующую проверку inert SVG, лимит расширения, MIME и проверку заголовка WOFF2. CSS в style-атрибутах также переписывается. Внешние URL, traversal, data URI на входе, отсутствующие файлы и unsafe SVG отклоняются. CSP viewer не расширена: сетевые запросы не разрешены. Версия builder теперь берётся из единого runtime-contract.

Тест HTML capture с CSS background прошёл previewReady; 203 теста и TypeScript проходят. Это проверка сборки, не приёмка живого облачного просмотра. CSS @import/srcset/module dependency graph остаются отдельными открытыми пунктами. Серверный процесс не перезапускался для этого изменения; новый builder вступит в работу после контролируемого обновления сервера.

### Постоянная очередь импорта: фундамент

Добавлена миграция 019_url_import_jobs и транзакционные операции create/get/cancel/claim/requireLease. Задание связано с tenant/account/connection и ключом идемпотентности. Повтор с другим запросом или подключением отклоняется. Права capture и активность владельца проверяются при пользовательских операциях. В публичном DTO нет исходного URL, подготовленных байтов и lease token. На владельца допускается до пяти незавершённых действующих заданий.

Проверено в отдельной транзакционной PostgreSQL-схеме с откатом DDL: дедупликация, owner isolation, отмена, возврат задания после просроченной lease и отклонение старого токена. Реальная схема пока не мигрировалась. Worker, восстановление из prepared snapshot, завершение/очистка исчерпанных заданий, gateway и UI/MCP ещё не подключены. Требование: перед fetch и каждым сохранением worker проверяет авторизацию; каждый переход/commit проверяет lease, чтобы отменённый или прежний исполнитель не завершил job.

### Автоматический просмотр и MCP transport — следующий проверенный шаг

Очередь теперь фиксирует `previewing` и receipt атомарно при сохранении. Следующий worker строит preview из сохранённой revision; после падения процесса повторяется именно сборка, а не скачивание источника. Только завершённая сборка даёт `ready`. Неподдерживаемый/выключенный просмотр, ошибка или исчерпанные попытки после сохранения дают `partial` с сохранённым receipt. Отмена после receipt возвращает актуальное состояние и не удаляет материал. В ещё не развёрнутую миграцию019 добавлено состояние previewing; рабочая схема по-прежнему не менялась.

Изолированный runtime-набор расширен до четырёх проверок: реальное сохранение и восстановление сборки без источника; авторизация/идемпотентность/отмена HTTP; сохранение receipt при исчерпании квоты preview; настоящий Streamable HTTP MCP. MCP проверен на capture scope, отсутствие import tool при read-only scope, создание→сохранение→ready, изоляцию между подключениями одного владельца, безопасную отмену завершённого задания. Источник в этих тестах детерминированный fixture; DB/S3, builder и MCP transport настоящие.

Отдельный сетевой эксперимент: `https://mdn.github.io/learning-area/javascript/introduction-to-js-1/what-is-js/javascript-label.html` получен public-fetch/captureHtmlUrl без cookie/proxy; результат title=JavaScript label example, 1 файл, previewReady=true, warnings=[]. Это проверка получения и преобразования реальной standalone HTML-страницы; браузерный клик и перенос Claude/ChatGPT этим не доказаны.

Следующий шаг: отдельная браузерная установка с включённым импортом, desktop/mobile сценарий сохранения и интерактивного просмотра. Затем визуальная приёмка компонентов/маршрутов. Облачная эксплуатационная приёмка остаётся отдельной.
