# Стенд: агент под ограничениями

Показывает службе ИБ, что агент работает в отдельной машине под песочницей, ходит в Полку со своим узким токеном задачи, не выходит за свои права на сервере, даже если взял токен в bash, и отключается за измеренное время. Это лаборатория для показа, а не установка у заказчика. Ноутбук здесь — только место, где поднята ВМ. Окружение вокруг агента целиком — доступ, шлюз моделей, секреты, сеть, журнал — показывает [стенд «Контур»](../contour-stand/README.md).

```
Mac: Полка (127.0.0.1:4390) ── ssh -R ──► ВМ Ubuntu 24.04 (Lima, без папок Mac)
                                           └─ пользователь agent, без sudo
                                              └─ env -i … srt (песочница: чтение, запись, сеть)
                                                 └─ Codex ──MCP──► Полка, токен задачи 15 мин
```

## Что нужно

- macOS с [Lima](https://lima-vm.io) (`brew install lima`), около 10 ГБ на диске.
- Полка этого репозитория, запущенная локально с полками отделов и сервисными доступами: `TEAM_SHELVES=on SERVICE_ACCOUNTS=on npm run dev` (`APP_ORIGIN=http://127.0.0.1:4390`).
- Аккаунт администратора компании на этой Полке: `npm run admin -- company admin <логин>`. Файл с его входом — JSON `{"name","password"}` вне репозитория, например `.local/local-account.json`.
- Вход в Codex (ChatGPT), который владелец стенда делает сам.

## Запуск

```bash
deploy/agent-stand/stand.sh up          # ВМ, Node, Codex, sandbox-runtime, пользователь agent, приманки
deploy/agent-stand/stand.sh tunnel &    # Полка внутри ВМ по тому же адресу
deploy/agent-stand/stand.sh login       # вход в Codex от имени agent (код подтверждается в браузере)
node deploy/agent-stand/seed.mjs --account .local/local-account.json
deploy/agent-stand/demo.sh --account .local/local-account.json
```

`seed.mjs` создаёт полки «Аналитика (демо)» и «Финансы (демо)», двух ботов на «Аналитике» — `report-bot` (`capture`, `revise`) и `reader-bot` (`read`, `source:read`) — и синтетическую работу на «Финансах». Длинные токены ботов лежат в `.local/agent-stand/tokens.json` (права 600) и в ВМ не попадают. Туда уходит только токен задачи (`run-task.sh`).

## Что лежит в папке

| Файл | Что делает |
|---|---|
| `lima.yaml` | ВМ: Ubuntu 24.04, `mounts: []`, без ssh-agent и контейнеров, порты ВМ на Mac не пробрасываются |
| `provision.sh` | Node 22, Codex 0.162.1, sandbox-runtime 0.0.79, профиль AppArmor для bubblewrap, пользователь `agent`, приманки, `/etc/agent-stand/srt.json` |
| `stand.sh` | `up`, `tunnel`, `login`, `down` |
| `seed.mjs` | Полки, боты, синтетические данные |
| `run-task.sh` | Одна задача: токен задачи → `env -i … srt … codex exec`; журнал запуска в `.local/agent-stand/runs/` |
| `bypass.sh` | Агент в bash с токеном пробует чужую полку, запись без права, ссылку без права, новый токен, веб-API |
| `journal.mjs` | Журнал агентов полки (`GET /api/shelves/:id/agent-audit`) и приёмка версии |
| `revoke.mjs` | Время от отключения сервисного доступа до первого отказа того же разрешённого чтения |
| `demo.sh` | Весь показ по шагам |

## Песочница

Одна граница — `srt` (sandbox-runtime, bubblewrap). Codex внутри запускается с `--dangerously-bypass-approvals-and-sandbox`: его собственная песочница не нужна, а вложенный bubblewrap ненадёжен. Если `srt` не запустился, ничего не запускается — без запасного варианта «без защиты».

Настройки (`/etc/agent-stand/srt.json`):

- **Чтение** закрыто для `/home`, `/root`, `/etc/agent-stand/secrets`, `/opt/agent-stand/canary`.
- **Запись** — только `/work`, `/opt/agent-stand/codex` (вход Codex) и `/tmp`.
- **Сеть** — только `127.0.0.1:4390` (Полка) и `chatgpt.com`, `auth.openai.com` (модель). Запросы идут через прокси `srt`; `NO_PROXY` очищается, иначе запрос к 127.0.0.1 уходит мимо прокси в пустую сеть песочницы.
- **Окружение:** `env -i` — внутрь доходят только `PATH`, `HOME`, `LANG`, `CODEX_HOME` и токен задачи.

Ubuntu 24.04 запрещает непривилегированные пространства имён (`apparmor_restrict_unprivileged_userns=1`), поэтому `provision.sh` ставит профиль AppArmor, который разрешает их только `/usr/bin/bwrap`.

Проверка: `scripts/polka-sandbox-check.mjs` ([AGENT_SANDBOX](../../docs/specs/AGENT_SANDBOX.md)), шаг 8 показа.

## Что показано и что нет

Показано:

- Токен задачи у агента виден (`env`), но сервер не пускает его на чужую полку (ни по id, ни заголовком полки), не даёт писать без права, выдавать ссылку без права, выпускать новый токен и ходить в веб-API.
- На сервере видно, какой сервисный доступ по какой задаче сохранил и прочитал версию, и кто за него отвечает.
- Писатель работает без права читать полку: `report-bot` делает вторую версию из своей страницы и номера версии, которые приходят с задачей (как их передал бы конвейер), — сервер принимает `polka_revise`, а читать работы на полке он по-прежнему не может.
- Другой агент берёт принятую версию, а не последнюю.
- Отключение сервисного доступа: на 16.10.2026 первое чтение после отключения отказано через 17 мс (шаг опроса 200 мс).

Не показано и важно назвать:

- Права сервисного доступа не шире прав ответственного человека: это не полностью независимая учётка. Потолок прав от администратора полки — задача #159.
- Вход в Codex лежит в `/opt/agent-stand/codex` и доступен процессам агента: это исключение демо. У заказчика ключ модели подставляет шлюз.
- Модель на стенде — ChatGPT. Замена на Yandex AI Studio или vLLM — отдельная проверка протокола (Responses API, потоковая выдача, вызовы инструментов), а не одна строка настроек.
- Разрешённые адреса (модель, Полка) остаются каналом передачи данных: всё, что агент прочитал, он может отправить туда.
- Уже прочитанное агентом до отзыва остаётся у него.
