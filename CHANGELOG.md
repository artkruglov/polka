# Changelog

Все заметные изменения Полки. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/). До `1.0.0` API, схема БД и интерфейс могут меняться между prerelease-версиями.

## [Unreleased]

### Added

- **Ссылка на исходный код.** Главная говорит, что Полка — открытый код (AGPL-3.0), и ведёт на GitHub; ссылка «Открытый код на GitHub» есть в подвале каждой страницы и в подробностях у получателя.
- **Страница «Для компаний»** (`/pricing`): облако polochka.app (бесплатно на время пилота), своя установка (бесплатно по AGPL-3.0) и коммерческая лицензия с кнопкой «Написать». Ссылки — в подвале и в блоке для компаний на главной.
- **Комментарии и реакции на тексте работы** (этап 3 [COMMENTS](docs/specs/COMMENTS.md); миграция 030).
  - **Обсуждение принадлежит ссылке.** Получатель выделяет фрагмент и пишет замечание или ставит реакцию (👍 👎 🎉 🤔 ❤️ 👀 ✅, повторное нажатие снимает); ответы в один уровень, «Решено», «Удалить». Читать может любой, у кого открыта ссылка, писать — только вошедший; вход возвращает на ту же ссылку, токен не попадает в `?next=`. Получатели одной ссылки не видят обсуждение другой; отзыв, истечение и проверка модератором закрывают обсуждение для получателей, у владельца оно остаётся. Владелец видит обсуждения всех ссылок работы на её странице, с числом новых.
  - **Привязка к тексту** — цитата `{exact, prefix, suffix}`; в новой версии она ищется заново (точно, затем без учёта пробелов, среди повторов — по контексту), не найденная или неоднозначная становится комментарием ко всей работе с пометкой «к прежней версии».
  - **Оверлей в просмотрщике** добавляется только к гранту, выданному оболочкой с `{comments: true}`; скачивания и прочие просмотры остаются побайтно исходными. В интерактивном просмотре он идёт после защиты от WebRTC; в статичном — `sandbox allow-scripts` и CSP `script-src 'nonce-…'` со случайным nonce на ответ, поэтому скрипты, обработчики и `javascript:` самой страницы по-прежнему не выполняются, а сеть закрыта и для оверлея. Подсветка — CSS Custom Highlight API, DOM страницы не меняется. Сообщения принимаются только от `parent` с `APP_ORIGIN`. Проверено в настоящем Chrome (`tests/comment-overlay-dom.test.ts`).
  - **Интерфейс:** лента справа от документа с карточками на высоте фрагментов, на телефоне — выезжающая панель; плавающая кнопка «Комментировать» и реакции у выделения; счётчик 💬 в верхней полосе. Текст комментариев — только текст, адреса не кликабельны; автор показан выбранным им именем (его просят выбрать перед первым комментарием), не почтой.
  - **Письма:** владельцу о каждом новом комментарии, участникам ветки — об ответах, пока ссылка открыта; не больше 30 в сутки на адрес в своём счётчике (вход не страдает), до 300 символов, адреса в тексте обезврежены (`example[.]com`), чужих почт нет; отключаются подписанной ссылкой `/mail-off#…` или в панели.
  - **Агентам:** `polka_comments` (`read`), `polka_resolve_comment` (`revise`), `polka_revise` с `edits: [{oldText, newText}]` (точное совпадение, затем нормализованное — NFKC, кавычки, тире, пробелы в конце строк; меняются только найденные места; 422 с номером правки, 409 с `currentRevisionId`), `polka_share` с `moveShareId` — перенести ссылку и её обсуждение на новую версию. HTTP: `POST /api/v1/works/:id/edits` (с `moveLink`). Цикл описан в `/llms.txt`, скилле и [connect-agents](docs/connect-agents.md).
  - **Модерация:** признаки фишинга в комментариях (как у страниц, плюс адреса); подозрительный комментарий нового автора виден только автору и владельцу, пока оператор не решит, оператор получает письмо. Жалоба на комментарий (не ставит ссылку на паузу). Скрипты `moderation:comments`, `moderation:delete-comment`, `moderation:release-comment`; `disable` и запрос удаления аккаунта скрывают комментарии и реакции автора, окончательное удаление аккаунта стирает их. Лимиты: 2000 символов, 200 комментариев на ссылку в сутки, 60 комментариев и реакций автора в час.

- **Иконка Полки во вкладке браузера и при установке.** `favicon.ico`/`favicon.svg`, иконки для iPhone и Android (в том числе maskable) и `manifest.webmanifest`: Полку можно установить как приложение или добавить на главный экран. PNG и ICO собираются из `apps/web/icons/*.svg` скриптом `scripts/gen-icons.mjs`.
- **Сравнение версий.** Во вкладке «Версии» владелец выбирает «Было» и «Стало» и видит построчный diff исходного кода: добавленные строки зелёным, удалённые красным, неизменённые участки свёрнуты («31 строка без изменений»). Байты читаются теми же маршрутами владельца, что «Скачать оригинал» (`/api/revisions/:id/bytes`, у пакета — `/export`: сравнивается главная страница, изменённые файлы перечислены), нового серверного маршрута нет. Diff — алгоритм Майерса в `shared/lib/line-diff.ts`, без зависимостей, в Web Worker; пределы названы в интерфейсе: 50 000 строк на сторону, после 2 500 отличий — замена целиком, показ до 2 000 изменённых строк («показано не всё»). Для изображений и двоичных файлов сравнение недоступно, и это сказано.
- **Превью ссылок в мессенджерах.** Оболочка приложения получает Open Graph и Twitter-теги с абсолютными адресами из `APP_ORIGIN`. Для `/s` — общая карточка «Полка — вам отправили страницу»: токен ссылки в `#` и до сервера не доходит, поэтому название работы в превью не попадает (тест сверяет, что страница одинакова для любого запроса и не содержит названия, токена и id). Для главной и остальных страниц — карточка Полки. Картинки 1200×630 собираются из SVG в `docs/design/og/` скриптом `scripts/render-og-images.mjs` (headless Chrome).
- **Полку находит агент без подсказок** (этап 2 [COMMENTS](docs/specs/COMMENTS.md#этапы)), как у justhtml.sh. `GET /llms.txt`: что такое Полка, подключение (фраза `/connect`, одна команда для Codex и Claude Code, коннектор для Claude.ai и ChatGPT, токен для остальных; человек входит в браузере), инструменты MCP со scope — список строится из зарегистрированных инструментов и не расходится с ними, HTTP API с curl, лимиты, модерация и как показать ссылку. `GET /openapi.json` — OpenAPI 3.1 HTTP API из zod-схем маршрутов; схемы ответов тесты сверяют с настоящими ответами. `GET /.well-known/agent-skills/index.json` и скилл `polka` в `skills/polka/SKILL.md`: `npx skills add artkruglov/polka`. Все адреса — из `APP_ORIGIN`, ответы публичные, без cookies, кэш 5 минут. `/connect` ссылается на `/llms.txt`.
- **Политика обработки персональных данных и пользовательское соглашение** на `/privacy` и `/terms`, ссылки в подвале и на странице входа. Оператор — Круглов Артем Игоревич; тексты описывают, как Полка устроена по коду, и ещё не проверены юристом (это сказано на странице). Обещанные сроки выполняются на деле: жалобы удаляются обслуживанием через год, дампы базы — правилом жизненного цикла хранилища через 30 дней.

### Changed

- **Лицензия: AGPL-3.0 вместо Apache-2.0, плюс коммерческая** ([LICENSE](LICENSE), [COMMERCIAL.md](COMMERCIAL.md)). Все коммиты в репозитории сделал один автор, поэтому автор вправе сменить лицензию. Зачем: Apache-2.0 разрешает взять Полку, доработать и запустить закрытым сервисом, ничего не вернув. AGPL-3.0 требует предложить исходный код изменённой версии всем, кто пользуется ею по сети (§ 13), а кому это не подходит, может взять коммерческую лицензию. Пользоваться Полкой без изменений или дорабатывать её открыто по-прежнему можно бесплатно. **Версии до v0.1.0-rc.5 включительно и все коммиты до этого изменения остаются под Apache-2.0**: выданную лицензию нельзя отозвать. Что изменилось в коде и документах:
  - `LICENSE` — официальный текст GNU AGPL-3.0 без изменений (тест сверяет SHA-256), `package.json` — `AGPL-3.0-only`, `NOTICE` — новая лицензия и оговорка про прежние версии; `/openapi.json` называет `AGPL-3.0-only`. Лицензии production-зависимостей (MIT, ISC, Apache-2.0, BSD, BlueOak, 0BSD, MIT-0, Unlicense) с AGPL-3.0 совместимы; проверка `npm run verify` не менялась.
  - Новая настройка `SOURCE_URL` (https, по умолчанию `https://github.com/artkruglov/polka`): куда ведёт ссылка на исходный код. Её отдаёт `GET /api/capabilities` (`sourceUrl`), интерфейс берёт её вместо зашитого адреса; она же в `/llms.txt` и `/connect`. Кто запускает изменённую Полку, обязан указать здесь свой код ([deploy/hosted](deploy/hosted/README.md#исходный-код-изменённой-версии)). Подвал со ссылкой теперь есть и на страницах `/away` и `/mail-off`.
  - Pull requests принимаются по [соглашению участника](CLA.md) (на основе Apache ICLA 2.2): автор сохраняет права, мейнтейнер может распространять вклад и по коммерческой лицензии. Принять — строкой «Я принимаю CLA (CLA.md)» или галочкой в шаблоне pull request.
  - Политика и соглашение называют новую лицензию; соглашение добавляет, что для пользования сервисом лицензия на код не нужна.
- **Политика и соглашение вычитаны по российскому праву** ([docs/reviews/2026-09-23-legal](docs/reviews/2026-09-23-legal/README.md)). Политика разложена по целям: данные, основание по ст. 6 152-ФЗ и срок для каждой; добавлены получатели ссылок, отпечаток жалобщика, автоматическая проверка на фишинг, localStorage, почта оператора в Gmail и комментарии как готовящийся пункт; удаление аккаунта — доступ закрывается за 10 рабочих дней, данные удаляются за 30 дней; ответ на запрос — 10 рабочих дней с продлением на 5. Соглашение — публичная оферта с акцептом первым входом, простая лицензия с территорией и закрытым перечнем способов, порядок заявлений правообладателей, изменения с уведомлением за 10 дней, необязательный досудебный порядок и сохранённая подсудность по месту жительства. Строка под формой входа больше не «принимает» политику, а подтверждает, что её прочитали.
- **Панель интерактивного просмотра у получателя на телефоне — одна строка.** «Развернуть», «Остановить» и «Обновить доступ» становятся кнопками-значками 40×40 с `aria-label` (слова видны с 761px); поведение, фокус при разворачивании и Escape не менялись. Снимки: `docs/design/2026-09-23-history-og/`.
- Письма модерации больше не содержат почту автора, только логин аккаунта: письма идут через почтовый сервис оператора, в том числе зарубежный. Адрес по-прежнему виден оператору на сервере (`/moderation`, `scripts/moderation.ts`).

### Added

- **Защита от злоупотреблений при открытой регистрации** (`docs/specs/ABUSE_PROTECTION.md`, пункты 1–7; миграция 029).
  - **Доверие к аккаунту.** Доверенный — созданный оператором (вход по паролю), одобренный оператором или старше `NEW_ACCOUNT_DAYS` (7) без нерассмотренных жалоб; аккаунт с приостановленной ссылкой доверие теряет до решения оператора. Все аккаунты, существовавшие до миграции, отмечены доверенными.
  - **Лимиты новых аккаунтов:** ссылка не дольше 7 дней и не больше `NEW_ACCOUNT_MAX_LINKS` (5) открытых ссылок; отказ объясняет причину и что сделать. `polka_publish` и publish API выдают новому аккаунту ссылку на 7 дней вместо 30 и сообщают это в `expiresNote`.
  - **Состояние ссылки** `none` / `held` / `paused`. `SHARE_MODERATION`: `off`, `flagged` (по умолчанию: подозрительная страница недоверенного автора), `new-accounts` (любая ссылка недоверенного автора), `all` (любая ссылка аккаунта, зарегистрированного по почте). Получатель ожидающей или приостановленной ссылки видит экран «Ссылка на проверке у модератора Полки» без названия и содержимого; владелец видит работу и состояние «на проверке». Новая версия, опубликованная по одобренной ссылке недоверенного автора, снова ждёт проверки.
  - **Агентам:** `polka_publish`, `polka_share` и `POST /api/v1/publish` возвращают `moderation: "held"` и `moderationMessage`, пока ссылка ждёт; описания инструментов велят не выдавать такую ссылку за готовую. CLI печатает это в stderr.
  - **Жалобы:** каждая — письмо оператору; `MODERATION_AUTOPAUSE_REPORTS` (3) разных жалобщиков за 7 дней ставят ссылку на паузу. Жалобщики различаются по `HMAC(LINK_KEY, ip|share)`, адреса не хранятся. Ссылки «Интересного» автоматически не приостанавливаются.
  - **Письма оператору с действиями в один клик** (`OPERATOR_EMAIL`): «Посмотреть» (тот же песочный просмотр, грант на 60 секунд), «Одобрить ссылку», «Одобрить и доверять автору», «Снять паузу», «Закрыть ссылку», «Закрыть и отключить автора». Кнопка — `/moderation#<токен>`: HMAC от ключа, выведенного из `LINK_KEY` с отдельным назначением, срок 7 дней. Открытие страницы ничего не меняет, действие выполняет только POST; повтор безопасен. Отправка писем вынесена в `apps/server/mailer.ts` (вход по коду и модерация); в `MAIL_MODE=local` письма оператору пишутся в `.local/mail/operator/`.
  - **Признаки фишинга** считаются при сохранении в том же линейном проходе parse5, что и классификатор, и по строкам скриптов (включая JSX-компоненты): поля паролей, карт и кодов из SMS вместе с брендом банка или сервиса либо срочностью. Список признаков — один файл `apps/server/phishing-signals.ts`.
  - **Скрипты:** `npm run moderation:queue`, `moderation:approve -- <shareId> [--trust]`, `moderation:unpause`, `moderation:trust`.

### Changed

- **Получатель видит предупреждение над страницей, а не мелким шрифтом под ней:** «Эту страницу опубликовал пользователь Полки. Полка её не проверяла. Не вводите здесь пароли, коды из SMS и данные карт.», рядом «Пожаловаться»; у автора младше 7 дней — «Автор недавно на Полке». Имя автора не показывается. Материалы «Интересного» подписаны «Редакция Полки» без предупреждения.
- `moderation:revoke-share` отмечает жалобы на закрытую ссылку рассмотренными.

### Security

- **Глубоко вложенная страница больше не останавливает сервер.** Разбор HTML в parse5 квадратичен по глубине вложенности (200 КБ вложенных `<div>` — около 4 с, 5 МБ — около 40 мин), а обход дерева в классификаторе был рекурсивным и падал с переполнением стека. Запись rc.4 о линейном времени была верна только для «плоских» страниц. Теперь страницы больше 16 КБ классифицируются в отдельном потоке с дедлайном 2 с (не успел — ссылка не выдаётся, владелец видит и скачивает работу), обход дерева — без рекурсии.
- **С доменом просмотра домен приложения больше не отдаёт пользовательский HTML.** Статичный (без скриптов) просмотр переехал на домен просмотра (`VIEWER_ORIGIN/static/:token`, грант на 60 секунд: у владельца — по сессии, у получателя — от гранта ссылки) с CSP статичного просмотра и `frame-ancestors <APP_ORIGIN>`; `/api/revisions/:id/document` и `/api/view/:grant/document` на таком сервере отвечают 404, а приложение встраивает фреймы только с домена просмотра (`frame-src` без `'self'`). Установка на одном домене работает как раньше. Спецификация: `docs/specs/ABUSE_PROTECTION.md`, п. 8.
- **Внешние ссылки статичного просмотра ведут через «Вы уходите с Полки».** При отдаче страницы абсолютные `http(s)`-ссылки в `<a>` и `<area>` заменяются на `APP_ORIGIN/away#<токен>`; токен подписан ключом, выведенным из `LINK_KEY`, и живёт 12 часов. Страница `/away` называет адрес и ждёт нажатия; без действующей подписи она ссылку не открывает и сама никуда не перенаправляет. Скачивание отдаёт исходные байты. Спецификация: п. 9.

## [0.1.0-rc.5] — 2026-09-23

Подготовка к открытому запуску: вход в продукт одной фразой агенту, открытая регистрация с потолком, онбординг, модерация и закрытый выход страниц через WebRTC.

### Added

- **Статус оператора** `GET /api/ops/status` (по токену `OPS_STATUS_TOKEN`, без него маршрута нет): БД, работает ли обслуживание, возраст свежего бэкапа, свободный диск; 503, если проверка не прошла. Скрипт `scripts/ci/uptime.mjs` проверяет снаружи доступность, TLS-сертификаты и этот статус — для запуска по расписанию вне VM.
- `npm run check:links` проверяет относительные ссылки и якоря во всех Markdown-файлах.
- **Вход по почте только по приглашению** (`EMAIL_SIGNUP=invite`, по умолчанию в hosted и в SMTP-оверлее base): код получают аккаунты с привязанным адресом (`npm run account:email -- <логин> <почта>`) и адреса или домены из `EMAIL_SIGNUP_ALLOW`; остальным форма отвечает так же, но письмо не уходит. `EMAIL_SIGNUP=open` оставляет открытую регистрацию.
- Hosted compose передаёт приложению `SMTP_*` и `MAIL_FROM`; описана отправка через Yandex Cloud Postbox.
- **Подключение одной фразой.** Агенту достаточно сказать «Подключи Полку: <APP_ORIGIN>/connect»: по этому адресу лежит инструкция для агентов (текст), агент выполняет одну команду, человек входит или создаёт полку по почте и разрешает доступ. Страница входа в этом сценарии объясняет, что агент просит доступ.
- **Суточный потолок новых полок** при регистрации по почте: `EMAIL_SIGNUP_DAILY_LIMIT` на установку (по умолчанию 50) и `EMAIL_SIGNUP_DAILY_PER_IP` (3). О заполненном дне человек узнаёт при запросе кода; существующие аккаунты входят как обычно.
- **Черновики политики обработки персональных данных и пользовательского соглашения** — страницы `/privacy` и `/terms`, ссылки внизу каждой страницы и под формой входа по почте. Текст — в `docs/legal/`, помечен как черновик для проверки юристом; поля оператора (имя, почта, сроки) — заглушки в квадратных скобках.
- **Codex и Claude Code подключаются одной командой, без токена** — через OAuth, как Claude.ai: `codex mcp add polka --url <APP_ORIGIN>/mcp` или `claude mcp add --transport http polka <APP_ORIGIN>/mcp`. Команды — на странице «Агенты» и в `docs/connect-agents.md`; подключение по токену осталось для остальных клиентов.
- **Модерация для оператора** — скрипты без веб-интерфейса, от runtime-роли БД: `npm run moderation:reports` показывает жалобы на ссылки (владелец, открыта ли ссылка, сколько жалоб на ссылку и владельца), `moderation:revoke-share` закрывает одну ссылку, `moderation:disable` блокирует аккаунт одной транзакцией (сессии, подключения агентов вместе с OAuth, все ссылки; данные не удаляются), `moderation:enable` снимает блокировку. Команды для hosted — в `deploy/hosted/README.md`.

- **Первые шаги на полке и `/start`.** Чек-лист из трёх шагов — агент подключён, первая работа сохранена, ссылка создана — выводится из существующих ответов API (`/api/agent-connections`, `/api/artifacts`), без новых таблиц. У каждого шага одно действие: скопировать фразу «Подключи Полку: …/connect» (с командами для Codex, Claude Code, Claude.ai и ChatGPT), «Сохранить без агента», «Поделиться». Блок «Попробовать за 10 секунд» сохраняет встроенную страницу-пример обычной загрузкой. Живая область объявляет выполненные шаги; «Скрыть» запоминается в этом браузере. Спецификация: `docs/specs/ONBOARDING_V2.md`.

### Changed

- Пустая полка объясняет, что здесь появится, вместо набора одинаковых кнопок; после «Разрешить» страница согласия говорит вернуться к агенту.
- **Облачного CI больше нет.** GitHub Actions и Dependabot убраны из репозитория. Все прежние проверки CI выполняет локально `npm run verify` (типы, ссылки, сборка, основной и live-наборы, права ролей БД, лицензии, секреты в истории, сборка образов); `--quick` — быстрый вариант.

### Security

- **Страница в интерактивном просмотре больше не может выйти в сеть через WebRTC.** CSP его не закрывает (Chrome игнорирует `webrtc 'block'`), и проверка на проде показала, что страница достаёт внешний STUN-сервер: могла бы отправить IP читателя и введённый текст. Просмотрщик теперь первым скриптом каждой страницы убирает конструкторы RTC и отдаёт `X-DNS-Prefetch-Control: off`. Отчёт — `docs/reviews/2026-09-23-viewer-egress`.
- **Посторонний больше не может заблокировать вход по почте.** Суточный лимит неудачных попыток на адрес убран: его мог исчерпать любой, кто знает адрес. Вместо него код стал восьмизначным, поэтому перебор при прежних ограничениях отправки и попыток бесполезен. Коды из уже отправленных писем (шестизначные) после обновления не принимаются — запросите новый.

## [0.1.0-rc.4] — 2026-09-22

Правки по итогам второго полного ревью перед открытым релизом (сервер, безопасность, веб, эксплуатация, документация).

### Security

- **Классификатор страниц работает за линейное время.** Регулярные выражения перезапускались с каждого `<`, поэтому время росло квадратично и занимало поток запросов: страница в 480 КБ останавливала сервер примерно на минуту, а разрешённые 5 МБ — на часы. Для второй половины атаки хватало ссылки на такую страницу. Теперь документ разбирается один раз (parse5), 5 МБ — меньше полсекунды.
- **Открытый редирект после входа закрыт.** `next=/.//evil.example` после нормализации превращался в `//evil.example` и уводил уже вошедшего пользователя с Полки без клика.
- **Токен ссылки не уходит в `?next=`.** «Войти» на странице получателя переносил `/s#<токен>` в query-строку, которую видят сервер и прокси.
- **Сохранённая страница не открывается как самостоятельная страница Полки.** Браузер, заявивший навигацию верхнего уровня (`Sec-Fetch-Dest: document`), получает 404; во фрейме всё как раньше.
- **Сборка не оставляет процессов-зомби.** Каждая runtime-сборка оставляла esbuild зомби-процессом сервера; воркер теперь дожидается его выхода.
- **Упавшую сборку нельзя перезапускать в цикле.** После таймаута, нехватки памяти или сбоя сборщика тот же исходник не пересобирается 30 секунд, поэтому один владелец больше не занимает слоты сборки всех остальных.

### Fixed

- Один лимит названия — 160 символов: MCP-захват и импорт по URL принимали 200 и затем падали с «internal».
- Запрос, дождавшийся занятой строки (медленный S3 под блокировкой владельца), получает повторяемый 503 вместо 500; S3-клиент делает не больше двух попыток.
- Интерактивные просмотры по ссылкам одного владельца больше не выстраиваются в очередь друг за другом.
- Неудачный `ROLLBACK` больше не подменяет исходную ошибку.
- Страница входа не говорит, что регистрации нет, если на установке включён вход по почте; приглашение в библиотеку не мигает ошибкой; повтор жалобы не создаёт дубль.
- Healthcheck PostgreSQL проверяет TCP: при первом старте временный сервер отвечал только на сокет, и `migrate` падал на медленной VM.
- Документированное восстановление hosted-дампа не работало (`pg_restore --clean`); новая процедура проверена на реальном дампе схемы 028.

### Changed

- Образ содержит `NOTICE` и `THIRD_PARTY_NOTICES.md`.
- CI собирает backup-образ и проверяет hosted compose; Dependabot следит за npm, actions и образами.
- Документация сверена с кодом: OAuth `resource` необязателен, коннектор проверен с Claude.ai (ChatGPT — ещё нет), приёмка изоляции viewer на hosted пока не записана, runbook первого запуска hosted дополнен.

### Known issues

- Посторонний, знающий адрес почты, может на сутки заблокировать вход по коду для этого адреса: лимит неудачных попыток считается на адрес. Касается только установок с `MAIL_MODE=smtp`, на polochka.app вход по почте выключен.

## [0.1.0-rc.3] — 2026-09-22

### Security

- Классификатор страниц читает атрибуты так же, как браузер: `<meta http-equiv="&#x72;efresh">` и `href="&#x6a;avascript:"` больше не проходят как обычная страница и не получают ссылку.
- `<base target="_blank">` вставляется в настоящий `<head>`, а не в закомментированный, поэтому ссылки в статичном просмотре всегда открываются в новой вкладке.

### Fixed

- В базовом `compose.base.yml` вернулся проброс `127.0.0.1:${APP_PORT}` — без него обратный прокси не мог достучаться до приложения.

## [0.1.0-rc.2] — 2026-09-22

### Added

- **Коннектор для Claude.ai и ChatGPT.** Удалённый MCP-сервер со входом через OAuth 2.1: PKCE S256, Dynamic Client Registration, protected-resource и authorization-server metadata, ротация refresh-токена с обнаружением повтора, страница согласия. Миграция 028. См. [docs/MCP_CONNECTOR.md](docs/MCP_CONNECTOR.md).
- **Инструмент `polka_publish`.** Одна HTML-страница или исходник React-компонента на входе, приватное сохранение и ссылка на выходе. Если на установке включён интерактивный просмотр, сразу собирается интерактивная версия.
- **Интерактивный viewer на отдельном домене.** Режим `HTML_LIVE_MODE=production`, второй registrable domain (polochka.page), Caddy vhost. Получатели и карточки «Интересного» сразу открывают интерактивную версию.
- **React runtime `react-runtime-v1`.** JSX/TS артефактов из чата компилируется при сборке производной. Доступны React, lucide-react, recharts, lodash, d3, three, papaparse, mathjs, chart.js и Tailwind v4. Библиотеки берутся из копий Полки, сети нет, неизвестный import отклоняет сборку.
- **Сборщик `bundle-inline-v6`** (через v4 и v5): принимает обычные артефакты из чата, в том числе data:-шрифты; пропускает внешние шрифты и картинки с предупреждением; даёт общую среду для `text/babel` скриптов. Готовые производные v3 остаются действительными.
- **HTTP API публикации** `POST /api/v1/publish` и `GET /api/v1/status/:id` для агентов без MCP, а также CLI без зависимостей `scripts/polka-publish.mjs` (установка отдаёт его по `/api/v1/cli/polka-publish.mjs`). См. [docs/PUBLISH_API.md](docs/PUBLISH_API.md).
- **«Вставить код»** на странице «Сохранить» и карточка HTTP API на странице «Агенты».
- **Интерактивный каталог «Интересное».** 12 материалов Редакции Полки, статичные снимки для установок без viewer, скрипт засева hosted-каталога.
- **Ссылки Claude/ChatGPT.** Полка узнаёт такую ссылку, объясняет, почему не может забрать артефакт сама, и принимает скачанный файл прямо в карточке.
- Ссылки внутри сохранённых страниц открываются в новой вкладке по клику получателя.
- Hosted-пилот на одной VM: роли PostgreSQL, Caddy с TLS, ежесуточные бэкапы.

### Changed

- **Полный рестайлинг по концептам.** Одна система токенов, общие компоненты, старый CSS удалён. Точки входа в интерфейсе зависят от возможностей установки.
- Обложки «Интересного» подписаны «Редакция».
- `polka_publish` сразу отказывает для страницы больше 5 МБ и называет лимит. Лимит 5 МиБ сохранён ([решение](docs/specs/DECISIONS.md#22092026-лимит-страницы-остаётся-5-миб)).
- Документация переписана: новые README (RU/EN), [архитектура](docs/architecture.md), [подключение агентов](docs/connect-agents.md), [FAQ](docs/faq.md), [состояние](docs/status.md), [дорожная карта](docs/roadmap.md). Спецификации перенесены в `docs/specs/`, внутренние рабочие материалы убраны из репозитория.

### Security

- Коннектор OAuth усилен по итогам ревью: неподтверждённые имена клиентов помечаются, ошибки запроса не пересылаются на адрес клиента, запрос привязан к браузеру, `/oauth/token` и `/oauth/revoke` принимают только form-urlencoded.
- Получатель интерактивной ссылки никогда не получает и не запускает исходную однофайловую загрузку, только собранную производную.
- Runtime-сборщик не читает файлы сервера, а память esbuild ограничена. Закрыты обходы проверки импортов через `require` и sloppy-mode.
- Capabilities viewer не попадают в журнал ошибок Caddy.
