## [0.1.0-rc.4] — 2026-09-22

Правки по итогам второго полного ревью перед открытым релизом (сервер, безопасность, веб, эксплуатация, документация).

### Security

- **Классификатор страниц работает за линейное время.** Регулярные выражения перезапускались с каждого `<`, поэтому время росло квадратично и занимало поток запросов: страница в 480 КБ останавливала сервер примерно на минуту, а разрешённые 5 МБ — на часы. Для второй половины атаки хватало ссылки на такую страницу. Теперь документ разбирается один раз (parse5), 5 МБ — меньше полсекунды.
- **Открытый редирект после входа закрыт.** `next=/.//evil.example` после нормализации превращался в `//evil.example` и уводил уже вошедшего пользователя с Полки без клика.
- **Токен ссылки не уходит в `?next=`.** «Войти» на странице получателя переносил `/s#<токен>` в query-строку, которую видят сервер и прокси.
- **Сохранённая страница не открывается как самостоятельная страница Полки.** Браузер, заявивший навигацию верхнего уровня (`Sec-Fetch-Dest: document`), получает 404; во фрейме всё как раньше.
- **Сборка не оставляет процессов-зомби.** Каждая runtime-сборка оставляла esbuild зомби-процессом сервера; воркер теперь дожидается его выхода.
- **Упавшую сборку нельзя перезапускать в цикле.** После таймаута, нехватки памяти или сбоя сборщика тот же исходник не пересобирается 30 секунд, поэтому один владелец больше не занимает слоты сборки всех остальных.

### Fixed

- Один лимит названия — 160 символов: MCP-захват и импорт по URL принимали 200 и затем падали с «internal».
- Запрос, дождавшийся занятой строки (медленный S3 под блокировкой владельца), получает повторяемый 503 вместо 500; S3-клиент делает не больше двух попыток.
- Интерактивные просмотры по ссылкам одного владельца больше не выстраиваются в очередь друг за другом.
- Неудачный `ROLLBACK` больше не подменяет исходную ошибку.
- Страница входа не говорит, что регистрации нет, если на установке включён вход по почте; приглашение в библиотеку не мигает ошибкой; повтор жалобы не создаёт дубль.
- Healthcheck PostgreSQL проверяет TCP: при первом старте временный сервер отвечал только на сокет, и `migrate` падал на медленной VM.
- Документированное восстановление hosted-дампа не работало (`pg_restore --clean`); новая процедура проверена на реальном дампе схемы 028.

### Changed

- Образ содержит `NOTICE` и `THIRD_PARTY_NOTICES.md`.
- CI собирает backup-образ и проверяет hosted compose; Dependabot следит за npm, actions и образами.
- Документация сверена с кодом: OAuth `resource` необязателен, коннектор проверен с Claude.ai (ChatGPT — ещё нет), приёмка изоляции viewer на hosted пока не записана, runbook первого запуска hosted дополнен.

### Known issues

- Посторонний, знающий адрес почты, может на сутки заблокировать вход по коду для этого адреса: лимит неудачных попыток считается на адрес. Касается только установок с `MAIL_MODE=smtp`, на polochka.app вход по почте выключен.

## [0.1.0-rc.3] — 2026-09-22

### Security

- Классификатор страниц читает атрибуты так же, как браузер: `<meta http-equiv="&#x72;efresh">` и `href="&#x6a;avascript:"` больше не проходят как обычная страница и не получают ссылку.
- `<base target="_blank">` вставляется в настоящий `<head>`, а не в закомментированный, поэтому ссылки в статичном просмотре всегда открываются в новой вкладке.

### Fixed

- В базовом `compose.base.yml` вернулся проброс `127.0.0.1:${APP_PORT}` — без него обратный прокси не мог достучаться до приложения.

## [0.1.0-rc.2] — 2026-09-22

### Added

- **Коннектор для Claude.ai и ChatGPT.** Удалённый MCP-сервер со входом через OAuth 2.1: PKCE S256, Dynamic Client Registration, protected-resource и authorization-server metadata, ротация refresh-токена с обнаружением повтора, страница согласия. Миграция 028. См. [docs/MCP_CONNECTOR.md](docs/MCP_CONNECTOR.md).
- **Инструмент `polka_publish`.** Одна HTML-страница или исходник React-компонента на входе, приватное сохранение и ссылка на выходе. Если на установке включён интерактивный просмотр, сразу собирается интерактивная версия.
- **Интерактивный viewer на отдельном домене.** Режим `HTML_LIVE_MODE=production`, второй registrable domain (polochka.page), Caddy vhost. Получатели и карточки «Интересного» сразу открывают интерактивную версию.
- **React runtime `react-runtime-v1`.** JSX/TS артефактов из чата компилируется при сборке производной. Доступны React, lucide-react, recharts, lodash, d3, three, papaparse, mathjs, chart.js и Tailwind v4. Библиотеки берутся из копий Полки, сети нет, неизвестный import отклоняет сборку.
- **Сборщик `bundle-inline-v6`** (через v4 и v5): принимает обычные артефакты из чата, в том числе data:-шрифты; пропускает внешние шрифты и картинки с предупреждением; даёт общую среду для `text/babel` скриптов. Готовые производные v3 остаются действительными.
- **HTTP API публикации** `POST /api/v1/publish` и `GET /api/v1/status/:id` для агентов без MCP, а также CLI без зависимостей `scripts/polka-publish.mjs` (установка отдаёт его по `/api/v1/cli/polka-publish.mjs`). См. [docs/PUBLISH_API.md](docs/PUBLISH_API.md).
- **«Вставить код»** на странице «Сохранить» и карточка HTTP API на странице «Агенты».
- **Интерактивный каталог «Интересное».** 12 материалов Редакции Полки, статичные снимки для установок без viewer, скрипт засева hosted-каталога.
- **Ссылки Claude/ChatGPT.** Полка узнаёт такую ссылку, объясняет, почему не может забрать артефакт сама, и принимает скачанный файл прямо в карточке.
- Ссылки внутри сохранённых страниц открываются в новой вкладке по клику получателя.
- Hosted-пилот на одной VM: роли PostgreSQL, Caddy с TLS, ежесуточные бэкапы.

### Changed

- **Полный рестайлинг по концептам.** Одна система токенов, общие компоненты, старый CSS удалён. Точки входа в интерфейсе зависят от возможностей установки.
- Обложки «Интересного» подписаны «Редакция».
- `polka_publish` сразу отказывает для страницы больше 5 МБ и называет лимит. Лимит 5 МиБ сохранён ([решение](docs/specs/DECISIONS.md#22092026-лимит-страницы-остаётся-5-миб)).
- Документация переписана: новые README (RU/EN), [архитектура](docs/architecture.md), [подключение агентов](docs/connect-agents.md), [FAQ](docs/faq.md), [состояние](docs/status.md), [дорожная карта](docs/roadmap.md). Спецификации перенесены в `docs/specs/`, внутренние рабочие материалы убраны из репозитория.

### Security

- Коннектор OAuth усилен по итогам ревью: неподтверждённые имена клиентов помечаются, ошибки запроса не пересылаются на адрес клиента, запрос привязан к браузеру, `/oauth/token` и `/oauth/revoke` принимают только form-urlencoded.
- Получатель интерактивной ссылки никогда не получает и не запускает исходную однофайловую загрузку, только собранную производную.
- Runtime-сборщик не читает файлы сервера, а память esbuild ограничена. Закрыты обходы проверки импортов через `require` и sloppy-mode.
- Capabilities viewer не попадают в журнал ошибок Caddy.

## [0.1.0-rc.1] — 2026-09-21

Первый открытый prerelease.

### Added

- Аккаунты: вход по паролю (аккаунт создаёт оператор) и по коду из письма (при настроенном SMTP).
- Полка: папки, поиск, переименование и перенос. Неизменяемые версии с SHA-256 и CAS. Корзина и восстановление.
- Загрузка HTML, текста и PNG/JPEG/WebP до 5 МБ. Multi-file bundle через MCP (до 64 файлов).
- Ссылки: срок, отзыв, привязка к версии, жалобы получателя. Статичный просмотр HTML в песочнице без скриптов и сети.
- MCP-сервер (Streamable HTTP) с токенами подключения и узкими scopes: `polka_context`, `polka_capture`, `polka_status`, `polka_revise`, `polka_share`, `polka_revoke_share`, `polka_list`, `polka_prepare_preview`, инструменты управления и шаблонов. Страница «Агенты» для выдачи и отзыва токенов.
- Контекст для агента и библиотеки шаблонов: роли reader/curator/admin, приглашения, журнал, закреплённые версии.
- Экспериментальный интерактивный просмотр на отдельном loopback origin.
- Импорт standalone HTML по URL (выключен по умолчанию).
- Удаление аккаунта: отзыв доступа в коде (выключено по умолчанию); очистка данных — отдельный purge worker, не принят и не подключён к установке. Синтетический restore drill, штатный restore CLI.
- Self-host: Docker-образ с закреплённым base digest, readiness, maintenance-воркер, рецепты прав ролей БД.
- CI: тесты на временных PostgreSQL и MinIO, проверка лицензий, поиск секретов, smoke-тест образа.
