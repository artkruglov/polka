# Changelog

Все заметные изменения Полки. Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/). До `1.0.0` API, схема БД и интерфейс могут меняться между prerelease-версиями.

## [Unreleased]

### Added

- **Обложки на полке** ([SHELF_COVERS](docs/specs/SHELF_COVERS.md); миграция 040). Карточка больше не показывает уменьшенную страницу в iframe.
  - Отчёты, заметки и документы получают текстовую обложку: собственный заголовок документа, начало лида, метку вида и цвет страницы. Дашборды, приложения и изображения получают снимок первого экрана, который рендерер рисует один раз на версию без доступа к сети (`COVER_SNAPSHOTS_ENABLED`, по умолчанию выключено).
  - Под обложкой: название (не больше двух строк), одна строка «вид · версия · дата» со значком доступа и меню «…». Вся карточка открывает работу; «Открыть ↗» ушло в меню (для ссылок — «Открыть оригинал»).
  - Работы с общим началом названия («Y360 Radar · …») получают значок серии. В списке появились миниатюры.
  - Для уже сохранённых работ: `npm run covers:backfill -- --dry-run`.
- **«Войти через Google»** (миграция 039, [SIGN_IN_PROVIDERS](docs/specs/SIGN_IN_PROVIDERS.md), «Google»; настройка — [google-oauth-setup](docs/ops/google-oauth-setup.md)).
  - Обычный OpenID Connect с accounts.google.com: discovery, PKCE S256, state, nonce, scopes только `openid email profile`, выбор аккаунта при каждом входе. `id_token` проверяется полностью: подпись по JWKS Google, `iss`, `aud`, `azp`, `exp`, `nonce`. Почта учитывается только при `email_verified: true`. Домен Google Workspace (`hd`) сохраняется в `account_identities.hosted_domain`, если он есть; аватар не хранится.
  - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`: без них кнопки нет. `GOOGLE_SIGNUP=on` (по умолчанию) — Google открывает полки, как Яндекс ID. `link-only` (по умолчанию в `deploy/hosted`) — Google только входит в полку, к которой владелец привязал его в «Способах входа». Он не открывает новую полку, не привязывается по почте и не закрепляет временную полку (ч. 10 ст. 8 149-ФЗ).
  - Кнопка по правилам Google Identity: светлая тема, стандартный «G», текст «Войти через Google». Привязка и отвязка в «Способах входа», последний способ входа отвязать нельзя. Удаление аккаунта стирает привязку Google вместе с остальными.
  - В политике обработки данных — пункт «Вход через Google» (редакция от 25 сентября 2026).
- **Агент раскладывает полку по папкам** (миграция 038, [connect-agents](docs/connect-agents.md#инструменты-mcp)).
  - Скилл `polka-organize` (`skills/polka-organize/SKILL.md`, `/.well-known/agent-skills/polka-organize/SKILL.md`, в индексе Agent Skills): на «разложи полку», «наведи порядок в папках», «структурируй работы» агент читает всю полку, предлагает 3–8 папок по проектам и темам (серии — в одну папку), показывает план таблицей и только после согласия создаёт папки и переносит работы. Папки владельца остаются, работы не удаляются и не переименовываются. Скилл `polka` теперь сохраняет новую работу в подходящую папку.
  - Инструменты MCP (scope `manage`, с ключом идемпотентности и записью в журнал): `polka_create_folder`, `polka_rename_folder`, `polka_delete_folder` (только пустую папку; работы в корзине при этом остаются «без папки»), `polka_move` — до 100 работ в папку или «без папки» одной транзакцией, всё или ничего, без изменения порядка полки.
  - `polka_list` (и `GET /api/v1/status/{id}`) отдаёт вид работы (`kind`), название папки, дату создания; `polka_list` — до 100 работ за вызов; `polka_list_folders` — число работ в папке.
  - У каждого инструмента MCP есть `title` и подсказка `readOnlyHint` или `destructiveHint`; тест следит за этим.
- **Плагин Полки для Claude Code и Codex** ([connect-agents](docs/connect-agents.md#плагин-полки-для-claude-code-и-codex)). Репозиторий — маркетплейс `polka` с одним плагином `polka`: `.claude-plugin/{marketplace,plugin}.json` для Claude Code, `.agents/plugins/marketplace.json` и `.codex-plugin/plugin.json` для Codex, общий `.mcp.json` (удалённый HTTP-сервер `https://polochka.app/mcp`, вход OAuth при первом подключении) и все скиллы из `skills/*` — каталог, а не список, так что новый скилл приходит с обновлением плагина. Установка одной командой:
  - Claude Code: `claude plugin marketplace add artkruglov/polka && claude plugin install polka@polka`, затем `/mcp` → `plugin:polka:polka` → Authenticate;
  - Codex: `codex plugin marketplace add artkruglov/polka && codex plugin add polka@polka`, затем `codex mcp login polka`.

  Проверено установкой из локальной копии в пустые профили Claude Code 2.1.282 и Codex 0.153.4. `/connect`, страница «Агенты», подсказки на `/start` и лендинг дают эти команды; `claude mcp add` и `codex mcp add` остались вариантом без плагина.

- **Одна полка на человека** ([SIGN_IN_PROVIDERS](docs/specs/SIGN_IN_PROVIDERS.md), § 1, 8–10; миграция 036).
  - **«Похоже, у вас уже есть полка».** Браузер после входа помнит только имя полки, способ и время входа — без id и почты, в `localStorage`. Если Яндекс ID, VK ID или код на новый адрес откроют новую полку, Полка сначала спрашивает на `/signup/choose`: войти в существующую (новый способ входа привяжется к ней) или создать новую. Данные поставщика 10 минут хранятся в памяти сервера и в URL не попадают.
  - **Страница подключения агента** показывает, куда пойдут работы («полка «…» (почта, Яндекс ID)»), и позволяет выйти и войти в другую.
  - **Без регистрации.** «Начать без регистрации» открывает временную полку этого браузера: сессия 30 дней, продлевается при посещении. Второй агент попадает в ту же полку. Ссылки и публикации — только после закрепления через Яндекс ID, VK ID или почту на российском домене (ч. 10 ст. 8 149-ФЗ). До того агенты и HTTP API получают `claimUrl`, а в интерфейсе вместо ссылки — «Закрепить, чтобы поделиться». Закрепление привязывает способ входа к этой же полке. Если способ уже открывает другую полку — «Объединить». Простаивающую 30 дней полку удаляет обслуживание.
  - **`npm run account:merge -- --from … --into … [--dry-run]`** — объединение двух полок оператором:
    - работы, версии, объекты хранилища, папки, ссылки (старые адреса открываются), обсуждения, подключения агентов с ключами продления (продолжают работать), привязки, библиотеки, заметки, статистика;
    - источник удаляется, в журнал пишется `account.merged` с номером обращения (`--proof`).
  - **«Открой мою Полку»** (`polka_open_shelf`, `POST /api/v1/sign-in-link`):
    - закреплённой полке агент даёт страницу входа без секрета;
    - одноразовую ссылку `…/enter#…` он даёт только временной полке и только с отдельным правом `sign_in` («Давать ссылку для входа», по умолчанию выключено; существующим подключениям не включено). Ссылка работает 5 минут, один раз, после клика, и никогда молча не заменяет текущий вход;
    - сессия по такой ссылке слабая: она не может закреплять и объединять полки, менять способы входа, управлять агентами и удалять аккаунт.
  - Объединение оператором требует `--proof <номер обращения>`, а источник удаляется. При закреплении каждый переезжающий агент отмечается вручную. Комментарии, реакции, библиотеки и приглашения тоже требуют закреплённой полки. У временной полки квота 20 МБ, одна полка на запрос подключения и свой суточный бюджет (20 с адреса, 2000 на установку), отдельный от регистраций. Слабая сессия живёт сутки, не выдаёт ссылок и удаляется при закреплении полки.
- **Импорт по ссылке: одна таблица источников** (`packages/contracts/link-providers.ts`). Её читают сервер, веб и рендерер. Маршруты: `server-api`, `server-fetch`, `server-try`, `server-render`, `extension`, `html` ([URL_IMPORT_SUPPORT](docs/specs/URL_IMPORT_SUPPORT.md)).
- **GitHub Gist** через официальный API (`api.github.com/gists/<id>`): HTML — страница, несколько файлов — пакет, код — статичная страница. Лимит GitHub сообщается как `rate_limited`, без повтора; `GITHUB_TOKEN` необязателен.
- **Рендерер** `apps/renderer`: отдельный сервис на образе Playwright, закреплённом по digest. `POST /render` делает снимок DOM SPA-сайтов (Lovable, bolt.host, Replit, GitHub Pages, Gemini share) и одну попытку для артефакта Claude. `POST /fetch` — один GET без браузера для общих ссылок ChatGPT. Egress только через прокси с закреплённым DNS, без приватных адресов и metadata. HMAC-подпись с окном 60 с. robots.txt для `PolkaRenderer` читает сам рендерер; проверки на бота → `source_blocked`, без повторов. Развёртывание: профиль compose, Yandex Cloud или Fly.io (`deploy/renderer`). Включается `RENDERED_IMPORT_ENABLED` (по умолчанию выключен), состояние задания `rendering` — миграция 037.
- **ChatGPT share и canvas** разбираются из данных React Router: canvas становится страницей или компонентом, HTML/React/SVG из последнего ответа — работой, иначе сохраняется сам разговор. Сервер Полки к chatgpt.com не обращается.
- **«Сохранить как ссылку»** ([SAVED_LINKS](docs/specs/SAVED_LINKS.md)): работа-закладка с адресом, названием и заметкой, без миграции. `POST /api/links`, MCP `polka_save_link`. На полке, на странице работы и у получателя — карточка со значком сервиса и кнопкой «Открыть ↗». Фильтр содержимого читает адрес (список доменов) и текст.
- **Страница `/bot`** для владельцев сайтов: что делает PolkaRenderer, что он работает только по действию пользователя и как запретить его в robots.txt.

### Changed

- **Фишинг — только когда страница уводит читателя** ([CONTENT_FILTER, «Фишинг»](docs/specs/CONTENT_FILTER.md#фишинг); [ABUSE_PROTECTION, п. 6](docs/specs/ABUSE_PROTECTION.md#6-признаки-фишинга); без миграции).
  - Экран входа с паролем, названия брендов (Яндекс, Apple, Telegram) и «подтвердите» больше не задерживают ссылку: на Полке введённое никуда не уходит (CSP `connect-src 'none'`, `form-action 'none'`, песочница, `/away`). Так задерживались прототипы B2B-продуктов, например прототип «Алиса AI в Яндекс 360» 25–26.09. Поля по-прежнему отмечаются, и получатель видит «Страница … просит пароль, код или данные карты. Не вводите их здесь.».
  - Нужен канал вне страницы. Это просьба передать код, пароль или данные карты («продиктуйте код», «отправьте код из SMS в Telegram @…»), перевести деньги на карту или кошелёк, или похожий домен бренда (`yandex-360-login.ru`, `apple-id-verify.com`, IDN, цифры вместо букв). Telegram, телефон, почта и ссылка на чужую страницу входа только добавляют к счёту. Бренд без канала весит ноль.
  - Фишинг, найденный только правилами у доверенного автора, — письмо оператору, ссылка работает, если модель прочитала работу и не назвала её фишингом (или ещё прочитает: её ответ решает ссылку заново). Подтверждённый моделью фишинг задерживается, как раньше.
  - Одобрение оператора переходит на следующие версии работы: версия с теми же или меньшими признаками не задерживается снова, новый признак задерживает (`revisions.content_filter.approved`, `details.approvedSignals` у `share.approved`).
  - `moderation.ts recheck --fraud [--dry-run]` перечитывает версии задержанных за фишинг ссылок по новым правилам и открывает те, что больше не подходят (журнал: `revision.rescanned`, `share.released`).
- **Все разрешения агента отмечены по умолчанию.** На странице согласия («Что сможет приложение») сразу стоят все галочки, включая «Управлять названиями, папками и корзиной» и «Давать ссылку для входа»: агент сразу умеет всё, владелец может снять любую. Действия за ними обратимы (корзина, удаление только пустых папок, новые версии не стирают старые); ссылка для входа открывает только временную полку. Уже выданные подключения не меняются — чтобы добавить разрешения, подключите агента заново.
- **Главная полка начинается с агента.** Вместо поля «Вставьте ссылку на артефакт» — один блок «Подключите агента — он сам сохранит работу на полку» с переключателем Claude (claude.ai и Desktop) / Claude Code / Codex / Другой MCP-клиент и одним шагом для каждого: адрес коннектора с кнопкой копирования, команда плагина или адрес MCP и `npx skills add artkruglov/polka`. Полная версия — «Агенты» (`/settings/agents?client=…`), «Загрузить файл» рядом. Когда агент подключён (или блок скрыт), остаётся одна строка: «Подключено: …», фраза «Сохрани это на Полку», «Агенты», «Загрузить файл». Чек-лист первых шагов на полке больше не показывается, он остался на `/start` (`features/agent-hero`).
- **«Сохранить» — файл или код.** Страница `/bring` называется «Сохранить работу» и предлагает загрузку файла и «Вставить код»; `?url=` из старых ссылок игнорируется.

- **Предупреждение получателю — только когда есть повод** ([CONTENT_FILTER, «Поля для секретов»](docs/specs/CONTENT_FILTER.md#поля-для-секретов)). При сохранении Полка отмечает, есть ли на странице поля для пароля, карты, одноразового кода или seed-фразы: в разметке и в скриптах, которые строят форму (`content_filter.sensitiveInput`, без миграции). Отчёт или дашборд без таких полей подписан тихо: «Опубликовал пользователь Полки». Страница с такими полями и версия, сохранённая раньше, показывают предупреждение без неточного «не проверена». В «Подробнее» сказано, проверила ли Полка текст и код автоматически. Старые версии размечает `npm run moderation:backfill-sensitive-input -- [--dry-run]`.

- **Страница работы — режим чтения.** Над работой одна тонкая полоса: «←», название, «v1 ▾», вкладки «Работа · Версии», ⓘ с подробностями (вид, доступ, версия, файл, пояснение о просмотре), «На весь экран», «Поделиться» и «…» со всеми остальными действиями. Работа занимает весь оставшийся экран и прокручивается внутри; на 1440×900 она начинается в 52 px от верха вместо ~450. Вкладка сохраняется в адресе (`?tab=versions`). Боковое меню на этой странице свёрнуто до иконок, переключатель запоминается в браузере. На телефоне — одна полоса и строка вкладок ([FRONTEND_COMPONENT_SYSTEM](docs/FRONTEND_COMPONENT_SYSTEM.md)).
- **Карточка ссылки AI-сервиса.** Способы идут по порядку: «Попросить Claude» (или фраза для своего агента), «Сохранить как ссылку», файл прямо в карточке. Расширение перенесено за ссылку «Сохранять в один клик». Неудавшийся импорт предлагает сохранить ссылку.

- **«На Полку» на странице `claude.ai/artifact/<id>`.** У неё нет Copy и вкладки Code, поэтому исходник берётся через меню названия → Export → Download: на время одного сохранения в мире страницы перехватываются `URL.createObjectURL`, клики и `dispatchEvent` по `a[download]` и `window.open`, Blob читается, файл в «Загрузки» не попадает (скачивание с сервера тоже останавливается — тогда берётся фрейм), всё восстанавливается, меню закрывается Escape. Меню — Base UI: открывается фокусом + ArrowDown (синтетические клики и Enter его не открывают), подменю — ArrowRight, пункты ищутся по `data-title-menu`/`data-download-submenu`/`data-download-item`, затем по тексту; закрывается Escape на пункте в фокусе, иначе на кнопке, иначе нажатием вне меню. «Copy as Markdown» не нажимается. Фрейм — `*.frame.claudeusercontent.com`, скрытый фрейм 1×1 пропускается; кнопка «На Полку» стоит рядом с Share. Фикстура `claude-artifact-page.html` повторяет эту структуру.

### Removed

- **Импорт по ссылке из веб-интерфейса** ([FAQ](docs/faq.md#почему-нельзя-вставить-ссылку-на-артефакт-claude-или-chatgpt)). Ссылки на артефакты Claude закрыты Cloudflare, а серверная загрузка на polochka.app выключена, поэтому сохранять работу теперь предлагается только агентом или файлом. Убраны поле ссылки на полке, на лендинге и на `/start`, карточка ссылки AI-сервиса на «Сохранить» (`features/import-url` удалён целиком), «Сохранить по ссылке» на пустой полке, подсказки «Сохранять в один клик» про расширение и закладку. `/bookmarklet` и `/bring/receive` работают по прямому адресу, но ни откуда не связаны. Сервер (`apps/server/url-import`), рендерер и MCP `polka_import_url` / `polka_save_link` не менялись; [URL_IMPORT_SUPPORT](docs/specs/URL_IMPORT_SUPPORT.md) помечен как эксперимент.

### Added

- **Закладка «На Полку»** — альтернатива расширению для тех, кто не ставит расширения: обычная закладка с `javascript:`-адресом, страница установки `/bookmarklet` (кнопка для перетаскивания, код для телефона, исходник на GitHub). По нажатию на странице Claude, ChatGPT или другого AI-чата из списка читает артефакт теми же модулями, что и расширение (Export → Download, кнопка Copy, вкладка Code; на других чатах — снимок страницы без скриптов), открывает вкладку `/bring/receive#nonce=…` и передаёт данные только ей через `postMessage` (протокол — `packages/contracts/bookmarklet.ts`). Вкладка принимает одно сообщение: от `window.opener`, с https-адреса AI-чата из списка, с её nonce, до 5 МБ; показывает карточку с названием, источником и размером, гостю — вход с возвратом (данные ждут в `sessionStorage` этой вкладки), сохраняет обычной загрузкой файла и открывает работу. Адрес страницы попадает в provenance: у загрузки HTML появилось необязательное поле `sourceUrl` (https, без query и фрагмента) → `provenance.kind = "url"`. Сборка — `extensions/bookmarklet` (esbuild, ~24 КБ), адрес Полки подставляет сама страница установки. Компонент `BookmarkletHint` для карточки ссылок Claude/ChatGPT.
- **Расширение «На Полку» для Chrome** (`extensions/chrome`, Manifest V3, `npm run ext:build` → `dist/` и zip). Сохраняет артефакт Claude (и, экспериментально, код из ChatGPT) из браузера пользователя: значок на панели, кнопка «На Полку» рядом с артефактом, а ссылка `claude.ai/artifact/…`, вставленная в «Сохранить», передаётся расширению через `postMessage` с nonce (только то же окно и origin Полки; протокол — `packages/contracts/extension-bridge.ts`), оно открывает её в фоновой вкладке и возвращает ссылку. Без расширения карточка Claude/ChatGPT показывает, как его установить. Код берётся по нажатию: кнопка Copy артефакта с перехватом `navigator.clipboard` в мире страницы, документ во фрейме `*.claudeusercontent.com` без рантайма просмотрщика, вкладка Code. - **Сервер для расширений браузера.** Экран согласия называет клиента с redirect `https://<id>.chromiumapp.org/…` «расширением браузера» с его ID, а ID из новой переменной `BROWSER_EXTENSION_IDS` — «Расширение браузера «На Полку»»; имя «На Полку» у остальных помечается «(имя не подтверждено)». `POST /api/v1/publish` принимает `Origin: chrome-extension://<id>`. В метриках клиент такого подключения — `browser-extension`.

### Security

- **Глубоко вложенная страница больше не останавливает сервер.** Разбор HTML в parse5 квадратичен по глубине вложенности (200 КБ вложенных `<div>` — около 4 с, 5 МБ — около 40 мин), а обход дерева в классификаторе был рекурсивным и падал с переполнением стека. Запись rc.4 о линейном времени была верна только для «плоских» страниц. Теперь страницы больше 16 КБ классифицируются в отдельном потоке с дедлайном 2 с (не успел — ссылка не выдаётся, владелец видит и скачивает работу), обход дерева — без рекурсии.
- **С доменом просмотра домен приложения больше не отдаёт пользовательский HTML.** Статичный (без скриптов) просмотр переехал на домен просмотра (`VIEWER_ORIGIN/static/:token`, грант на 60 секунд: у владельца — по сессии, у получателя — от гранта ссылки) с CSP статичного просмотра и `frame-ancestors <APP_ORIGIN>`; `/api/revisions/:id/document` и `/api/view/:grant/document` на таком сервере отвечают 404, а приложение встраивает фреймы только с домена просмотра (`frame-src` без `'self'`). Установка на одном домене работает как раньше. Спецификация: `docs/specs/ABUSE_PROTECTION.md`, п. 8.
- **Внешние ссылки статичного просмотра ведут через «Вы уходите с Полки».** При отдаче страницы абсолютные `http(s)`-ссылки в `<a>` и `<area>` заменяются на `APP_ORIGIN/away#<токен>`; токен подписан ключом, выведенным из `LINK_KEY`, и живёт 12 часов. Страница `/away` называет адрес и ждёт нажатия; без действующей подписи она ссылку не открывает и сама никуда не перенаправляет. Скачивание отдаёт исходные байты. Спецификация: п. 9.

- **Модерация для оператора** — скрипты без веб-интерфейса, от runtime-роли БД: `npm run moderation:reports` показывает жалобы на ссылки (владелец, открыта ли ссылка, сколько жалоб на ссылку и владельца), `moderation:revoke-share` закрывает одну ссылку, `moderation:disable` блокирует аккаунт одной транзакцией (сессии, подключения агентов вместе с OAuth, все ссылки; данные не удаляются), `moderation:enable` снимает блокировку. Команды для hosted — в `deploy/hosted/README.md`.

- **Первые шаги на полке и `/start`.** Чек-лист из трёх шагов — агент подключён, первая работа сохранена, ссылка создана — выводится из существующих ответов API (`/api/agent-connections`, `/api/artifacts`), без новых таблиц. У каждого шага одно действие: скопировать фразу «Подключи Полку: …/connect» (с командами для Codex, Claude Code, Claude.ai и ChatGPT), «Сохранить без агента», «Поделиться». Блок «Попробовать за 10 секунд» сохраняет встроенную страницу-пример обычной загрузкой. Живая область объявляет выполненные шаги; «Скрыть» запоминается в этом браузере. Спецификация: `docs/specs/ONBOARDING_V2.md`.

### Changed

- Пустая полка объясняет, что здесь появится, вместо набора одинаковых кнопок; после «Разрешить» страница согласия говорит вернуться к агенту.
- **Облачного CI больше нет.** GitHub Actions и Dependabot убраны из репозитория. Все прежние проверки CI выполняет локально `npm run verify` (типы, ссылки, сборка, основной и live-наборы, права ролей БД, лицензии, секреты в истории, сборка образов); `--quick` — быстрый вариант.

### Security

- **Страница в интерактивном просмотре больше не может выйти в сеть через WebRTC.** CSP его не закрывает (Chrome игнорирует `webrtc 'block'`), и проверка на проде показала, что страница достаёт внешний STUN-сервер: могла бы отправить IP читателя и введённый текст. Просмотрщик теперь первым скриптом каждой страницы убирает конструкторы RTC и отдаёт `X-DNS-Prefetch-Control: off`. Отчёт — `docs/reviews/2026-09-23-viewer-egress`.
- **Посторонний больше не может заблокировать вход по почте.** Суточный лимит неудачных попыток на адрес убран: его мог исчерпать любой, кто знает адрес. Вместо него код стал восьмизначным, поэтому перебор при прежних ограничениях отправки и попыток бесполезен. Коды из уже отправленных писем (шестизначные) после обновления не принимаются — запросите новый.

## [0.1.0-rc.4] — 2026-09-22

Правки по итогам второго полного ревью перед открытым релизом (сервер, безопасность, веб, эксплуатация, документация).

### Security

- **Классификатор страниц работает за линейное время.** Регулярные выражения перезапускались с каждого `<`, поэтому время росло квадратично и занимало поток запросов: страница в 480 КБ останавливала сервер примерно на минуту, а разрешённые 5 МБ — на часы. Для второй половины атаки хватало ссылки на такую страницу. Теперь документ разбирается один раз (parse5), 5 МБ — меньше полсекунды.
- **Открытый редирект после входа закрыт.** `next=/.//evil.example` после нормализации превращался в `//evil.example` и уводил уже вошедшего пользователя с Полки без клика.
- **Токен ссылки не уходит в `?next=`.** «Войти» на странице получателя переносил `/s#<токен>` в query-строку, которую видят сервер и прокси.
- **Сохранённая страница не открывается как самостоятельная страница Полки.** Браузер, заявивший навигацию верхнего уровня (`Sec-Fetch-Dest: document`), получает 404; во фрейме всё как раньше.
- **Сборка не оставляет процессов-зомби.** Каждая runtime-сборка оставляла esbuild зомби-процессом сервера; воркер теперь дожидается его выхода.
- **Упавшую сборку нельзя перезапускать в цикле.** После таймаута, нехватки памяти или сбоя сборщика тот же исходник не пересобирается 30 секунд, поэтому один владелец больше не занимает слоты сборки всех остальных.

### Fixed

- Один лимит названия — 160 символов: MCP-захват и импорт по URL принимали 200 и затем падали с «internal».
- Запрос, дождавшийся занятой строки (медленный S3 под блокировкой владельца), получает повторяемый 503 вместо 500; S3-клиент делает не больше двух попыток.
- Интерактивные просмотры по ссылкам одного владельца больше не выстраиваются в очередь друг за другом.
- Неудачный `ROLLBACK` больше не подменяет исходную ошибку.
- Страница входа не говорит, что регистрации нет, если на установке включён вход по почте; приглашение в библиотеку не мигает ошибкой; повтор жалобы не создаёт дубль.
- Healthcheck PostgreSQL проверяет TCP: при первом старте временный сервер отвечал только на сокет, и `migrate` падал на медленной VM.
- Документированное восстановление hosted-дампа не работало (`pg_restore --clean`); новая процедура проверена на реальном дампе схемы 028.

### Changed

- Образ содержит `NOTICE` и `THIRD_PARTY_NOTICES.md`.
- CI собирает backup-образ и проверяет hosted compose; Dependabot следит за npm, actions и образами.
- Документация сверена с кодом: OAuth `resource` необязателен, коннектор проверен с Claude.ai (ChatGPT — ещё нет), приёмка изоляции viewer на hosted пока не записана, runbook первого запуска hosted дополнен.

### Known issues

- Посторонний, знающий адрес почты, может на сутки заблокировать вход по коду для этого адреса: лимит неудачных попыток считается на адрес. Касается только установок с `MAIL_MODE=smtp`, на polochka.app вход по почте выключен.

## [0.1.0-rc.3] — 2026-09-22

### Security

- Классификатор страниц читает атрибуты так же, как браузер: `<meta http-equiv="&#x72;efresh">` и `href="&#x6a;avascript:"` больше не проходят как обычная страница и не получают ссылку.
- `<base target="_blank">` вставляется в настоящий `<head>`, а не в закомментированный, поэтому ссылки в статичном просмотре всегда открываются в новой вкладке.

### Fixed

- В базовом `compose.base.yml` вернулся проброс `127.0.0.1:${APP_PORT}` — без него обратный прокси не мог достучаться до приложения.

## [0.1.0-rc.2] — 2026-09-22

### Added

- **Коннектор для Claude.ai и ChatGPT.** Удалённый MCP-сервер со входом через OAuth 2.1: PKCE S256, Dynamic Client Registration, protected-resource и authorization-server metadata, ротация refresh-токена с обнаружением повтора, страница согласия. Миграция 028. См. [docs/MCP_CONNECTOR.md](docs/MCP_CONNECTOR.md).
- **Инструмент `polka_publish`.** Одна HTML-страница или исходник React-компонента на входе, приватное сохранение и ссылка на выходе. Если на установке включён интерактивный просмотр, сразу собирается интерактивная версия.
- **Интерактивный viewer на отдельном домене.** Режим `HTML_LIVE_MODE=production`, второй registrable domain (polochka.page), Caddy vhost. Получатели и карточки «Интересного» сразу открывают интерактивную версию.
- **React runtime `react-runtime-v1`.** JSX/TS артефактов из чата компилируется при сборке производной. Доступны React, lucide-react, recharts, lodash, d3, three, papaparse, mathjs, chart.js и Tailwind v4. Библиотеки берутся из копий Полки, сети нет, неизвестный import отклоняет сборку.
- **Сборщик `bundle-inline-v6`** (через v4 и v5): принимает обычные артефакты из чата, в том числе data:-шрифты; пропускает внешние шрифты и картинки с предупреждением; даёт общую среду для `text/babel` скриптов. Готовые производные v3 остаются действительными.
- **HTTP API публикации** `POST /api/v1/publish` и `GET /api/v1/status/:id` для агентов без MCP, а также CLI без зависимостей `scripts/polka-publish.mjs` (установка отдаёт его по `/api/v1/cli/polka-publish.mjs`). См. [docs/PUBLISH_API.md](docs/PUBLISH_API.md).
- **«Вставить код»** на странице «Сохранить» и карточка HTTP API на странице «Агенты».
- **Интерактивный каталог «Интересное».** 12 материалов Редакции Полки, статичные снимки для установок без viewer, скрипт засева hosted-каталога.
- **Ссылки Claude/ChatGPT.** Полка узнаёт такую ссылку, объясняет, почему не может забрать артефакт сама, и принимает скачанный файл прямо в карточке.
- Ссылки внутри сохранённых страниц открываются в новой вкладке по клику получателя.
- Hosted-пилот на одной VM: роли PostgreSQL, Caddy с TLS, ежесуточные бэкапы.

### Changed

- **Полный рестайлинг по концептам.** Одна система токенов, общие компоненты, старый CSS удалён. Точки входа в интерфейсе зависят от возможностей установки.
- Обложки «Интересного» подписаны «Редакция».
- `polka_publish` сразу отказывает для страницы больше 5 МБ и называет лимит. Лимит 5 МиБ сохранён ([решение](docs/specs/DECISIONS.md#22092026-лимит-страницы-остаётся-5-миб)).
- Документация переписана: новые README (RU/EN), [архитектура](docs/architecture.md), [подключение агентов](docs/connect-agents.md), [FAQ](docs/faq.md), [состояние](docs/status.md), [дорожная карта](docs/roadmap.md). Спецификации перенесены в `docs/specs/`, внутренние рабочие материалы убраны из репозитория.

### Security

- Коннектор OAuth усилен по итогам ревью: неподтверждённые имена клиентов помечаются, ошибки запроса не пересылаются на адрес клиента, запрос привязан к браузеру, `/oauth/token` и `/oauth/revoke` принимают только form-urlencoded.
- Получатель интерактивной ссылки никогда не получает и не запускает исходную однофайловую загрузку, только собранную производную.
- Runtime-сборщик не читает файлы сервера, а память esbuild ограничена. Закрыты обходы проверки импортов через `require` и sloppy-mode.
- Capabilities viewer не попадают в журнал ошибок Caddy.
