## [Unreleased]

### Added

- **Страницы проекта с React** ([PROJECTS](docs/specs/PROJECTS.md#страницы-с-react), #20). HTML-страница проекта может грузить React, ReactDOM, Babel или Tailwind с CDN или подключать `<script type="module">` и `text/babel`. Просмотрщик отдаёт её собранной тем же сборщиком, что одиночные страницы, без сети и с копиями библиотек Полки. Стили, картинки, обычные скрипты и ссылки остаются файлами проекта. Раньше такие скрипты блокировались и страница оставалась пустой. Страницы, которые не собрались, перечислены в `pagesNotBuilt` в ответе на сохранение проекта (REST и MCP), CLI печатает их.
- **Контекст для агента у сохранённой ссылки** ([AGENT_CONTEXT_TEMPLATES](docs/specs/AGENT_CONTEXT_TEMPLATES.md#обычные-исходники--серверный-пакет-реализован), #46): «Скопировать для агента», «Подробный контекст» и `polka_read_source` передают адрес и заметку ссылки (`link.json`). Раньше на ссылке они отвечали 422. Отказ для формата без контекста теперь перечисляет форматы, у которых он есть.
- **Приёмка управления работами настоящим агентом** ([AGENT_MANAGE_ACCEPTANCE](docs/dev/AGENT_MANAGE_ACCEPTANCE.md), #47): `scripts/agent-manage-acceptance.ts` даёт Claude Code или Codex с правами `context`, `read`, `manage` переименовать работу, перенести, убрать в корзину и вернуть без веба, затем проверяет результат и журнал. Прогон 09.10.2026: оба агента прошли. В `connect-agents.md` добавлено, что Codex в `exec` останавливается перед `polka_trash` и `polka_restore`, пока их не одобрить.

## [0.13.0] — 2026-10-09

### Added

- **Приглашение ссылкой на полку отдела** ([TEAM_SHELVES](docs/specs/TEAM_SHELVES.md#приглашение-ссылкой-миграция-067)), миграция 067: администратор или куратор полки создаёт ссылку с ролью, сроком (до недели) и числом мест (1–50); коллега, который ещё ни разу не входил, открывает её, входит и оказывается на полке. Ссылку можно отозвать; куратор приглашает только читателей и авторов, администратора ссылкой не назначить. Всё пишется в журнал полки.
- **«Предложить в Ленту» с полки отдела** ([DISCOVER_V2](docs/specs/DISCOVER_V2.md), раздел 5а), миграция 068: куратор предлагает версию работы с заголовком и строкой описания, решает и публикует оператор (`npm run feed:proposals`). Предложение можно отозвать; всё пишется в журнал полки.
- **«Полка на дату»** ([SHELF_SNAPSHOT](docs/specs/SHELF_SNAPSHOT.md)): экран `/snapshot` (ссылка в боковой панели полки под «Корзиной») показывает полку на выбранный момент — какая версия каждой работы была последней, какая принята тогда и что изменилось с тех пор. Только чтение; на полке отдела — любому участнику. MCP-инструмент `polka_snapshot` (scope `read`) отдаёт ровно ответ `GET /api/v1/snapshot` (`at`, `limit`, `cursor`).
- **Поиск по фразе** ([CONTENT_SEARCH](docs/specs/CONTENT_SEARCH.md#поиск)): слова в кавычках — `"годовой отчёт"` или «годовой отчёт» — ищутся рядом и в этом порядке, на полке и в `polka_list`. Слово в кавычках ищется целиком, а не как начало слова.
- **«Сначала подходящие»:** пока в поиске есть запрос, полка ставит выше работы, где запрос есть в названии, затем те, где найденные слова в тексте стоят близко. `polka_list` ранжирует так же.
- **Для расширений** ([EXTENSIONS](docs/specs/EXTENSIONS.md)):
  - маршруты для машин — `machinePaths` и `context.agent(req, reply, scope)`: запросы агентов и сборщиков телеметрии по токену агента с нужным разрешением, без проверки `Origin`; вход по cookie на этих адресах не принимается;
  - `context.redact(text)` скрывает секреты в тексте, пришедшем нескрытым (телеметрия по OTLP), теми же правилами и метками, что `polka-sessions.mjs`; при `AGENT_SESSION_FINGERPRINTS=installation` отпечаток совпадает с отпечатком того же секрета в сессиях;
  - `session.saved` в журнале несёт сработавшие правила (`alerts`), а стирание аккаунта оставляет строку `account.erased` без личных данных (миграция 069): тревогам в SIEM и индексу сессий больше не нужно читать сессию или сверяться с таблицей аккаунтов.
- **Уведомления о заявках в Telegram:** `OPERATOR_TELEGRAM_BOT_TOKEN` и `OPERATOR_TELEGRAM_CHAT_ID` (оба или ни одного) — оператор узнаёт о заявке с /enterprise сразу, письмо уходит как раньше.
- **`npm run hosted:setup`** пишет `hosted.env` для своей установки с новыми секретами (права 600; `--force`, `--set`, `--live`), ключи S3 берёт из окружения ([deploy/hosted](deploy/hosted/README.md), шаг 4).
- **Документация для участников на английском:** CONTRIBUTING.md (русский — CONTRIBUTING.ru.md), [docs/en](docs/en/README.md) — устройство и локальная разработка.

### Changed

- Работа находится по названию, даже если слова запроса стоят в нём в другом порядке или в другой форме: «отчёт годовой» находит «Годовой отчёт».
- **CI на GitHub Actions снова работает** на каждый pull request и push в `main`. MinIO для разработки и CI собирается из исходников (`deploy/minio/Dockerfile`; первый `infra:up` — около 10 минут): готовые образы MinIO больше не публикуются.

### Fixed

- **Хук сессий агентов: `/clear`, закрытый терминал, `disableAllHooks`** ([AGENT_SESSIONS](docs/specs/AGENT_SESSIONS.md#когда-хук-не-срабатывает)):
  - `sync` берёт не только `--since`, но и всё, что изменилось после начала последнего прошедшего `sync`. Сессия, закрытая в пятницу вместе с терминалом (без `SessionEnd`), к понедельнику выпадала из `--since 2d` и не доходила совсем;
  - одна сессия, которой сервер отказал (слишком большая), больше не останавливает `sync`: остальные уходят, её пробуем в следующий раз, код выхода 1;
  - отправка из хука отмечает сессию, и досылка по расписанию не отправляет её второй раз;
  - во фрагменте `managed-settings` у хука `timeout: 10`: хуки `SessionEnd` получают на всех 1,5 с. В установке пилота подхватится при повторном запуске установщика;
  - `/clear` до первого запроса: хук пишет в журнал «nothing to send», а не ошибку отправки;
  - проверено и записано: после `/clear` уходят обе части разговора; начатую отправку закрытие терминала не останавливает; `disableAllHooks` у человека управляемый хук не выключает, а хук плагина выключает.
- Список сессий листается по паре «начало, id»: сессии, начатые в одну и ту же миллисекунду, больше не пропадают на границе страниц. Курсор старого вида (просто время) по-прежнему работает.
- Курсор страницы поиска, выданный до нового ранжирования, отклоняется, а не пропускает работы.
- Нестабильные тесты: журнал расширений, закладка и Chrome, срок проверки страницы — на загруженной машине CI падали без ошибки в коде.

## [0.10.0] — 2026-10-07

### Added

- **Чтение версий для расширений** (`context.content`, [EXTENSIONS](docs/specs/EXTENSIONS.md)): версия любой полки установки с работой, полкой и файлами, каждый файл потоком с проверкой размера и SHA-256 (видео тоже). Версию, которую модератор изолировал или стёр, ядро называет, но не отдаёт. Нужно коммерческой редакции для выгрузки принятых версий.

- Миграция 064: индекс `audit_outbox` для чтения журнала по всей установке.
- **Печать в PDF** у рендерера (`POST /pdf`): вся страница на A4 в той же песочнице без сети, что и обложки; для расширений — `context.content.pdf`, где рендерер настроен.

### Fixed

- `docs/specs/EXTENSIONS.md` обещал доставку `onEvent` «как минимум один раз»; на деле событие не хранится и теряется при перезапуске. Описание исправлено, для надёжной работы — `context.auditFeed`.

Раньше проект правился только новой загрузкой целиком. Теперь сервер читает один текстовый файл (Markdown, HTML, CSS, JavaScript, JSON, SVG, текст), применяет правки, а остальные файлы хранилище копирует в новую версию само (`CopyObject`), поэтому размер проекта не важен. У каждой версии по-прежнему свои объекты. При сохранении все файлы читаются обратно, сверяются с манифестом, проверяются и индексируются как при обычной загрузке. Ключ идемпотентности, проверка базовой версии и права подключения — те же.
- **`polka pull` и `push`** ([PUBLISH_API](docs/PUBLISH_API.md#polka-pull-и-push)). `polka-pull.mjs` скачивает версию работы в папку: `GET /api/v1/works/:id/files` и `…/revisions/:rev/files/:index`, scope `source:read`, каждый файл сверяется с SHA-256. Заодно он записывает `.polka.json`. `polka-publish-project.mjs` такой папки сохраняет следующую версию того же проекта. Изменённые файлы он отправляет, а остальные хранилище копирует само (`POST /api/v1/projects/:uploadId/reuse`). Токен из `polka_project_upload` теперь получает и `source:read`, если оно есть у подключения, и тогда в ответе есть `pullCommand`. Синхронизации нет: если на Полке уже есть более новая версия, сохранение отказывает.
- **Письмо с приглашением в библиотеку шаблонов.** Раньше администратор получал ссылку и пересылал её сам. Теперь Полка отправляет приглашённому письмо: название библиотеки, логин пригласившего, роль, срок и ссылку. Текст фиксированный, своего сообщения к нему не добавить: приглашать может любой закреплённый аккаунт. Не больше 20 писем в сутки от одного администратора и 3 на один адрес. Окно говорит, ушло ли письмо, а ссылку по-прежнему можно скопировать. Ответ `POST /api/template-libraries/:id/invitations` содержит `mail`: `sent`, `disabled`, `limited` или `failed`. В [Политике](docs/legal/privacy.md) раздел «Библиотеки шаблонов» говорит об этом письме.

## [0.3.1] — 2026-09-27

### Security

Исправления по итогам проверки безопасности перед запуском.

- **Страницы проекта без WebRTC.** Страница проекта выполняет свои скрипты, а CSP не закрывает WebRTC, поэтому через `RTCPeerConnection` она могла отправить наружу то, что вводит читатель. Теперь каждый HTML-ответ просмотрщика проектов начинается с того же скрипта, что и интерактивный просмотр: он убирает конструкторы RTC раньше любого скрипта страницы, даже стоящего до `<head>`. Проверено в Chrome.
- **Просмотр проекта не зависает на подобранной странице.** Место для скриптов Полки искалось регулярным выражением по `<head>`, и страница из множества незакрытых `<head` на 256 КБ обрабатывалась 4 секунды (на 5 МБ — около 25 минут). Теперь скрипты ставятся линейным проходом в начало документа, после doctype.
- **Заголовок страницы по ссылке не блокирует сервер.** «Сохранить как ссылку» и рендерер искали `<title>` и `og:title` регулярными выражениями по всей странице (до 512 КБ); подобранная страница на 32 КБ держала сервер 7 секунд. Теперь заголовки читаются только из первых 32 КБ линейным проходом.
- **Скрипты пакетов и проектов проверяются вне основного потока.** Проверка на фишинг читала `.js`-файлы при сохранении прямо в потоке запросов: 48 МБ подобранных строк останавливали сервер примерно на 25 секунд. Теперь скрипты читаются в воркере с дедлайном (2 секунды и ещё секунда на мегабайт); не успевшая проверка добавляет сигнал `scan:incomplete`, и интерактивная ссылка ждёт проверки, как для страниц. Из каждого файла в текстовые сигналы попадает не больше 256 тысяч символов строк. Так же теперь работает `moderation.ts recheck --fraud`.
- **Воркеров проверки не больше, чем ядер.** Каждая проверка страницы запускала отдельный воркер с кучей до 256 МБ без ограничения их числа, и одновременные сохранения могли исчерпать память. Теперь одновременно работает не больше воркеров, чем ядер (`os.availableParallelism()`), остальные ждут в очереди. Ожидание в очереди не входит в дедлайн проверки.
- **Сессия по ссылке от агента не объединяет полки.** С такой сессией можно было войти в другую полку и нажать «Объединить»: работы и агенты временной полки уходили туда. Держатель ссылки мог так забрать чужие работы. Теперь `POST /api/account/claim/merge` требует обычного входа, а сессии по ссылке доступно только «Открыть ту полку без объединения»; работы остаются на месте. Экран `/claim` пока показывает «Объединить» и для такой сессии, сервер ответит отказом.
- **Похожие на чужие имена клиентов OAuth.** «CIaude» (заглавная I), «Clauԁe» (кириллическая ԁ) и «ΟpenAI» (греческая Ο) показывались на странице согласия без пометки «(имя не подтверждено)». Теперь имя сравнивается после сведения похожих латинских, кириллических и греческих букв, а также I/l/1 и O/0, к одному написанию. Имена «Полка», «Polka» и «Полочка» подтверждаются только для адресов возврата на домене самой установки.
- **HSTS с `includeSubDomains`** на обоих хостах в `deploy/hosted/Caddyfile`.
- **Полка сортирует и фильтрует все работы, а не загруженную страницу.** `GET /api/artifacts` принимает `sort` (`new`, `old`, `title`) и `kind` (`pages`, `documents`, `images`, `other`), первая страница отдаёт `counts` по всей полке. Любая HTML-работа теперь «Страница» везде: в чипах, на карточке и в просмотре. Снимки — docs/assets/launch-fixes-2026-09-27.
- **Удаление.** В корзине сказано, сколько там лежат работы (пока их не восстановят) и где удалить их навсегда. В настройках (`/settings`, пункт «Настройки» в меню аккаунта) появился раздел «Удалить полку» с адресом оператора: `/api/capabilities` отдаёт его как `privacyContact` (`OPERATOR_CONTACT`, иначе `OPERATOR_EMAIL`).

Так задерживались прототипы B2B-продуктов, например прототип «Алиса AI в Яндекс 360» 25–26.09. Поля по-прежнему отмечаются, и получатель видит «Страница … просит пароль, код или данные карты. Не вводите их здесь.».
  - Нужен канал вне страницы. Это просьба передать код, пароль или данные карты («продиктуйте код», «отправьте код из SMS в Telegram @…»), перевести деньги на карту или кошелёк, или похожий домен бренда (`yandex-360-login.ru`, `apple-id-verify.com`, IDN, цифры вместо букв). Telegram, телефон, почта и ссылка на чужую страницу входа только добавляют к счёту. Бренд без канала весит ноль.
  - Фишинг, найденный только правилами у доверенного автора, — письмо оператору, ссылка работает, если модель прочитала работу и не назвала её фишингом (или ещё прочитает: её ответ решает ссылку заново). Подтверждённый моделью фишинг задерживается, как раньше.
  - Одобрение оператора переходит на следующие версии работы: версия с теми же или меньшими признаками не задерживается снова, новый признак задерживает (`revisions.content_filter.approved`, `details.approvedSignals` у `share.approved`).
  - `moderation.ts recheck --fraud [--dry-run]` перечитывает версии задержанных за фишинг ссылок по новым правилам и открывает те, что больше не подходят (журнал: `revision.rescanned`, `share.released`).
- **Все разрешения агента отмечены по умолчанию.** На странице согласия («Что сможет приложение») сразу стоят все галочки, включая «Управлять названиями, папками и корзиной» и «Давать ссылку для входа»: агент сразу умеет всё, владелец может снять любую. Действия за ними обратимы (корзина, удаление только пустых папок, новые версии не стирают старые); ссылка для входа открывает только временную полку. Уже выданные подключения не меняются — чтобы добавить разрешения, подключите агента заново.
- **Главная полка начинается с агента.** Вместо поля «Вставьте ссылку на артефакт» — один блок «Подключите агента — он сам сохранит работу на полку» с переключателем Claude (claude.ai и Desktop) / Claude Code / Codex / Другой MCP-клиент и одним шагом для каждого: адрес коннектора с кнопкой копирования, команда плагина или адрес MCP и `npx skills add artkruglov/polka`. Полная версия — «Агенты» (`/settings/agents?client=…`), «Загрузить файл» рядом. Когда агент подключён (или блок скрыт), остаётся одна строка: «Подключено: …», фраза «Сохрани это на Полку», «Агенты», «Загрузить файл». Чек-лист первых шагов на полке больше не показывается, он остался на `/start` (`features/agent-hero`).
- **«Сохранить» — файл или код.** Страница `/bring` называется «Сохранить работу» и предлагает загрузку файла и «Вставить код»; `?url=` из старых ссылок игнорируется.

- **Предупреждение получателю — только когда есть повод** ([CONTENT_FILTER, «Поля для секретов»](docs/specs/CONTENT_FILTER.md#поля-для-секретов)). При сохранении Полка отмечает, есть ли на странице поля для пароля, карты, одноразового кода или seed-фразы: в разметке и в скриптах, которые строят форму (`content_filter.sensitiveInput`, без миграции). Отчёт или дашборд без таких полей подписан тихо: «Опубликовал пользователь Полки». Страница с такими полями и версия, сохранённая раньше, показывают предупреждение без неточного «не проверена». В «Подробнее» сказано, проверила ли Полка текст и код автоматически. Старые версии размечает `npm run moderation:backfill-sensitive-input -- [--dry-run]`.

- **Страница работы — режим чтения.** Над работой одна тонкая полоса: «←», название, «v1 ▾», вкладки «Работа · Версии», ⓘ с подробностями (вид, доступ, версия, файл, пояснение о просмотре), «На весь экран», «Поделиться» и «…» со всеми остальными действиями. Работа занимает весь оставшийся экран и прокручивается внутри; на 1440×900 она начинается в 52 px от верха вместо ~450. Вкладка сохраняется в адресе (`?tab=versions`). Боковое меню на этой странице свёрнуто до иконок, переключатель запоминается в браузере. На телефоне — одна полоса и строка вкладок ([FRONTEND_COMPONENT_SYSTEM](docs/FRONTEND_COMPONENT_SYSTEM.md)).
- **Карточка ссылки AI-сервиса.** Способы идут по порядку: «Попросить Claude» (или фраза для своего агента), «Сохранить как ссылку», файл прямо в карточке. Расширение перенесено за ссылку «Сохранять в один клик». Неудавшийся импорт предлагает сохранить ссылку.

- **«На Полку» на странице `claude.ai/artifact/<id>`.** У неё нет Copy и вкладки Code, поэтому исходник берётся через меню названия → Export → Download: на время одного сохранения в мире страницы перехватываются `URL.createObjectURL`, клики и `dispatchEvent` по `a[download]` и `window.open`, Blob читается, файл в «Загрузки» не попадает (скачивание с сервера тоже останавливается — тогда берётся фрейм), всё восстанавливается, меню закрывается Escape. Меню — Base UI: открывается фокусом + ArrowDown (синтетические клики и Enter его не открывают), подменю — ArrowRight, пункты ищутся по `data-title-menu`/`data-download-submenu`/`data-download-item`, затем по тексту; закрывается Escape на пункте в фокусе, иначе на кнопке, иначе нажатием вне меню. «Copy as Markdown» не нажимается. Фрейм — `*.frame.claudeusercontent.com`, скрытый фрейм 1×1 пропускается; кнопка «На Полку» стоит рядом с Share. Фикстура `claude-artifact-page.html` повторяет эту структуру.

### Added

- **Закладка «На Полку»** — альтернатива расширению для тех, кто не ставит расширения: обычная закладка с `javascript:`-адресом, страница установки `/bookmarklet` (кнопка для перетаскивания, код для телефона, исходник на GitHub). ### Added

Привязать и отвязать поставщика можно в «Способах входа» (`/settings/agents`). Удаление аккаунта сразу стирает привязки: это делает триггер, функция purge не переопределяется.

    - `YANDEX_CLIENT_ID`/`YANDEX_CLIENT_SECRET`, `VK_CLIENT_ID`;
    - `OIDC_DISCOVERY_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `OIDC_ALLOWED_DOMAINS`, `OIDC_ORG_CLAIM`/`OIDC_ORG_VALUE`.

- **Комментарии и реакции на тексте работы** (этап 3 [COMMENTS](docs/specs/COMMENTS.md); миграция 030).
  - **Обсуждение принадлежит ссылке.** Получатель выделяет фрагмент и пишет замечание или ставит реакцию (👍 👎 🎉 🤔 ❤️ 👀 ✅, повторное нажатие снимает); ответы в один уровень, «Решено», «Удалить». Читать может любой, у кого открыта ссылка, писать — только вошедший; вход возвращает на ту же ссылку, токен не попадает в `?next=`. Получатели одной ссылки не видят обсуждение другой; отзыв, истечение и проверка модератором закрывают обсуждение для получателей, у владельца оно остаётся. Владелец видит обсуждения всех ссылок работы на её странице, с числом новых.
  - **Привязка к тексту** — цитата `{exact, prefix, suffix}`; в новой версии она ищется заново (точно, затем без учёта пробелов, среди повторов — по контексту), не найденная или неоднозначная становится комментарием ко всей работе с пометкой «к прежней версии».

В интерактивном просмотре он идёт после защиты от WebRTC; в статичном — `sandbox allow-scripts` и CSP `script-src 'nonce-…'` со случайным nonce на ответ, поэтому скрипты, обработчики и `javascript:` самой страницы по-прежнему не выполняются, а сеть закрыта и для оверлея. Подсветка — CSS Custom Highlight API, DOM страницы не меняется. Сообщения принимаются только от `parent` с `APP_ORIGIN`. Проверено в настоящем Chrome (`tests/comment-overlay-dom.test.ts`).

Текст комментариев — только текст, адреса не кликабельны; автор показан выбранным им именем (его просят выбрать перед первым комментарием), не почтой.
  - **Письма:** владельцу о каждом новом комментарии, участникам ветки — об ответах, пока ссылка открыта; не больше 30 в сутки на адрес в своём счётчике (вход не страдает), до 300 символов, адреса в тексте обезврежены (`example[.]com`), чужих почт нет; отключаются подписанной ссылкой `/mail-off#…` или в панели.
  - **Агентам:** `polka_comments` (`read`), `polka_resolve_comment` (`revise`), `polka_revise` с `edits: [{oldText, newText}]` (точное совпадение, затем нормализованное — NFKC, кавычки, тире, пробелы в конце строк; меняются только найденные места; 422 с номером правки, 409 с `currentRevisionId`), `polka_share` с `moveShareId` — перенести ссылку и её обсуждение на новую версию. HTTP: `POST /api/v1/works/:id/edits` (с `moveLink`). Цикл описан в `/llms.txt`, скилле и [connect-agents](docs/connect-agents.md).

Жалоба на комментарий (не ставит ссылку на паузу). Скрипты `moderation:comments`, `moderation:delete-comment`, `moderation:release-comment`; `disable` и запрос удаления аккаунта скрывают комментарии и реакции автора, окончательное удаление аккаунта стирает их. Лимиты: 2000 символов, 200 комментариев на ссылку в сутки, 60 комментариев и реакций автора в час.

  - **Лимиты новых аккаунтов:** ссылка не дольше 7 дней и не больше `NEW_ACCOUNT_MAX_LINKS` (5) открытых ссылок; отказ объясняет причину и что сделать. `polka_publish` и publish API выдают новому аккаунту ссылку на 7 дней вместо 30 и сообщают это в `expiresNote`.
  - **Состояние ссылки** `none` / `held` / `paused`. `SHARE_MODERATION`: `off`, `flagged` (по умолчанию: подозрительная страница недоверенного автора), `new-accounts` (любая ссылка недоверенного автора), `all` (любая ссылка аккаунта, зарегистрированного по почте). Получатель ожидающей или приостановленной ссылки видит экран «Ссылка на проверке у модератора Полки» без названия и содержимого; владелец видит работу и состояние «на проверке». Новая версия, опубликованная по одобренной ссылке недоверенного автора, снова ждёт проверки.
  - **Агентам:** `polka_publish`, `polka_share` и `POST /api/v1/publish` возвращают `moderation: "held"` и `moderationMessage`, пока ссылка ждёт; описания инструментов велят не выдавать такую ссылку за готовую. CLI печатает это в stderr.
  - **Жалобы:** каждая — письмо оператору; `MODERATION_AUTOPAUSE_REPORTS` (3) разных жалобщиков за 7 дней ставят ссылку на паузу. Жалобщики различаются по `HMAC(LINK_KEY, ip|share)`, адреса не хранятся. Ссылки «Интересного» автоматически не приостанавливаются.
  - **Письма оператору с действиями в один клик** (`OPERATOR_EMAIL`): «Посмотреть» (тот же песочный просмотр, грант на 60 секунд), «Одобрить ссылку», «Одобрить и доверять автору», «Снять паузу», «Закрыть ссылку», «Закрыть и отключить автора». Кнопка — `/moderation#<токен>`: HMAC от ключа, выведенного из `LINK_KEY` с отдельным назначением, срок 7 дней. Открытие страницы ничего не меняет, действие выполняет только POST; повтор безопасен. Отправка писем вынесена в `apps/server/mailer.ts` (вход по коду и модерация); в `MAIL_MODE=local` письма оператору пишутся в `.local/mail/operator/`.
  - **Признаки фишинга** считаются при сохранении в том же линейном проходе parse5, что и классификатор, и по строкам скриптов (включая JSX-компоненты): поля паролей, карт и кодов из SMS вместе с брендом банка или сервиса либо срочностью. Список признаков — один файл `apps/server/phishing-signals.ts`.
  - **Скрипты:** `npm run moderation:queue`, `moderation:approve -- <shareId> [--trust]`, `moderation:unpause`, `moderation:trust`.

### Changed

- **Получатель видит предупреждение над страницей, а не мелким шрифтом под ней:** «Эту страницу опубликовал пользователь Полки. Полка её не проверяла. Не вводите здесь пароли, коды из SMS и данные карт.», рядом «Пожаловаться»; у автора младше 7 дней — «Автор недавно на Полке». Имя автора не показывается. Материалы «Интересного» подписаны «Редакция Полки» без предупреждения.
- `moderation:revoke-share` отмечает жалобы на закрытую ссылку рассмотренными.

### Security

- **Глубоко вложенная страница больше не останавливает сервер.** Разбор HTML в parse5 квадратичен по глубине вложенности (200 КБ вложенных `<div>` — около 4 с, 5 МБ — около 40 мин), а обход дерева в классификаторе был рекурсивным и падал с переполнением стека. Запись rc.4 о линейном времени была верна только для «плоских» страниц. Теперь страницы больше 16 КБ классифицируются в отдельном потоке с дедлайном 2 с (не успел — ссылка не выдаётся, владелец видит и скачивает работу), обход дерева — без рекурсии.
- **С доменом просмотра домен приложения больше не отдаёт пользовательский HTML.** Статичный (без скриптов) просмотр переехал на домен просмотра (`VIEWER_ORIGIN/static/:token`, грант на 60 секунд: у владельца — по сессии, у получателя — от гранта ссылки) с CSP статичного просмотра и `frame-ancestors <APP_ORIGIN>`; `/api/revisions/:id/document` и `/api/view/:grant/document` на таком сервере отвечают 404, а приложение встраивает фреймы только с домена просмотра (`frame-src` без `'self'`). Установка на одном домене работает как раньше. Спецификация: `docs/specs/ABUSE_PROTECTION.md`, п. 8.
- **Внешние ссылки статичного просмотра ведут через «Вы уходите с Полки».** При отдаче страницы абсолютные `http(s)`-ссылки в `<a>` и `<area>` заменяются на `APP_ORIGIN/away#<токен>`; токен подписан ключом, выведенным из `LINK_KEY`, и живёт 12 часов. Страница `/away` называет адрес и ждёт нажатия; без действующей подписи она ссылку не открывает и сама никуда не перенаправляет. Скачивание отдаёт исходные байты. Спецификация: п. 9.

- Пустая полка объясняет, что здесь появится, вместо набора одинаковых кнопок; после «Разрешить» страница согласия говорит вернуться к агенту.

### Security

- **Страница в интерактивном просмотре больше не может выйти в сеть через WebRTC.** CSP его не закрывает (Chrome игнорирует `webrtc 'block'`), и проверка на проде показала, что страница достаёт внешний STUN-сервер: могла бы отправить IP читателя и введённый текст. ## [0.1.0-rc.4] — 2026-09-22

Правки по итогам второго полного ревью перед открытым релизом (сервер, безопасность, веб, эксплуатация, документация).

### Security

- **Классификатор страниц работает за линейное время.** Регулярные выражения перезапускались с каждого `<`, поэтому время росло квадратично и занимало поток запросов: страница в 480 КБ останавливала сервер примерно на минуту, а разрешённые 5 МБ — на часы. Для второй половины атаки хватало ссылки на такую страницу. Теперь документ разбирается один раз (parse5), 5 МБ — меньше полсекунды.
- **Открытый редирект после входа закрыт.** `next=/.//evil.example` после нормализации превращался в `//evil.example` и уводил уже вошедшего пользователя с Полки без клика.
- **Токен ссылки не уходит в `?next=`.** «Войти» на странице получателя переносил `/s#<токен>` в query-строку, которую видят сервер и прокси.
- **Сохранённая страница не открывается как самостоятельная страница Полки.** Браузер, заявивший навигацию верхнего уровня (`Sec-Fetch-Dest: document`), получает 404; во фрейме всё как раньше.
- **Сборка не оставляет процессов-зомби.** Каждая runtime-сборка оставляла esbuild зомби-процессом сервера; воркер теперь дожидается его выхода.
- **Упавшую сборку нельзя перезапускать в цикле.** После таймаута, нехватки памяти или сбоя сборщика тот же исходник не пересобирается 30 секунд, поэтому один владелец больше не занимает слоты сборки всех остальных.

### Fixed

- Один лимит названия — 160 символов: MCP-захват и импорт по URL принимали 200 и затем падали с «internal».
- Запрос, дождавшийся занятой строки (медленный S3 под блокировкой владельца), получает повторяемый 503 вместо 500; S3-клиент делает не больше двух попыток.
- Интерактивные просмотры по ссылкам одного владельца больше не выстраиваются в очередь друг за другом.
- Неудачный `ROLLBACK` больше не подменяет исходную ошибку.
- Страница входа не говорит, что регистрации нет, если на установке включён вход по почте; приглашение в библиотеку не мигает ошибкой; повтор жалобы не создаёт дубль.
- Healthcheck PostgreSQL проверяет TCP: при первом старте временный сервер отвечал только на сокет, и `migrate` падал на медленной VM.
- Документированное восстановление hosted-дампа не работало (`pg_restore --clean`); новая процедура проверена на реальном дампе схемы 028.

### Changed

- Образ содержит `NOTICE` и `THIRD_PARTY_NOTICES.md`.
- Документация сверена с кодом: OAuth `resource` необязателен, коннектор проверен с Claude.ai (ChatGPT — ещё нет), приёмка изоляции viewer на hosted пока не записана, runbook первого запуска hosted дополнен.

### Known issues

- Посторонний, знающий адрес почты, может на сутки заблокировать вход по коду для этого адреса: лимит неудачных попыток считается на адрес. Касается только установок с `MAIL_MODE=smtp`, на polochka.app вход по почте выключен.

- MCP-сервер (Streamable HTTP) с токенами подключения и узкими scopes: `polka_context`, `polka_capture`, `polka_status`, `polka_revise`, `polka_share`, `polka_revoke_share`, `polka_list`, `polka_prepare_preview`, инструменты управления и шаблонов. Страница «Агенты» для выдачи и отзыва токенов.
- Контекст для агента и библиотеки шаблонов: роли reader/curator/admin, приглашения, журнал, закреплённые версии.
- Экспериментальный интерактивный просмотр на отдельном loopback origin.
- Импорт standalone HTML по URL (выключен по умолчанию).
- Удаление аккаунта: отзыв доступа в коде (выключено по умолчанию); очистка данных — отдельный purge worker, не принят и не подключён к установке. Синтетический restore drill, штатный restore CLI.
- Self-host: Docker-образ с закреплённым base digest, readiness, maintenance-воркер, рецепты прав ролей БД.
- CI: тесты на временных PostgreSQL и MinIO, проверка лицензий, поиск секретов, smoke-тест образа.
